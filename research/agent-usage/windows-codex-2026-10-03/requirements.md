# Windows 本地统计＋Codex 额度：需求与最小交付

日期：2026-10-03，Asia/Shanghai。范围来自用户本轮明确选择。本文件是复评建议，不覆盖已完成 M1 的事实，也不授权实施。

## 用户任务

个人在一台 Windows 电脑上查看：今天及近期各 agent、模型使用了多少本机可观测 token；估算费用覆盖多少数据；已连接 Codex 账号的官方额度剩多少、何时重置；哪些数字过期、缺失或读取失败。所有结果应能解释来源和时间。

## 已确认约束

| 约束 | 产品要求 |
|---|---|
| 平台与技术栈 | Windows x64；沿用现有 Electron 与统计合同。普通功能不引入第二套桌面框架。 |
| 本地统计来源 | Codex、Claude Code、OpenCode、WorkBuddy、MiMo Code 五类；具体 Desktop/CLI 入口仅在元数据能证明时区分。 |
| 账号额度首批 | 只接 Codex；通过官方 CLI 的账号接口与用户本人完成的官方登录。 |
| 权限隔离 | 原 M1 采集入口保持离线；额度使用独立可选入口、独立 CODEX_HOME 和自己的数据目录。 |
| 凭据 | 系统 keyring；核对实际生效配置，不可用时阻止连接，不降级为 auth.json；应用不导入既有认证文件。 |
| 数据最小化 | 只保留统计白名单；不保存、输出或导出正文、代码、原始路径和凭据。额度账号缓存沿用独立最小白名单。 |
| 无业务干扰 | 不写来源数据库，不改其他 agent 配置或登录；断开仅针对本应用独立连接。 |
| 展示口径 | token、账号额度、费用估算分别展示；没有可靠依据不关联本机历史与当前账号。 |
| 当前视觉基准 | 沿用用户已选 Nowdex Mac 参考与既有层级；动画保持关闭。AgentHub 用于状态和交互参考。 |
| 研究边界 | 本轮只新增研究文档；不安装、启动或实连，不创建云资源，不开始后来阶段。 |

## 必须固定的数据含义

1. 本机 token 是所选来源的可观测活动，不能承诺包含同账号的网页端、其他设备或云端任务。
2. 账号额度是服务商返回的独立快照；各账号、额度池和窗口不得相加。窗口长度按返回字段显示，不固定为五小时或一周。
3. API 等价费用是固定价格快照下的估算，不能称为实际支付或订阅账单。未定价、字段缺失、部分覆盖必须可见。
4. 当前合同的 output 包含 reasoning；inputUncached 排除缓存。归一化后的不重叠桶才可相加，不能再次加 reasoning。
5. null、没有数据、读取失败和已观测零是不同状态。到达重置时间只能表示待刷新，不能自行把额度置满。
6. 账号连接标签是用户备注，不能单独证明真实身份。相同身份的多个连接也不代表多个独立额度池；无可靠身份依据时不自动合并。
7. 官方文档中的 account/usage/read 属于账号活动汇总；不自动纳入当前 RPC 白名单，也不与本机 token 求和。它需要单独范围和版本核对。

依据：[本地统计合同](../../../docs/m1/DATA-CONTRACT.md)、[当前额度合同与实现记录](../../../docs/m1/CODEX-QUOTA.md)、[官方 App Server](https://learn.chatgpt.com/docs/app-server)。

## 最小版本包含什么

| 编号 | 必须交付 | 可观察验收 |
|---|---|---|
| M01 | 五来源本地统计、保存历史、暂停/恢复和手动刷新 | 每类提供已支持版本、字段、独立样本对照和 partial/unknown 原因；重复刷新、归档或复制不增加重复量。 |
| M02 | 今日、近 7 天、近 30 天、已有历史累计，agent/model 筛选与趋势 | 同一筛选下图表与明细一致；时区和覆盖范围可见；缺失日期不当作测得零。 |
| M03 | API 等价估算与定价覆盖 | 展示价格版本、已定价子集和未定价情况；估算可按明确公式核对。 |
| M04 | Codex 连接、取消登录、查询、刷新和断开 | 用户完成一次官方登录后可读取官方额度；操作只作用于本应用独立目录；取消、超时和未登录有明确状态。 |
| M05 | 账号连接列表、各额度池与窗口、更新时间和重置时间 | 单连接不混入其他连接快照；出现多个连接时不求和。若宣称多账号已验证，至少用两个本人可用账号完成隔离核对。 |
| M06 | 手动刷新与可关闭的周期刷新 | 周期刷新默认关闭；关闭应用后停止。建议五分钟作为初始周期，对服务端限流退避；上次成功时间与本次失败原因分开。 |
| M07 | 未知、过期、限流、重登与协议异常状态 | 可识别的失败使用脱敏错误类别；通用错误仍有安全提示。旧数值必须标历史状态，身份失效时不能冒充当前有效额度。 |
| M08 | 自有统计导出与清空、来源状态 | 导出仅含统计白名单；清空不影响 agent 业务文件；额度缓存不混入原统计导出。 |
| M09 | Windows 本地目录包与完整退出 | 新目录解压可启动；路径含中文/空格；托盘恢复、单实例、系统 DPI、休眠恢复、系统文件对话框与退出后停止子进程有证据。 |

允许保留当前离线统计入口与可选额度入口的拆分，以满足权限隔离。首轮可交付本地未签名目录包，签名和公共发布另行评审；不能声称继承上游发布者签名。

## 排除什么

- iPhone、云端、外网同步、生产端到端加密、设备配对与远程控制；长期需求留在原研究目录。
- Claude、Cursor、WorkBuddy 等其他 provider 的账号连接、Cookie 导入和额度网络请求。
- API 按量账单、余额、充值、汇率在线更新；本机 token 的固定 USD 等价估算仍包含。
- 自动切账号、账号池反代、模型请求转发、暖号、重置权益消耗、邀请发信和微信控制。
- 自动改 hooks、全局 provider、现有客户端配置，以及登录自启动。
- 公共排行榜、数据上传、公开个人主页、团队权限和商业分发。
- 任务工作台、项目/完整会话详情、父子 agent 成本归因、桌面宠物和重新设计整套 UI。

## 交付门槛与当前缺口

既有 M1 记录提供自动检查、部分真实来源样本和 Windows 打包证据；它们不证明所有版本、所有入口和长时间生命周期。既有额度记录主要提供合成测试与独立 CLI 空目录握手证据。[M1 验收](../../../docs/m1/ACCEPTANCE.md)、[额度验收](../../../docs/m1/CODEX-QUOTA.md)。

后续实施与验收最应优先收敛的事项：

1. 官方登录后真实读取，与同一账号、接近时间的官方额度对照；允许服务端更新延迟，并记录两侧观察时间。
2. 核对有效 keyring 配置后验证真正的凭据写入和应用重启恢复。配置读成功不代替这两项。
3. 若保留多账号能力，验证两个独立连接、相同账号重复连接提示、失败/断开不影响其他客户端。仅在官方接口提供可靠身份证据时做身份去重。
4. 区分超时、协议错误、需登录和可识别的限流；有界并发、取消和退避不重复发起请求。官方 CLI 未给出结构化原因时诚实保留通用错误。
5. 产品数据、日志、renderer、导出和测试产物中均不出现凭据或授权 URL。额度专用 CLI 的真实网络行为仍需范围内验证。
6. 真实 Windows 托盘、DPI、休眠/恢复、系统对话框和退出清理。浏览器预览与强制缩放只能补充证据。

性能建议是验收目标：在约三万条既有记录规模、普通本地磁盘、电脑在线且来源持续写入时，本地新数据可见目标为 60 秒以内；应明确测试机器和冷/热启动条件。更大历史与慢磁盘单列测量，额度无需追求秒级刷新。

## 剩余需求决策

| 决策 | 建议工作假设 | 改变时的影响 |
|---|---|---|
| 额度过期阈值 | 保持当前超过十分钟或重启缓存需要刷新 | 更短会增加网络负担；应按 provider 能力调整。 |
| 刷新间隔是否可配置 | 首版默认关闭，可选五分钟 | 自定义高频轮询需要限流上限和体验验收。 |
| 历史保留 | 沿用当前不自动裁剪；让用户主动导出与清空 | 更大规模可能需要增量索引；不能为性能优化静默删历史。 |
| 交付包形态 | 保持两权限入口，提供清楚的运行说明 | 合并入口需要重新核对离线边界与打包清单。 |

这些假设用于需求评审；本轮不实施，也不改变现有设置。

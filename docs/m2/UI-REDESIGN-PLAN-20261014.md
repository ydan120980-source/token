# 界面与排版重做计划（2026-10-14，待项目负责人确认）

状态：**已批准（2026-10-14），按步实施中**。P0 已完成（见文末"进度"）。

项目负责人的决定：
1. 设计语言：以现有的中性灰主体为基础，采用 Apple 式的设计风格（克制、只用一种强调色、用细线代替边框、只有浮层才用半透明材质）。
2. 用量页：方案 A，在同一页内分成"概览 / 分析"两段。
3. "采集来源"区：改成一行状态摘要，链接到来源管理。
4. P1 跑一次全量 UI 套件，其余各步只跑受影响的套件。

以下是批准前的检查和方案原文。依据是 `main` @ `167f9b1` 的演示数据页面（`serve.js`，1280×820，浅色），`design:accessibility-review` 和 `design:design-critique` 两轮检查，以及对 `design/desktop-reference/*.css` 的计数。没有读取任何真实来源。

## 结论

现有界面在功能上可用，主要问题出在结构上：17 个样式文件逐层覆盖，三种设计语言混在一起，彼此不统一，所以零碎的微调已经收不住。重做要先建立一套样式规范（字号、颜色、间距、圆角等统一变量）和一套组件，再逐页迁移。不改数据口径，也不改测试依赖的 DOM 钩子。

## 一、检查发现

### 1. 结构（根因）

| 指标 | 现状 | 说明 |
|---|---|---|
| 样式文件 | 17 个，按加载顺序层层覆盖（`style` → `nowdex` → `refined` → `refinement` → `polish` → `rhythm` → …） | `.card` 在 5 个文件里都有定义。改一处常被后面的文件盖掉 |
| `!important` | 213 处 | 是层层覆盖的直接后果 |
| 字号 | 页面上用到 18 种，CSS 里有 100 种不同写法（10px、10.4167px、10.5px、11px、11.5px、12px、12.5px…） | 没有统一的字号阶梯，相邻字号区分不出层级 |
| 圆角 | 页面上 15 种 | 同一类卡片的圆角不一致 |
| 颜色 | 134 个十六进制写法加 45 个 rgb 写法；`:root` 变量分散在 `polish`、`nowdex`、`rhythm` 三个文件里 | 深色模式要靠逐个覆盖，容易漏 |
| 设计语言 | 主体是中性灰的 Nowdex 风格；设置页是 GitHub Primer 风格（`settings.css` 907 行，自带一套变量）；效率卡片是 Apple 风格 | 三处的视觉规则互不相同 |

### 4. 性能底线

`desktop-performance`（2 万行合成数据）在合并后测得 `maxSyncMs` 为 186.5，预算是 200。重做不能再加渲染开销。

**更正（2026-10-14 实测）：**原文推断"效率卡片那次改动让耗时翻倍"，这是错的。在改动前的 `c971693` 上实测为 389.8ms，所以 `c29ea12` 实际上把耗时降了一半左右。从 10-12 的大约 69ms 涨到 390ms，发生在中间那几次会话页和设置页的提交里，没有逐个二分定位。CPU 采样显示，每次切换时间范围时，最大的一块是趋势图第一次测量刻度文字时触发的整页样式重算，大约 50ms，起因是前面几个渲染步骤改了大量 DOM，而不是图表本身。

## 二、方案

### 原则

1. **只改外观，不改数据。** 未知显示为未知，未定价显示为未定价。数字格式和计算函数（`usage-math`、`insights-math`）都不动。
2. **保留测试钩子。** UI 套件依赖的 `id`、`data-*` 属性和 ARIA 结构一律不改。确实要改时，同一个提交里同步改测试。
3. **一种设计语言。** 以现在的中性灰主体为基础，原因是它覆盖面最大、迁移量最小。设置页和效率卡片向它靠拢，不反过来改。

### 分步（每步一个分支，单独合入）

| 步 | 内容 | 涉及文件 | 验收 |
|---|---|---|---|
| P0 | **样式规范层**：新建 `tokens.css`，定义颜色（浅色和深色各一套，文字、图形、状态色分档）、字号阶梯（11/12/13/15/18/24/32 加上总额大字）、4px 间距网格、3 档圆角、2 档阴影。旧文件的变量改为引用新变量，外观先保持不变 | 新增 1 个文件，改各文件里的 `:root` | 截图对比基本无变化；verify + layout / overview / detail |
| P1 | **合并样式文件**：17 个合成 4 层：`tokens` → `base` → `components`（卡片、按钮、分段控件、标签、表格、搜索框、空状态）→ `views/*`。删掉没用到的规则和 `!important`，目标是 `!important` 少于 20 处 | `index.html` 的样式引用、`serve.js` 的白名单、`audit:runtime` | 全部源码模式 UI 套件跑一遍。这一步影响所有页面，只在这里跑全量 |
| P2 | **外壳和用量页**：统一页头；用量页按"概览 / 分析"重新排版；去掉重复的数字和"采集来源"区；效率卡片改用通用卡片组件，并把渲染耗时降下来 | `index.html`、`preview.js`、`insights.js`、`views/usage.css` | overview / detail / layout / functional / motion + desktop-performance |
| P3 | **其余四页**：会话、来源管理（改紧凑列表）、设置（去掉 Primer 那套变量，改用通用组件）、额度监控（重做空状态） | `views/*.css`、对应页面的 `*-ui.js` | sessions / quota / agent* / polish / visual |
| P4 | **可访问性和文案**：落实第一节第 3 部分列出的问题，文案改写（用 `design:ux-copy`），再做一次深色模式对比度检查 | 主要是 tokens 和文案 | accessibility-review 复查；改到哪里跑哪里的套件 |

P0 和 P1 不改变外观，P2–P4 才会改。每步合入之前，在你看过演示页截图（浅色和深色、100% 和 150%）后再合。

### 不在这次范围内

新功能（工作台阶段 2–4）、数据口径、托盘、打包验收（这些归发布负责人"开发续进"）。

## 三、需要你决定

1. **设计语言**：建议以现有的中性灰主体为准。如果你更想要设置页那种 Primer 风格，或效率卡片那种 Apple 风格作为全局风格，P0 的取值会不同，工作量也会变大。
2. **用量页分段方式**：A 是同一页内分"概览 / 分析"两段，向下滚动；B 是页内二级导航，一次只显示一段。建议选 A，改动小，测试也少动。
3. **"采集来源"区**：建议删掉，或者保留为一行摘要。
4. **测试成本**：P1 必须跑一次全量 UI 套件，其余各步只跑受影响的套件。

# 费用页：费用与构成和模型明细合并（2026-10-17）

> 页面排版和新增的构成、按月、订阅对照、计价覆盖、缓存几块见 `UI-COST-PAGE-REDESIGN-20261017.md`；本记录中的表格、明细、CSV 导出和数据语义仍然有效。

用量页底部原有"费用与构成"（成本去向、用量占比、效率三张卡）和"模型明细"表，两处展示同一组数，算法却各自独立。项目负责人看过样稿后批准：合并成侧栏里单独的"费用"页（位于"用量"和"会话"之间）；默认按模型分组、按 Token 排序；加 CSV 导出；费用页有自己的时间范围，默认累计，不跟随用量页。本记录是这些决定和语义，实现以 `feat/cost-page` 的提交为准。

## 页面

- **汇总行**：API 等价估算（有区间时写出上限）、缓存约省下、每百万 Token、日均费用。每百万 Token 只除已定价的 Token；日均费用只除有用量的日子。
- **费用构成条**：按输入、输出、缓存读取、缓存写入分摊，斜纹段是估算区间（上限减下限）。
- **表格**：
  - "模型 | Agent"两种分组共用一套列：Token、占比、估算、每百万、单行构成、较前期。
  - 前 6 项之外合并为"其他 N 个"，点开显示全部，展开后只有一个"收起"。超过 12 项时出现筛选框。
  - 点表头"Token"或"估算"切换排序；按估算排序时，未计入的排在后面。分组和排序记在本机。
- **行内明细**（同一时间只展开一行）：
  - 模型：用量构成（各字段的 Token 和金额，未报告的写"未报告"或"部分未报告"）；计价依据和四项单价；未计入的原因，以及唯一可做的操作（"设置计费"或"调整计费"打开设置页同一个价格编辑器，来源没报告完整时是"查看来源"）；使用方；缓存命中率；每日走势。
  - Agent：所含模型的金额、计价覆盖率和走势。
  - 两种分组都可"在用量页查看"，即带上对应的模型或 Agent 筛选跳回用量页。
- **时间范围**：累计、30 天、7 天、今日，与用量页互不影响。"较前期"一列只在上一周期完整有记录时显示，累计没有这一列。
- 用量页去掉这两块；概览的估算旁边加"查看费用明细 ›"；效率卡里的"单次调用 Token"移到用量趋势卡的统计行。

## 数据语义

- 计算放在 `src/m1/cost-table.js`，窗口和主进程共用。未知保持 null：
  - 某字段所有日子都没报告的，为"未报告"；只有部分日子报告的，标记为部分；
  - 没有价格或用量不完整的，估算为"未计入"，写明原因；
  - 没有可比的上一周期时，变化为空。
- **估算区间不归到单一字段。** 区间可能来自缓存写入未报告、请求上下文长度未报告、推理数量未报告或按时段计价，按记录统计原因后显示在区间旁边。实现初期曾把整段区间标成"缓存写入至多 $X"；合成数据中 gpt 模型的区间实际来自上下文长度未报告，所以改掉了。
- 修掉旧模型明细表的两个问题：综合单价曾经除以全部 Token，现在只除已定价的 Token；估算区间曾经在表里被抹平，现在完整显示。旧"成本去向"把来源未报告的写入显示成 $0.00 的问题，由独立的"估算区间"项替代。
- 原因文字从渲染层移到 `src/m1/pricing-labels.js`，设置页的定价面板和 CSV 共用，说法一致。

## CSV 导出

- 窗口只传分组和日期区间（`usage:exportCost`）。主进程用自己的统计快照重新计算，写入用户选的文件（`mode 0o600`）。文件里的数字和名称都不来自窗口。参数不合规时拒绝（`EXPORT_REJECTED`）。
- UTF-8 BOM 加中文表头；每个模型或 Agent 一行；未知是空单元格，不是 0；来自日志的名称如果以 `= + - @` 开头，前面加 `'`，防止被表格软件当成公式。
- 只含聚合数字，不含会话 ID、工作目录或任何路径。

## 同方法性能测量

合成 20,000 日聚合行、100 模型、200 天。每种缩放做 16 次 today/7/30/all 的同步 click 提交，分别关闭动效及跟随系统；同时采样 RAF 间隔。下表是各组最大值，不能替代长时间分位数或真实显示器帧率。

| 环境 | 100% 同步提交 / RAF 最大间隔 | 150% 同步提交 / RAF 最大间隔 |
| --- | --- | --- |
| 本轮改动前源码基线 | 499.7 / 503.4ms | 368.3 / 373.5ms |
| 最终产品源码 | 152.6 / 156.7ms | 140.8 / 143.4ms |
| 新 Windows 包 | 143.7 / 146.7ms | 180.9 / 183.4ms |
| 中文/空格路径副本复验 | 144.2 / 149.9ms | 153.2 / 160.1ms |

源码同方法最大同步提交下降约 69.5% / 61.8%。这与历史 polish 文档的 334–364ms 是不同运行时点的结果，不混用历史数据来计算收益。数字仍用 760ms 呈现；同步提交和包含呈现的操作耗时分别记录。

新包 UI stress 启动 2385 / 2171ms；20 次范围切换最大端到端 874 / 200ms；20 次并发快照读取 3169 / 3552ms。其动效/操作条件与显式 off/system 同步采样不同，不能据此宣称呈现恒定耗时或高频 IPC 已优化。

首次副本性能运行触发 `<200ms` 门槛。当时脚本只在全部通过后写 JSON，因此没有保留下超标的具体数值，根因未确定。已修复采样留存：每组在断言前写 `samples-<scale>.json`，错误也包含实际值。保留原失败日志；使用同一门槛复验通过（144.2 / 153.2ms），没有降低门槛、跳过断言或强制点击。这个波动说明不能承诺所有运行都低于 200ms。

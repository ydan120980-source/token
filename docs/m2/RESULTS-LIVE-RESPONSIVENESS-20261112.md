# 本机实时用量与交互复测 · 2026-11-12

`codex/responsiveness-20261112` 继续优化 `2a6ede9` 留下的首次切页和长会话响应。状态为 **RESPONSIVENESS_REMAINS_OPEN / RAM_NOT_RETESTED**。

## 改动

- 费用分析和会话页沿用简明诊断。项目与预算、来源能力和完整定价目录由实际打开的入口读取。费用概要单独读取已启用的计价覆盖，保底和下限金额与已保存规则的计算结果一致。预算和来源诊断复用统计投影已有的时区日期，同一会话的项目归属在单次查询内解析一次。
- 费用首屏与覆盖区域直接按容器宽度布局，避免宽度测量后重新挂载卡片。分段出现的下方区域复用已渲染的首屏和走势。
- 先读会话页的选定范围，再读概要的近期列表。回访复用仍有效的结果，显式重载和失败重试仍会读取。传输解码按字典项校验重复的已知字段，会话行的操作按钮无需订阅整个会话状态。
- 阅读时用列表滚动事件记录位置。流式 JSONL 增大读块，Codex 工具输出只在可能含结构化返回时尝试解析 JSON。记录范围、未知用量和既有阅读动效沿用原规则。试验中的轮播高度与阅读动效改动已撤回。

## 采集与切页并行复测

采集器与统计查询共用一个线程。许多文件解析在同步执行后返回已经完成的 Promise，连续 `await` 只切换微任务，统计线程要等实际的 I/O 轮次才处理状态查询。采集现在在来源枚举、文件检查及解析的边界检查 12 ms 时间片，超时便让出事件循环。单个文件的同步读取和解析仍可能超过这个时间片。关闭会取消后续扫描，异步读取完成后会在启动原生校验之前检查关闭状态。扫描、原生总量校验和账本提交沿用同一数据口径。会话阅读复用同一份全部会话列表时省去重复通知，会话行复用已格式化的时间与时长。

运行 `npm.cmd run validate:local -- --performance --collection-overlap`。`resume-before` 是本次采集调度优化前的候选。`resume-final` 是最终源码。两者使用同一探针 `2f47d68ad6d0`，窗口均为 1482 × 962 DIP、300 Hz、125%，全程前台且无渲染错误。各读到 51,992 和 52,036 条实时用量、260 条日汇总和 387 份会话元数据。用于阅读复测的记录计数分别为 Antigravity 3,599 条与 Codex 2,989 条。

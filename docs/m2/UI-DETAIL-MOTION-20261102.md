# 概览对齐、统一详情、阅读页动效和 Codex 审阅 · 2026-11-02

所有者 2026-11-02 提出的修改。下面只用合成数据、源码模式验证过；动效只确认了结构和终态，没有人工看手感。

## 概览：Agent 卡片和上方组件对齐

**原因**：卡片用 `minmax(248px, 288px)` 的格子，到 288px 就不再变宽，右边留白；小组件的栏数按窗口断点变化。两者规则不同，所以对不齐。

**现在**：两者用同一个变量 `--home-column: 280px` 和同一个 16px 间距。网格和分栏算出的列数、列宽相同，任何窗口宽度都能对齐，不需要断点。

**这改变了所有者 2026-10-29 的“卡片不再变宽”**：默认窗口下卡片约 340px，最宽约 380px，仍是正方形。如果觉得太大，可以调大列数的门槛。

测试：`overview-ui-test` 在 1180、1480、1920 三种窗口宽度下断言外边缘、间距和列宽相同。

## 会话详情：和费用详情同一排版

- **位置**：改到左侧，可拖动关闭，和费用详情一样。
- **顺序**：大数字和徽章 → 六格数字 → 用量构成（`Breakdown`）→ 每日 Token 图 → 模型 → 会话。
- **六格**：Token、用量占比、每百万 Token、时长、缓存命中、缓存约省下，和费用详情对应。
- **去掉的小字**：底部“复制官方恢复命令……”，按钮的提示里还有。

同一个组件 `SessionFacts` 用在详情卡片和阅读页右栏，以后改一处即可。

**顺手修的**：kit 的 `Breakdown` 在详情卡片打开时，因为焦点落在第一行而自动弹出说明卡，还被挤出屏幕。现在只有键盘操作才会弹出（费用详情同样受益）。

## 阅读页右栏

右栏改成卡片，分四个标签：

| 标签 | 内容 |
|---|---|
| 概况 | 和详情卡片相同的内容，加“这段对话”：轮次、工具调用、子 Agent、上下文压缩、附带的文件、引用的记忆 |
| 命令 | 真正跑过的命令，可筛选，每次多显示 200 条 |
| 文件 | 改过的文件，点击只看相关的轮次 |
| 失败 | 失败的步骤，点击跳转 |

之前数字被滚动条遮住（所有者截图里的 `46.3 M`、`$10.99+`）。所有者看过第一版后说左右两栏占地方太多，现在目录 208px、右栏 320px，正文在默认窗口约 820px 宽。右栏用紧凑排版：大数字小一号，用量构成改成一列，数字格改小。测试断言内容不超出栏宽。

## 动效补齐

都走 kit 的弹簧，能打断，减少动效时改成淡入淡出。

| 场景 | 之前 | 现在 |
|---|---|---|
| 目录、右栏开合 | 瞬间出现，正文跳动 | 横向展开，正文跟着移动 |
| 查找栏、只看文件栏、记录更新提示 | 瞬间出现 | 展开收起 |
| 全部/只看对话/只看失败、只看文件 | 内容瞬间替换 | 淡入 |
| 上一个/下一个会话 | 内容瞬间替换 | 从对应方向淡入，标题也淡入 |
| 读取中到读取完成 | 瞬间替换 | 淡入 |
| 跳到附近的位置 | 瞬间跳转 | 平滑滚动 |
| 跳到任何位置后 | 没有提示 | 落点高亮一下 |
| 目录当前项 | 瞬间换位 | 高亮滑动过去 |
| 跟随时新来的轮次 | 瞬间出现 | 从下方淡入 |
| 右栏标签切换 | 不适用 | 淡入 |
| 并排新增一栏 | 不适用 | 从右侧淡入 |
| 操作条 | 不适用 | 从底部滑入 |

**有意不做**：并排时其他栏不做宽度动画。长文档逐帧重排容易掉帧，所以它们直接变窄。

## 修掉的 bug

**右侧摘要卡一直显示“正在读取会话”**：切换时间范围时，正在进行的读取被作废，之后没人重新读取。这是 `sessions-host.js` 和 `useSessions` 之间的问题，真实使用也会遇到。现在会重试，最多 3 次，避免读取失败时无限循环。

**后来所有者仍反复看到这个提示（截图里的右上角卡片），所以把根源也改了**，只有代码分析和合成测试，没有在真实数据上复现：

| 原因 | 现在 |
|---|---|
| 切换时间范围、每次新数据都让这次读取作废，切换范围本来和这份列表无关 | 列表有自己的版本号，只有新数据才让它过期 |
| 新数据一来就清空列表，卡片退回“正在读取” | 读取新数据时继续显示旧内容 |
| 读取作废后，不在概览页就没人再读 | 卡片在显示就会重新读取 |
| 读取失败时永远显示“正在读取” | 显示“会话读取失败，下次更新时重试”，有新数据时自动重试，不循环 |

测试：`tests/m1/sessions-recent.test.js`。如果真实数据下仍然常见，可能是采集忙时 `usage:sessions` 返回慢，那要另查。

## 保留的实现

- 跟随阅读用请求内的累计 SHA-256 检查点校验整个预览，只传输不一致位置之后的条目。来源仍重新读取；改写、截短、子会话插入、晚到工具结果都能退回受影响的检查点。窗口只复用它目前已显示的前段，没有新的正文缓存、持久化索引或来源写入；无参数的完整 TranscriptV2 路径兼容保留。全文／图片分页仍随新 stamp 清空；即使预览相同、只有未显示的尾部被改，旧版本全文请求仍拒绝。
- 流式读取把 `SOURCE_BUSY` 单独映射为 `TRANSCRIPT_CHANGED`。仅整份预览允许丢弃不完整结果、按新版本再读一次；持续写入在第二次失败时退出，其它 I/O 错误不重试，全文分页／查找不重试到新版本。实际变化通过合成源文件在读取中追加来复现，未关闭变化保护。
- 图表高度改用原生 ResizeObserver 的内容高度，在绘制前交付变化；费用页壳只订阅它真正使用的 760px 分界，构成图仍得到完整宽度、保留 400/600px 规则；portal 根引用在连接／归属／属性仍有效时复用，移除后重新查找。
- 阅读轮次不再把全轮索引展开为函数参数，修复单轮 50 万条目触发 `RangeError`；分组／权重减少临时索引数组，条目到轮次映射用连续范围填充。问题、子 Agent、压缩、失败、已知零和未知 Token 的语义保持。

没有修改 JSX 外观结构、CSS、字体或动效参数。CSS SHA-256 与基线相同：`5de2d63a7002613214397504c314f4e9d12b776b7933a978e8acd8b5178b286f`。

## 响应证据及限制

`interaction-benchmark.js` 使用默认窗口、原生显示设置、新建合成 home／usage／quota，6.4 万条统计、2 万份会话元数据、300 轮长记录。真实鼠标事件由 Event Timing 计时；`readyMs` 包含驱动等待，不称为 INP。滚动要求实际滚动位置变化。没有 CPU 采样器、截图、真实来源或固定 60 Hz 帧率。

私有 `perf-memory-20261106/interaction-ab` 的两轮 `d12e39f` 基线首次用量点击均为 328 ms；保留的三项测量修正加续传的 `after-1` 为 304 ms。费用首次点击约 104–112→104 ms，回访约 104→96 ms；收益有限。长会话就绪约 319–355→302 ms，含驱动等待，未证明更普遍的读取加速。对应滚动 p95 约 3.4–3.5 ms、最大约 10 ms，没有超过 50 ms 的帧间隔；最大主线程长任务约 188→170 ms，**仍不能称为不卡顿**。

后续合并 stack 尺寸观察、离屏调度、重新进入状态和无变化滚动短路的实验没有明确额外收益，全部撤回。私有 `rejected-chart-scheduling/experiment.patch`、`stacks-after-2`、`reconnect-after-3`、`visible-stacks-after-4` 保留，不冒充最后实现的回执。最后工具还增加了非空统计／Token 数检查和探针字节指纹；采用该新版工具的最后一对交替实测因锁屏尚未派发。

轮次计算是单独的纯计算对照：同一 5 万合成条目，两次预热后九轮交替，完整分组和权重哈希一致；中位约 3.86→2.00 ms。50 万条目的原代码先复现栈溢出，修复后通过。这不是 renderer 或 Windows 全进程 RAM 证据。

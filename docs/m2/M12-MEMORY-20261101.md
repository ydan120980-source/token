## 渲染器的正常回收增长策略

保留 `5441202` 的流式 JSON、草稿分支复制、增量聚合/传输和身份索引优化。固定 Electron 43.4.0 / V8 15.0.245.28 的渲染器，在既有 semi-space 4 MiB 之外，设置 `--heap-growing-percent=10`。现有明确指定的同名参数仍优先。

[该 V8 版本的声明](https://raw.githubusercontent.com/v8/v8/15.0.245/src/flags/flag-definitions.h) 和 [堆增长控制实现](https://raw.githubusercontent.com/v8/v8/15.0.245/src/heap/heap-controller.cc) 定义了 `1 + percent/100` 的增长因子。这里让正常分配触发的回收更早发生，以减少切页产生的垃圾长期占着空间。没有设置旧生代容量上限、减少历史、关闭 GPU/vsync、降低显示刷新率或调用 GC/内存压力/工作集裁剪 API。此参数依赖固定 V8 实现；升级 Electron 时须重新核对，不假定永久兼容。更频繁回收有 CPU/帧间隔取舍，因此必须连同交互、高刷新和实际新包复核。

2026-11-01 源码试验：100k、100 模型、500 会话、200 天；三轮导航、四次合成采集，合计从 10000694 增至 10000814。离散私有工作集最高 393.1 MiB，独立连续计数最高 414.7 MiB，最后约 306.6 MiB；私有提交量采样最高约 581.0 MiB，不能混为物理常驻 RAM。计数无缺值，实际最大间隔 801ms；不能据此宣称任何瞬间都有严格数学上界。`memory-next/growth10-source-20261101-100k/`。

共享 tooltip 的页面/可见性清理同时取消尚未提交的 rAF 指针提示，避免关闭后下一帧复活；新高刷新断言覆盖“当前没有提示，但已有排队更新”的情形。没有改变样式或动效档位。

# 发布验收发现的轻量诊断摘要与测试注入修复（2026-10-22）

正式打包验收首轮发现预算遗漏计数测试与来源失败恢复测试超时。两者仍修改主进程 Store／Service 原型；统计所有权移到独立线程后，这些原型不再参与实际请求。首轮日志与截图保留，不能称为首次通过。

预算测试改在实际 sender-guarded `usage:workbench` 与 `usage:attention` 返回值上注入合成计数，保留 general=7／budget=11 和隐藏已知悉后仍不能确认全部状态的原断言。交互可靠性改在实际 StatisticsService owner-command 边界模拟发现失败、保存命令失败、延迟及采集错误；仍检查实际 preferences 字节、历史统计、恢复、忙时重入和 UI 区分“已保存／发现失败”。不再声称直接注入独立线程内部磁盘错误；该原子性由已有存储单元测试另行覆盖。打包模式标记也改为实际 EXE 模式，避免结果误标 sourceMode=true。

定向复核另发现实际产品字段遗漏：轻量 `attention` 保存了 issues 和 budgetOverview，却没有复制完整工作台的 `omittedIssues`。当普通诊断超过返回上限时，后台来源摘要会失去“另有未返回项”的事实。新增真实统计 owner 回归以 510 个独立未定价模型构造超过上限的保存事实，先复现完整摘要 omittedIssues=11、轻量摘要 undefined，随后验证补回该字段。普通和预算遗漏保持独立、摘要键保持有界、统计账本字节不变。

产品修复仅复制已有计算结果，不新增扫描、配置读写、账号请求、诊断项、全量账本驻留或自动刷新，也不改变错误／未知数据的语义。单行统计 worker 变化需要新的 Windows 候选；首代次保留，最终使用 `dist/config-center-20261022-r2`，重新检查对应代码、ASAR／helper／native 与所有打包 UI。最终验收以 `RESULTS-CONFIG-CENTER-20261022.md` 为准，不能用旧包通过项代替最终候选。

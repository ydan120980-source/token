## 实施步骤

1. **冻结接入合同**：逐个列明 Agent、功能、官方格式或接口依据、只读数据字段、目录 / 固定网络端点、凭据需求、统计语义与验收样本。时间敏感格式与接口使用官方当前源码 / 文档核验。明确请求数与日志记录数、余额与额度窗口的区别；缺失值保持未知，不能制造费用或余额。
2. **实现适配器**：本地用量从 policy 路径/文件白名单、sources 字段投影、normalize 缓存/推理语义到 store 去重/迁移逐层接入；账号额度需要独立适配器边界、授权/凭据生命周期、最小网络能力和有效 keyring 校验。主进程、renderer、离线采集器不放开网络。未有可靠官方读取方法的 Agent 不宣称支持在线额度。
3. **接入桌面流程**：统一 Agent 元数据、来源状态、选择器、成本定价与显式模型映射；保留 Nowdex / Apple 风格、现有 Electron 技术栈、旧数据、连接与未提交改动。已有用户统计只通过必要且可恢复的迁移变更，不重建历史应用。
4. **主线程验收**：先做格式/合同和生命周期测试，再运行 verify、native、usage UI、quota UI、stress、crypto 与运行图审计。UI 使用独立 usage/quota 目录和合成 home，覆盖两种缩放、主题、错误/空态/未知值/零值、取消、退出、重启和减少动态；Windows 打包与独立中文/空格解压验收。真实来源及真实账号验收单独标识，并遵守相应隐私和授权边界。
5. **独立审查**：开发与主线程检查完成后，为审查提供明确需求、固定源码指纹、已实现行为、文件范围、测试命令、输出和已知限制。审查线程不修改产品、测试或文档源码，只运行隔离检查、读取证据并输出六方面的报告。
6. **修复 / 复验循环**：报告形成带编号、严重程度、证据/复现步骤、预期与实际结果、影响文件及建议验收的修复清单。主线程逐项修复并复测；每轮复验绑定新的源码指纹，旧报告不自动算新版本通过。无法确认的事项明确写出缺失的条件或资源，不隐去失败，也不以合成通过替代真实运行通过。
7. **交付与停止**：达到确认的需求和验收标准后创建独立新交付目录、源码 ZIP、manifest 与 SHA，核对 ASAR/当前源码、解压版及现存上一代完整性。总结通过项、限制及剩余人工/真实验证；不自动开启云、手机版、其他后续 Agent 或付费服务。

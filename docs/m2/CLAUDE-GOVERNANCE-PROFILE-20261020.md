# Claude 本机治理画像与独立泛化方向（2026-10-20）

本次只澄清规则与设计，不改安装器运行逻辑，不读取或修改真实代理、防火墙、启动包装、控制器凭据或治理配置。当前实现与历史授权见 [安装恢复合同](INSTALLER-RECOVERY-20261019.md)。

`127.0.0.1:17898`、`verge-mihomo`、`ClaudeNetworkPolicy` 共同标识所有者已批准的本机 Claude 治理画像。它包含固定 npm 原生 exe 路径、全防火墙 Profile、该路径的出站阻断、仅 loopback 的已核对监听所有者、全部安装 HTTP 经过专用 CONNECT、TLS 验证、无 DIRECT 回退、原路径备份/替换/复检/回滚。它是受控原路径升级的窄例外，不是面向公开用户的默认网络前提，也不证明完整工具树隔离或出口 IP。

## 后续独立实施方向（未获本轮实现授权）

1. **画像合同**：定义版本化、受信任的治理画像，约束可替换目标、受控传输、监听与进程身份、规则覆盖和备份恢复能力。只有实现并审核的画像可选；不能把现有常量替换成任意 URL/程序名/防火墙规则输入框。
2. **识别与明确选择**：产品展示已支持画像、可证明的能力、未知项及将写入的固定目标。元数据识别只作证据，不自动授权升级或网络探测；真实检查需要单独明确范围。公共用户可以继续使用已有独立应用目录安装合同，不应被要求复刻本机端口/进程/规则名。
3. **失效阻断**：监听身份、规则覆盖、目标字节/路径或配置版本变化时使预检失效。治理无法核验时停止受控动作，提供恢复说明；不得静默换成直连、普通代理或其他路径执行。
4. **运输与替换**：每个受信任画像提供固定传输策略及原路径版本复检；保持证书校验、哈希锁定、无任意重定向凭据转发、无暂存位置启动、冲突拒绝和原子备份/回滚。回滚失败阻断队列并保留可恢复记录。
5. **独立验收**：合成覆盖多画像、未知画像、监听/规则身份变化、取消竞态、目标并发更新、网络失败、替换失败及回滚失败。各平台/画像的真实治理验证与公开发布分别审批和记录，不能用合成测试或旧本机实测替代。

这里不新增画像、配置入口、远程服务或自动配置导入，也不放宽当前固定地址、进程、规则名或安装器动作合同。

## 所有者决定：Agent 色调

**这是对"中性灰、只用一种强调色"方向的一处明确例外。**

- 每个 Agent 有一个柔化的品牌色（`tokens.css` 中的 `--agent-*`，深浅外观各一套），只用在：
  - 额度条；
  - 圆环；
  - 时间线泳道；
  - 钱包第一张票据。
- 色调只表示"是哪个 Agent"，不表示好坏。
- 窗口剩余低于 20% 时，仍按原规则变为 `--warn`。
- 用量的多少仍不按好坏着色，所以节奏估算只用灰色文字。
- 票据上的文字统一用 `--on-agent`。

## 页面顶部（`#quotaOverview`，取代原来的四项概况）

**左栏：最快恢复**
- 已耗尽的窗口里，最早重置的那个；如果没有已耗尽的窗口，就显示最早的一次重置。
- 用细字重的大号倒计时显示，下面一行写明具体时刻，例如"明天 00:25"。
- 再下面是"接下来"，列出最多三件事：重置、恢复、积分到期。
- 两项统计：
  - 已连接 Agent 数 / Agent 总数；
  - 超过 1 天未更新的卡片数。

**右栏：额度时间线**，可切换 24 小时 / 7 天 / 30 天，所选范围保存在本机卡片偏好里。
- 每个百分比窗口一条泳道：从"现在"画到重置时刻，在重置处画一条竖线，标出剩余和节奏。
  - 已耗尽的窗口用警示色短条，并标出恢复时刻。
  - 重置在所选范围之外的，在条尾写"重置在 …"。
- 重置时间已过的窗口（待刷新）：同一连接合成一条斜纹泳道，写"等待下次读取"。
- 积分到期：同一天的积分包合成一个菱形，7 天内到期的用警示色；标签之间放不下时不再标注；范围外的写"另 N 批在 X 后"。
- **只比较时间，不合计额度**。周期性窗口不推算以后的重置（例如 Codex 的 5 小时窗口不一定按固定周期重置），只画下一次。
- 最多显示 6 条泳道，其余写"另有 N 项在各卡片详情里"。没有时间信息的连接列名说明。
- 窄窗口（容器宽度不超过 760px）时，左右两栏改为上下排列。

**需要处理条**（`#quotaAttention`）
- 每个需要处理的连接一项：名称、简短原因（服务消息的第一个分句）和修复按钮。
- 修复按钮：
  - 缺少凭据 → 重新连接或重新提供凭据；
  - 读取失败 → 重试；
  - Codex → 查看。
- 最多显示三项，其余写"另 N 个"。
- 点击"需要处理 N"会依次定位到对应卡片，沿用 G3 的提示框。

## 卡片

卡片仍是同一尺寸的正方形，按数据的形状选择一种布局：

| 形态 | 用于 | 内容 |
| --- | --- | --- |
| 百分比窗口 | Codex、Antigravity、Claude 等 | 最多两个窗口：细字重大号数字，Agent 色调分段条；条上有时间刻度（剩余模式下标时间还剩多少，已用模式下标时间已过多少）；窗口名后标节奏；另有一行金额 |
| 主窗口加子行 | 三个及以上窗口（如 Gemini 的多个模型） | 一个大窗口，下面两行小条，参照 Cursor 的参考卡片 |
| 双环加细条 | OpenCode Go | 每周、5 小时两个圆环，每月一条细条 |
| 钱包口袋 | 有合计的余额（DeepSeek 服务报告的总余额、WorkBuddy 积分合计） | 上方是最先到期的两张票据（7 天内到期的用警示色）；口袋里是合计；WorkBuddy 还显示一条按到期时间分段的条（7 天内 / 30 天内 / 更久 / 不限期），以及 7 天内到期的积分数 |
| 需要处理 | 全部连接都出错 | 顶部是原因和修复按钮，并写明"显示的是 X 读到的数据"；下面只保留主数字，调暗显示 |
| 无额度项 / 尚未读取 | 服务返回空列表 / 还没读过 | 空心分段条加说明（明确"这不代表额度为 0"），提供"重新读取"和"隐藏此卡" |

**节奏估算**：
- 计算方法：额度剩余百分比减去时间剩余百分比。
  - 差值 ≥ −5，显示"节奏充裕"；
  - 差值 < −15，显示"节奏偏快"；
  - 介于两者之间，显示"节奏正常"。
- 窗口已过去不到 10%、已耗尽、待刷新、无限，或剩余未知时，不显示。
- 悬停提示写明这是"估算：按本窗口至今的平均速度"。

**其他细节**：
- 超过 1 天未更新时，刷新时间显示为警示色。
- 积分包的票据只显示剩余部分，悬停显示原值。

## 同一账号合并成一张卡

后端 `1c41986` 提供 `duplicateKnown` / `duplicateAccountIds`。界面按以下规则合并：

- 已知是同一账号的连接合成一张卡，标题下写"N 个连接 · 同一账号"，悬停列出全部连接名。
- 卡片读取的是"没有出错、且最近一次读取最新"的那个连接；每个连接在详情面板里仍各占一段，各自刷新和移除。
- 只要还有一个连接能正常读取，卡片就显示完整内容，底部写"1 / 2 个连接需要处理"，需要处理条点名出错的那个；全部出错才显示需要处理的形态。
- 卡片的名称、位置和隐藏设置记在**最早建立的那个连接**上。这样，重启后身份变回未知、合并卡拆开时，这些设置仍然对应原来的卡片。
- 不同账号仍是不同的卡；身份未知的连接不合并；额度从不跨账号相加。

## 未连接的 Agent

原来是 200px 的小方卡，现在改为细线分隔的列表行，有空间时排两列。每行包括：名称、说明（一行，超长省略）、"连接"和"说明"按钮。

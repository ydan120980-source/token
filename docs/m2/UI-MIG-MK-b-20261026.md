## 已裁决问题：ChartLegend 无法表达已要求的联动与旧行语义

最高效力 `UI-MIG-M4-M8-RULINGS-20261025.md` §4.5 明确列出的接口只有：

```ts
ChartLegend({ items: { key, label, tone, hidden, note? }[], onToggle, minVisible: 0 | 1 })
```

紧随其后的要求是“图例行的悬停 / 聚焦与图中的 active 联动”。该接口没有向父级报告当前图例键或接收图表 active 的通道。`onToggle` 是显示/隐藏动作，不能拿它冒充指向/焦点事件。

旧 `cost-donut.js:39–43` 通过 pointerover/focusin 在图例和弧之间共享 active，更新中心读数并加粗对应弧；`126–130` 的图例保留未计价解释行、aria-disabled、原生 title、含金额/份额/切换说明的完整 aria-label。`cost.css:600` 对指向/激活行使用既有 fill 底色。M8 盘点 F15/F16 明确要求保留这些行为。现有接口也没有单行不可切换、title 或独立可访问名称字段。

不能在页面加悬停事件/改查 DOM 来绕过 kit 归属；不能把未计价行静默变成可切换行；不能把 title 与完整 aria 文案都塞进可见 label 改变原文案。

## 建议的最小接口补充（尚未应用）

```ts
// 保留原来的 items / onToggle / minVisible；只补：
active?: string | null;                      // 默认 null，父级受控
onActiveChange?: (key: string | null) => void;
// 每个 items 项只补：
disabled?: boolean;                         // 默认 false
title?: string;
ariaLabel?: string;                         // 未提供时沿用可见文本的无障碍名称
```

- 图例指向/聚焦报告 key，离开/失焦及 Escape 报告 null，父级与图表使用同一个 active；受控值同步激活行。保持原生 title 和已存在的读数内容，不新增悬停卡或格式化。
- disabled 只阻止显示/隐藏切换，以 aria-disabled 标记，保留焦点与解释读数；不能变成不可聚焦的 native disabled。原隐藏集合和至少一个已计价正值项的业务保护继续由旧 UMD 管理，组件的 minVisible 仍按裁决保留。
- 激活反馈采用旧版既有 fill 对应的规范语义 token，不增加颜色、尺寸、文案、布局或动效档位。

这五个可选字段原不在列表，已按 §9.4 停止后获得所有者明确批准。见 `UI-MIG-CHARTLEGEND-RULING-20261026.md`。按原裁决和本补充实现，再过 MK-b 的 gallery、双主题/键盘/减少与关闭动效/未知不为零、几何对照、verify 和 foundation 门槛；完成 MK-b 后才进入 M6。

## 已裁决问题：StepChart 缺少预格式化刻度标签

裁决 §4.8 的 StepChart 输入只有 steps、unlimited、start/end、tone、active/onActiveChange 和 aria-label；同节要求旧几何的三条水平刻度、四段时间刻度。§4.1 又要求页面提供完整文案，组件不格式化金额或 Token。

已核对旧 `quota-hero.js:146–161` 的 drawCredit：水平标签由旧 `m.short(top * f)` 生成，f 为 0、0.5、1；时间轴四段、五个标签，首项“今天”，其余由 `m.day(t)` 生成。这些字符串不在当前 StepChart 输入内。只画线而删除文字违反旧行为；在 kit 重新格式化数量/日期也违反分层约束。不能将假到期点塞入 steps 来携带坐标轴标签。

建议只补两个可选属性（尚未实现）：

```ts
ticks?: { value: number; label: string }[]; // 水平轴数量读数，由旧 UMD 原 formatter 提供
axis?: { at: number; label: string }[];     // 时间轴四段的五个标签，由旧 UMD 提供
```

不传时不生成标签或拿未知量补 0；原几何、三条网格线、四段时间轴、菱形/聚焦/合并规则不变。M6 始终传入从旧算法得到的三项和五项。数量只用于几何，精确文本原样显示，不在组件内做单位换算/舍入。`steps` 的起点投影沿用旧 c.now，首项 at=start 表示初始余额且不画到期菱形，后续项 amount 为该点之后的余额；这些均来自现有事实，不新增数据源或合计。

已按统一裁决 §1 和计划 §9.4 停止全部工作后，获得所有者明确批准两个刻度属性及上述起点语义。见 `UI-MIG-STEPCHART-RULING-20261026.md`。不推及其它未列接口，现恢复 MK-b 实施。

## 已裁决问题：Timeline marker 与滑块缺少原文案通道

原 §4.7 markers 只有 key、at、kind、tone、state，没有 label；Timeline 也没有接收 aria-valuetext 的属性。旧 `quota-hero.js:62–63` 给每个时间点提供 `m.clock(at)` 加到期/重置说明（到期还含原数量文案），`:95` 给滑块提供“现在/格式化时刻，N 个窗口已重置”。这些文本不等于 key、固定轴标签或图表整体名称，不能用整体 aria-label 代替每个点的独立说明，也不应让 kit 重写时刻和业务重置数量。

建议只增加（尚未实现）：

```ts
// 每个 markers 项：
label: string;
// Timeline：
"aria-valuetext"?: string;
```

由旧 UMD 按原算法提供完整文本，label 原样用于点的可访问名称/title，aria-valuetext 原样用于滑块；M6 总是提供当前时刻及重置数量的旧字符串。其它接口、图形、位置、针/ghost、单位和交互不变。缺省不编造读数、不拿未知补 0。

当前 Ring/Bar/Line/Step 初版和几何/common/legend 均未 export 到产品，产物没有重建；只过局部类型、设计 guard 和几何测试，尚未 gallery 或 MK-b 全部门槛。按 §9.4 暂停所有工作。建议所有者在批准本两项后，允许先只读核对剩余 MK-b 接口，将任何其它必需缺口一次列出再裁决；该只读核对不授权实现新接口。

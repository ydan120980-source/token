## 配对、权限与密钥生命周期候选

1. Windows 是 writer，未来查看设备是 reader。一次性配对凭证短时有效、一次使用，通过用户确认的本地渠道交换；双方确认设备指纹并绑定方向/角色。relay 不能替换身份，配对材料不进入聊天/仓库/日志。具体交换协议与加密库需独立评审，不能把 AES 实验视作已完成配对。
2. relay 按 writer 的写入能力与 reader 的读取能力分离授权；reader 无上传、删除、设备管理或控制电脑接口。加密密钥不能兼作 relay 写权限。共享对称密钥的 reader 能生成 GCM 密文，因此还需 writer 身份签名与 reader 固定验证公钥，不能仅用 AEAD 证明写者身份。
3. 数据密钥与设备身份私钥在经有效配置验证的 Windows keyring 中保存；不允许明文 fallback。身份密钥、epoch 数据密钥、relay 能力分离，renderer 不接触秘密；初次/轮换密钥分发需认证的配对通道。
4. 每次轮换建立新 epoch 与新随机密钥，并重新授权仍保留的 reader；撤销同时拒绝 relay 能力并切换未来数据密钥。已下载/已解密的历史无法撤回，必须明示这个限制。
5. 恢复方案尚未确认：默认不实现任何恢复路径。恢复码、本地备份或重新配对的选择影响密钥保存与历史可读性，实施前向用户确认。不能因 reader 重装就清空防回放水位，也不能暗中保管云解密密钥。

## 防重放、nonce 与不可信 relay

未来 nonce 候选为每个随机 epoch 密钥对应固定 32-bit 前缀 + 64-bit 单调计数；只允许一个 writer。发送前原子持久化预留序号/nonce，失败可跳号、不重用；备份还原/状态缺失必须轮换密钥与 epoch。这个候选需要按选定库及跨平台字节序规范复核。AAD 与签名输入使用确定的二进制或明确固定序列化，覆盖协议/设备/epoch/角色/sequence；拒绝未知版本、非规范编码、超限长度。

reader 按 writer + epoch 持久化最高已认证 sequence，先验证签名/AEAD/内层绑定，再将快照与水位作为同一原子事务提交，持久化成功后才显示或确认收件。崩溃、重启、损坏、回滚、旧 epoch 都要 fail closed 或显式重新配对，不能降级为内存水位。重复投递是幂等结果，不二次应用；epoch 更新需由固定 writer 身份认证，不能由 relay 单方面宣布。

原子文件本身不能识别一个仍然有效的旧备份被恢复。可信水位/回滚检测机制尚未选定；在这项解决之前，不能宣称抵抗有本机权限的状态回滚，也不能宣称生产 nonce 安全。受支持的备份恢复流程必须新建 epoch/密钥，不能把历史 sequence 直接当作发送计数继续用。

relay 仅保留密文与必需的路由/epoch/序号/大小/接收时间元数据；这些仍会暴露活动时间和大小。不能读取统计，不能以它的时间作为统计权威。离线队列有界、重试退避、最新快照可替代未发送旧快照；采集与额度服务不依赖网络成功。正式网络模块需最小能力隔离，不能去掉现有 main/renderer 全局网络禁用来恢复上游 Hub/Worker。

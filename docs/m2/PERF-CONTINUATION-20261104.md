- 不强制 GC、裁剪工作集、设置内存上限或关闭 GPU / vsync；不增加会话正文缓存。后台只保留原来允许的已保存统计事实。

## 实现

1. **内部采集记录共享。** `sources.js` 默认公开扫描仍克隆隔离；后台所有者通过 `borrowRecords` 共享冻结的普通统计记录，跨来源会原地合并的 sharedKey 记录继续复制。`worker.js` 使用该内部路径。跨来源去重、追加/删除、数据库变化、调用方修改、失败回滚和增量投影测试通过。
2. **按真实会话计数失效。** `preview.js` 不再把每次 `sessions-change` 都当成统计事实变化，比较实际保存计数后才重建用量投影。现有 Today 套件补验证：无关会话事件保持 view 身份、未知保持 null、真实零替代未知；实际五秒采集稳定、真实筛选仍更新，均通过。
3. **会话列表的后台表示。** `Store` 同一个选择的缓存改为弱引用完整对象和紧凑传输字节；IPC 返回独立 Buffer 副本，防止转移使缓存失效。不是新增第二组缓存或正文缓存，选择/快照变化仍替换。原有 Store 调用持有对象时仍得到相同引用。会话、范围、写入一致性和重启存储测试通过。
4. **更低开销的计数器。** 新的 Windows 11+ PDH `Process V2` 采样器以 PID 关联进程，原生约 100 ms 采样；Windows 10 保留 CIM 分支，亦可显式 `MEMORY_COUNTER_BACKEND=cim`。新的父子进程 40+24 MiB 分配测试确认全部计入、调用方不计入，并与 CIM 对照一致。缺失采样或最大间隔超过 500 ms 不算可靠采样。源码报告增加后台及数据 host 文件 SHA，不能只拿未变化的 UI bundle SHA 证明后台版本。
5. **逐会话生成已保存事实。** 后台先按既有顺序分组记录引用，再逐个会话聚合与编码；不同时保留全库的聚合 Set/Map 和完整对象图。公开数组接口、持有对象的引用身份及同一选择的编码字节缓存不变。独立旧实现对照覆盖交错记录、所有时间范围、recent、未知/零、元数据和逐字节传输一致性。
6. **扫描只准备所需的身份。** 跨会话查找、文件历史、工具使用只生成 key/agent/end 引用，再按原顺序筛选与分页；不为寻找源文件而计算所有会话的每日费用。保留原来的候选成员语义，不暗改时间范围对成员的处理。回归要求这些操作在费用估算器禁止调用时仍给出相同候选、分页和汇总结果。
7. **共享重复的原始字符串。** 只处理刚解析的程序自身保存事实，临时 Map 复用 sessionKey 和最多 4096 个短字符串。函数返回后不保留索引，不合并可变对象；数值、null、属性顺序和保存字节不变。复制整棵事实树中每个字符串的 UTF-16 方案曾使扫描峰值升到 514.48 MiB，已撤回，仅保留小范围原始字符串复用。

上述追加实现的首次五类诊断为：扫描 507.14、对比 455.86、三栏 440.72、两栏 441.56、全部会话列表 411.05 MiB。扫描仍超标，不以较好单轮代替稳定结论。随后采样器增加同一次 PDH 查询的逐 PID 归因，完整源码和夹具指纹也增加新字符串模块；最终复测在结果记录中单列。

随后追加的会话分段解码：同步与异步 facade 共用验证生成器；原始 ArrayBuffer 不变，私有解析帧的已消费行可释放，所有行验证完成后才交付完整列表。约 4 ms 检查点以 MessageChannel 让出任务队列，端口在完成/异常时关闭，不使用正文缓存或持久任务队列。20000 行微基准五次交错的总时间中位 46.5 → 47.9 ms，最大帧间隔的中位 42.6 → 6.8 ms；这是同一新生成器两个 facade 的隔离调度对照，不是实际产品版本或 RAM 对照。scheduler.yield 未获得稳定帧收益、每 256 行等待 rAF 导致总时间升至约 523 ms，两者都未接入。原 JSON.parse 与单个复杂会话本身仍不可中断。

## 采集基准

新增 `owner-refresh-benchmark.js` 测真正的 StatisticsService 所有者路径：建所有者、解析、原生校验、完整入账、持久化以及窗口实际取的 packed response。夹具 2000 文件 / 40000 条 / 4,800,000 Token；增量严格要求 40001 条 / 4,800,099 Token。任一方零记录、缺失新增记录、原生校验未 passed 或记录语义哈希不同都会失败。

运行时需为没有 node_modules 的对照 checkout 提供本工作树的 `NODE_PATH`，不得为了基准修改共享 main：

```powershell
$env:NODE_PATH = Join-Path (Get-Location) 'node_modules'
$env:OWNER_FILES = '2000'
$env:OWNER_RUNS = '3'
node scripts/m1/owner-refresh-benchmark.js '<workspace-parent>/token-worktrees/perf-baseline-25574d5/src/m1/statistics-service.js' '<现有证据目录>/owner-ab.json'
```

三组交错的初步中位数：与 `25574d5` 同一条所有者链路比较，full 4064.64 → 1980.53 ms（2.05×），incremental 3035.56 → 1119.35 ms（2.71×）。与当前 main `1f36b10` 比较，另一轮是 3129.97 → 2191.93 / 1877.23 → 1166.25 ms。以上是 CLI Node 初步口径。

**后台 2157d54 / 3be9061 时的五次：** 使用产品 Electron 43.4.0 的 Node 24.18.1（`ELECTRON_RUN_AS_NODE=1`，通过 Node `spawnSync` 等待 Windows GUI EXE 退出），交错原始 `25574d5` / 当前后台。冷启动中位数 **3476.74 → 1552.33 ms（2.24×）**，单文件增量 **2690.60 → 913.99 ms（2.94×）**。全部 20 个样本严格记录数量、Token 和原生校验通过，两个版本各轮统计字段语义哈希相同，`valid: true`。此结果覆盖本轮已提交的后台 `2157d54` / `3be9061`。**同一已声明的端到端合成负载达到 2×；不保证所有工作负载，不把新所有者口径与旧 Service-only 的 2820.5 / 1916.6 ms 混比。**

为排除计时边界变更影响，又增加 `OWNER_CHAIN=service`，保持旧基准的 `Service.refresh()` 边界，构造在计时外，刷新仍完整解析、原生校验、入账、写盘、返回快照。相同产品运行时、夹具、交错五次：冷启动 **4932.77 → 1829.99 ms（2.70×）**，增量 **3085.31 → 1142.79 ms（2.70×）**，所有样本数量、Token、语义哈希、两 Agent 原生校验通过。原始报告为 `codex-service-final5-20261104.json`。这里“冷”指新 Store / Worker，不是清空操作系统文件缓存；绝对耗时不能与其他运行时或历史磁盘状态混比。

后台的另一项改动是流式 native 校验输入：每次仍验证固定 native 程序的 SHA，使用 1 MiB 缓冲读取并检查读取前后文件身份；规范 JSON 分块写出，不缓存校验结论。正样本加零值/过滤负样本实际通过固定 native 程序；规范输入字节黄金 SHA 保持不变。

## 已排除 / 失败记录

- 零拷贝、OpenGL、D3D11-on-12 试验未发现可信达标方案，均未改产品默认参数。早期 GPU wrapper 在完整 workload 后调用 `getGPUInfo('complete')` 时连续采样器尚未停止，可能计入额外初始化；这些带 GPU 查询的结果仅作诊断，不拿来与普通验收作精确收益对比。
- 放宽读取 Worker 跨记录复用的一行试验没有内存收益，已恢复原逻辑。
- Graphite 试验因旧 CIM 采样器启动未就绪而失败，不是通过；当时也发生了显示环境切换。
- 新所有者基准的初次零记录来自对照 main 缺 `@tokscale` 依赖。补单次执行的 NODE_PATH 后有效。不是已确认的产品解析缺陷。
- 下载 Electron 校验的第一条匹配式没容纳官方 SHASUMS 文件中的 `*` 前缀，曾安全拒绝继续；实际 ZIP SHA 与官方一致，修正匹配式后才解压。
- PDH 最早原型错误地用经典 Process 的非唯一名称关联，父子进程测试失败，未用于任何应用通过记录。修正为 Process V2 后，PID 字段名称也按实际 counter schema 改为 `Process ID`，重新对照通过。
- 一轮完整 verify 仅 Windows Claude statusline helper 的 15 秒子进程期限失败；独立重跑该项及后续安静环境整轮 verify 通过。另一次最终检查先因探针的 requestAnimationFrame 全局声明缺失而 lint 失败，修正后完整通过；保留初始失败日志。
- `Service` 边界新增模式首次 smoke 因误把 owner 专用第五参数传给旧构造器而产生零记录，报告按设计失败。修正调用后 20 文件 / 400 条 smoke 和最终大负载均通过。此为基准调用错误，不能作为产品零记录通过。
- 整页 `useDeferredValue` 试验让路由先切换，却把实际内容到下一帧从约 123 ms 推迟到约 187 ms，已撤回。没有采用“先空页”制造响应数字。
- 通用 Marquee/filter/plot 测量抽象没有可靠收益，已撤回。最终仅保留图表自身的原生宽度观察，不引入通用调度框架。
- `codex-native-chart-batch-leave-20261104` 曾在 build 未退出前启动探针，属于旧 bundle / 新源码混合证据，作废；保留随后等 build 退出的 r2 结果。CPU profiling 数字只用于归因，不当验收耗时。

# 内存、启动与响应优化（2026-10-22）

项目所有者要求检查当前项目并整体优化内存、启动速度和运行流畅度，随后确认均衡优化、允许合成测试占用屏幕、不改变视觉样式的必要渲染优化，以及分阶段调整统计处理架构，并授权开始实施。基线为本地 `main` 的 `7e3b669`。这不启动未指派 Backlog、真实来源／配置／账号操作、远程同步或正式打包。

## 实施顺序与合同

1. 建立可重复的合成基线，再改启动关键路径。
2. 取消 preload 同步获取完整统计投影；正常重开未变化账本不写盘。首屏保留未知／加载状态，不展示演示数字。
3. 一个统计工作线程负责 Store、采集、原生验证调度、归并、聚合和持久化。主进程只持有轻量代理与必要元数据；额度网络、安装和显式配置检查维持各自隔离。
4. 按需加载完整会话和管理详情；首页计数与来源角标走轻量摘要。已有桥接读接口返回形状和 `snapshotRevision` 语义保持有效。
5. 限制解析缓存，合并重复请求，释放失效临时对象，最后运行综合回归和长期采样。

窗口、权限检查和系统对话框仍由主进程负责。统计命令集封闭，写操作顺序执行，整批持久化后才发布新版本；失败保留历史数据。工作线程失败后的重建从已保存事实恢复，不重放未确认的写操作。JSON 保存格式、未知值、冲突保护、备份／隔离、来源白名单、SQLite/WAL 只读与原生二进制校验不变。

解析结果缓存初始预算为 64 MiB **估算载荷**和 2,048 个文件，先达到哪项即淘汰；小型指纹索引独立保留且有界。缓存预算不是进程 RSS 上限；淘汰只影响重读，不删除历史。

## 实现边界与维护入口

`src/m1/statistics-service.js` 是主进程代理，只镜像设置、来源状态和目录元数据，不持有账本、会话全文或完整投影。`statistics-worker.js` 是唯一统计状态所有者，复用 `Service` 和 `worker.js` 导出的独立 executor；修改操作排队，读取返回最近一次完整提交的事实。工作线程的网络默认关闭，定价同步仍使用既有固定公开地址子进程。退出会取消采集并关闭定价进程；线程故障拒绝待处理请求，下一次读取从磁盘恢复，版本号保持进程内单调。未确认的修改不会自动重放。

主进程仍验证 IPC 发送方、用户路径与系统对话框；统计导出在工作线程重新走原白名单后，由主进程异步写入用户选择的目标。`usage:get` 的对象协议保留；界面内部的 `getPacked`／`refreshPacked` 传送 `LocalUsageColumnsV1` ArrayBuffer，页面适配器恢复原 `usageBridge.get/refresh` 形状。编码只作用于白名单投影，字典、列布局与不可变计数映射保留 null、零、未知价格和冲突语义；同版本仍返回空快照表示未变化。磁盘 JSON、导出和保存查询协议不变。

故障恢复另保留进程内的已启动标记：替代线程恢复原设置允许的采集／价格同步安排，首次启动仍由窗口加载后的 `start` 触发。`start` 幂等，关闭优先于恢复启动。实际线程测试先复现“恢复历史但未恢复采集”的失败，再验证无需手动刷新即可重新得到 `checkedAt`；Electron 测试分别验证停采集时账本不变与启用采集后的恢复。

启动时先显示加载状态，再异步取得用量；完整会话仅在会话页请求，首页使用轻量计数。价格目录与大选项列表在费用／设置／编辑器首次使用时加载，同类请求合并；失效的异步编辑器请求不会在导航后重新打开。最小化期间保留最新数据并延迟用量重绘。解析载荷 LRU 与最多 100,000 项的小指纹索引分离，缓存淘汰不破坏安静扫描判定。自定义来源预览按原期限主动回收，配置编辑器关闭只释放匹配上下文并保留原加密撤销能力；被动额度定时器仅在存在被动连接时运行。

`usage:performanceState` 是受发送方保护的内存计数接口，只返回请求／完成／失败／并发／工作线程启动次数及传输字节，不接受参数，也不读取账号或来源。该接口用于测试生命周期与队列是否收敛，不是包含路径、ID 或原始错误的诊断出口。

## 测量方式

`npm.cmd run test:performance -- --repeats 10 --output <证据目录>`：空账本、2 万、10 万条记录，各自使用合成 home 和独立 usage/quota 目录，不查询真实账号。每个场景聚合最多约 2 万日行和 2 万小时行；不放宽投影上限。

- `--entry <原始 main.js>` 可用同一驱动测未修改基线；`QUOTA_PACKAGED_EXE` 留给另行批准的打包验收。
- `--rows 100000 --repeats 1 --soak-minutes 60` 用于长期场景；采样记录进程私有内存、工作集、主进程延迟及刷新次数。
- 窗口加载、数据可见、空闲内存分别记录。磁盘缓存未控制，不称为严格冷启动；不强制 GC 或修改 GPU／系统策略。
- `--idle-ms 30000 --memory-samples 5` 在数据就绪后第 30、35、40、45、50 秒取样；基线与候选使用相同设置并重复启动。3 秒启动期值与这组稳定期值分别报告，不能交叉计算降幅。
- 页面就绪只向驱动返回布尔／数值，不能通过 CDP 返回完整快照。初版驱动违反此条件，抬高耗时与内存，相关探索证据保留但不参与验收。CPU profiler 采样也不混入正式时间比较。
- 性能测试串行执行，不与其他性能或界面套件竞争；真实来源、物理 DPI 和严格冷启动需要独立证据。

## 目标与验证

目标是首屏可操作 P95 不超过 2 秒；2 万／10 万记录统计就绪 P95 不超过 3.5／5 秒；有数据场景进程私有内存中位数比重复基线下降至少 20%，同时报告 GPU 与非 GPU 分项；主进程事件循环延迟 P95 不超过 50 ms；既有 2 万行切换同步耗时 P95 不超过 100 ms、最大值仍低于 200 ms。

长期场景持续 60 分钟且至少 100 轮刷新；比较预热后与末段内存中位数，末段不高于前者 10%，并检查线程、监听和进程回收。目标与已执行结果分别记录，不以窗口更早出现替代数据就绪或内存改善。

每个接受增量提交代码、测试及文档。完整验证包括 `verify` 的 `fail 0`、`audit:runtime`、采集／存储对应的 `test:native`、定价对应的 `pricing:check`、受影响的源码 UI 套件与桌面性能套件；最终结果写入独立验收记录。只在全部本地合入门槛通过、共享树干净且没有其他合入进行时合入本地 `main`，不产生 `dist/<generation>` 或源码归档。

验收收尾时，所有者在约 24 分钟持续运行后表示“差不多可以了”，据此提前结束该项并完成原先已授权的本地收尾。实际为 24.94 分钟／99 次刷新，原定 60 分钟／至少 100 轮保持未完成；其余本地合入门槛照常执行。完整数据、目标偏差与原驱动因正常关窗而产生的 exit 1 见 [验收记录](RESULTS-PERFORMANCE-20261022.md)。

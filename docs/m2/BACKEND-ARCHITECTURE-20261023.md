所有者在架构评估后明确要求执行三项建议：整理核心服务接口与状态边界；集中服务商适配并补充可观测性；根据实际规模测量决定存储演进。本增量基于本地 main `032c914`，在独立主题工作树完成。保持 Windows Electron／CommonJS、现有样式、数据格式、额度／身份语义及真实数据边界；没有子代理、在线依赖安装、真实来源／配置／凭据维护或账号查询、其他服务商自动刷新、发布打包或远程 Git 操作。

## 统计服务和协议

`StatisticsService` 是主进程应用服务，统计线程独占 `Store` 和完整账本。主进程不再持有名为 `store` 的模拟对象：工作台、价格、会话、来源修改和导出使用显式方法；`facts()` 返回从线程同步的独立副本，修改该副本不改变线程状态或磁盘。保存失败的回滚归真正的 Store 负责，主进程不再回写镜像掩盖失败。现有 renderer IPC 的参数、返回形状和错误语义保留。

`statistics-contract.js` 集中定义读、修改、关闭三类命令。只读请求可在异步采集等待时处理，修改仍按原队列串行，关闭可以越过队列取消工作。线程和服务入口共同使用固定名单，线程启动时检查实现与名单一致。未知／原型成员不能作为方法调用；已有页数、缓存、排队及时间限制保持。线程异常后恢复保存事实与此前已启动的采集安排，不重放未确认写操作。

协议和状态增加 JSDoc 说明；已有 ESLint 对主进程增加禁止访问 `usage.store` 的所有权约束。这不是引入 TypeScript 编译器，也不宣称全仓库静态类型校验。

## 固定内置服务商适配

`provider-adapters.js` 注册现有 17 条 HTTP 读取路线。纯资源解析迁到 `provider-adapters/` 对应模块，通用格式校验和 AccountQuotaV2 投影仍由 `provider-resources.js` 统一执行。组织／工作区选择、Google 项目发现、MiMo 多段观测、WorkBuddy 有界分页与所属适配器放在一起；实际 HTTP 和分页能力由原 IPC worker 注入。Claude OAuth 与网站只共享解析，OAuth 不执行网站的组织发现。

没有动态插件、可选执行路径或 renderer 提供的 URL。固定域名、请求方法、认证范围、子进程、凭据续期、CLI 固定映像和身份识别模块仍按原合同执行；登录和凭据权限不混入纯解析器。运行依赖审计新增适配器直接依赖白名单，阻止这些模块直接引入文件、进程或网络能力。

合成 parity 文件记录重构前 `032c914` 对全部 HTTP adapter 的正常响应输出，回归逐字段比较精确金额、标签、未知字段、资源单位、覆盖状态和生命周期。其内容是合成输入与输出，不含真实服务响应。原有分页、同账号、换号、错误／取消、保存失败与重启测试继续保留。

## 有界诊断

所有诊断只累计固定键的标量，不保存账号、路径、凭据、响应体、异常文本或逐请求数组，也不写入统计／额度缓存。

- Store：采集提交路径 clone、digest、persist、projection 的次数、耗时及失败数；投影原因区分首次、账本版本、时区、日期、显式失效，另计缓存命中。不是所有配置／偏好文件 IO 的审计。
- 统计线程：资源打包、会话索引和缓存命中、快照版本变化。
- 主进程门面：原有请求统计，加异常线程退出、超时和命令拒绝计数；旧 performanceState 形状保持。
- Provider：刷新排队、成功、失败、取消、跳过及认证／限流／保存失败分类，另记刷新执行时间。失败可被业务层捕获，分类计数与 Promise 是否抛出分别表达。

新增 sender-guarded `usage:statisticsDiagnostics`／`usageBridge.statisticsDiagnostics()` 只读取上述统计内存诊断。线程已经退出时返回 `owner: null`，不会为读取诊断重启线程或恢复采集。Provider 的 `diagnostics()` 是内部服务接口，不新增账号请求或自动刷新。读取诊断不扫描来源、不重算投影、不读取凭据。

## 存储测量和决定

`node scripts/m1/storage-benchmark.js` 每个规模启动新 Node 进程，默认 2 万／10 万／20 万条合成记录，每组各三次无变化完整扫描和新增一条记录的提交。测量不含来源解析、CLI、网络或 GUI。分别检查无变化时文件字节／版本保持、缓存读取、重启与保存查询合计、未知价格语义；操作阶段时间可重叠，不能把它们当独立总耗时相加。

内存记录注明阶段：预热、刷新、额外重启 Store、额外保存查询模型。进程 RSS 峰值还包含 seed 数组和这些同时存在的模型，不能作为产品稳定私有内存、连续峰值或泄漏证据。磁盘缓存未控制，每组小样本只作为该次测量证据。

首轮测量确认一次完整 built-in 扫描重复计算最终账本摘要。现在复用 `ingestDraft` 已计算的草稿摘要；自定义来源修改仍会清除该摘要并重新计算最终批次，保证整批原子提交。新增回归同时覆盖无变化字节保持和后续自定义事实正确保存／重启。

本增量保留 JSON 格式与现有备份／隔离流程，没有做数据库迁移。当前目标规模先消除已定位的重复工作，并利用有界诊断观测后续数据增长。若目标账本的读写／重投影持续超出采集和交互预算，再另立存储迁移合同，涵盖保存查询兼容、版本迁移、失败原子性、备份、回退与合成验收。不可仅把 JSON 改成数据库就宣称问题解决。

测量环境为本机 Node 24.13.1；优化前后均按上述流程、每规模独立进程顺序执行，各三轮。结果为本次样本中位数，未控制磁盘缓存和 GC，不作统计显著性或产品端到端性能承诺：

| --- | --- | --- | --- |
| 20,000 | 5,899,277 字节 | 143.9 → 118.9 ms | 271.7 → 239.3 ms |
| 100,000 | 29,553,684 字节 | 976.3 → 701.3 ms | 1,642.1 → 1,281.9 ms |
| 200,000 | 59,321,684 字节 | 2,174.1 → 1,492.2 ms | 3,876.4 → 2,698.8 ms |

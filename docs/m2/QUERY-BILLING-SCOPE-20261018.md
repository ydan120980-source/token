## 阶段 2 读取范围澄清

原方向文档的“只读 statistics.json”描述了事实来源，但当前 GUI 与 `readSavedSnapshot` 已使用应用自己保存的四个文件共同计价。本轮将这一现有实现明确为封闭白名单：`statistics.json`（归一化用量）、`billing.json`（用户计费设置）、`pricing.json`（用户费率）、`model-pricing.json`（已保存价格目录）。后三者可缺省，采用与 GUI 一致的默认值和嵌入目录。禁止读 preferences、来源配置、认证、会话元数据、工作目录、原始日志、文件索引或任意请求指定的文件。查询参数不能修改数据目录；目录只由启动命令选择。

这不是扩大到 Agent 数据的授权：四个文件均属现有应用自有存储，复用现有计价核心，不创建 Store 实例（构造器会迁移/写盘）。`statistics.json` 中只使用归一化用量及去重标记；会话计数仅内部使用已有不透明 sessionKey，不访问 `sessions` 中原始 ID/cwd。注册的自定义来源只用于识别 agent ID，不导出映射、来源路径或索引。

四文件分别原子替换；查询对整组做两次字节读取并比较，变化时有限重试，仍变化则受控失败。每次请求重新读取，不缓存过时计价。此保证是稳定读取区间中的已保存状态，不承诺与同时发生的 GUI 编辑跨进程事务一致；GUI 同样按当前已保存账本和价格重算。旧账本缺失会话标识时计数为 null，并单独报告未归属记录，不能当 0。

## 查询输出与约束

唯一查询工具 `usage_query`：按日期、Agent、模型、provider、入口筛选；按这些固定维度分组，输出 token 桶、缓存命中率、成本上下界、已/未计价覆盖、会话计数与未归属记录。使用白名单逐字段构造结果。绝不输出路径、原始/散列身份、记录、配置映射、文件索引、项目、会话正文或恢复命令。错误只含受控码，stdout 仅协议。

日期必须为真实 YYYY-MM-DD，范围有界且开始不晚于结束；数组/字符串/组数/响应字节/协议行长度均设上限。分页为稳定排序后的 offset/limit，并在响应中标明剩余行。非法字段拒绝，不能静默忽略。空结果的未知桶/成本/会话数为 null；显式已观测零保留 0。费用是 API 等价估算，含未定价用量时不能称完整费用。

CLI 和 MCP 共用查询模块；GUI 与查询复用 Store 的 estimate/resolvePrice 和迁入 src/m1 的 usage-math。MCP 遵守 [官方 stdio 规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)：UTF-8 JSON-RPC，每行一条，日志走 stderr。使用 SDK 实际外部客户端验证启动、initialize、tools/list、tools/call；Windows 打包 EXE 以 ELECTRON_RUN_AS_NODE 运行 ASAR 内入口另测。开发验证构建仅放 artifacts，不生成正式代次、归档或替换运行包。

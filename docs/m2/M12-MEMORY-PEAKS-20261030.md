# M12 内存削峰续进 · 2026-10-30

所有者看到已交付候选的内存结果后明确选择“继续削减切页峰值，暂不推送”。保留 `af35e95` 和 `dist/20261030-M12-candidate` 的完整功能验收；它们不是后续内存改动的验收。继续只用合成数据，不合入 main、不推送、不读取真实来源或认证文件，不通过强制 GC、删历史、关闭 GPU 或硬限制旧生代达标。当前 CodeGraph 工具仍不可用，使用定向源码、测试与测量。

第一项改动是大账本加载：原来 `readFileSync(...,'utf8') + JSON.parse` 会在创建所有记录对象时同时保留整份大 JSON 文本。现在仅对应用自有 `statistics.json`、大于等于 4 MiB 的文件，以 64 KiB UTF-8 块读取顶层 records 字典，逐条交给原生 JSON.parse。磁盘格式、未知保存字段、元数据、重复键语义、null、数值、对象自有 `__proto__` 键均保留；小文件及其他保存 JSON 仍用原生整份解析。没有新缓存文件或迁移。

直接解析器测试覆盖跨块 Unicode/转义/括号/字符串/重复键、与原生解析相等、非法 JSON 拒绝及异常后关闭句柄。大于 4 MiB 的账本加载保持原文件字节不变；损坏大文件沿用原有隔离与恢复，隔离副本字节完整。首轮集成用例把合成 home 放在产品目录内，被原有 SOURCE_PRODUCT_OVERLAP 防护拒绝；调整成并列目录后通过，没有放松防护。verify fail 0，runtime audit 通过。

首轮 100k 源码导航采样：私有工作集最高约 475.3 MiB，私有提交量最高约 631.9 MiB；统计 Worker 在切页时的 heapUsed 约 77–83 MiB，原候选 100k 样本曾约 154 MiB。源码运行的 GPU 占用低于原包测量，不能把整体差值全部归因于解析器，也不能据此宣布打包版达标。证据 `artifacts/m12/memory-next/streamed-load-100k/results.json`。

接下来使用新运行包核对 64k/100k 的相同场景，并覆盖合成采集/刷新峰值；再判断是否需要优化规范化快照与传输的中间副本。后续结果追加，不改写原候选失败与既有截图。

## 导航之后的采集削峰（续进中）

`ed78ec9` 的独立运行包 `dist/20261030-M12-memory-candidate` 审计通过。相同七个导航样本：64k 私有工作集最高 458.9 MiB，100k 465.9 MiB；这是离散导航结果，不能代表刷新或连续切页。新增独立 Windows 计数采样器，只查询该测试应用及其当时的子孙 PID，同时在窗口执行多轮导航、合成采集与新的合成记录追加。实际采样间隔和缺值保存在报告中，250ms 是查询之间的等待，不是瞬时峰值的采样精度保证。

扩大场景发现初版仍有问题：大文件流式读取后的源码三轮导航约 506 MiB；首次采集的私有工作集连续采样最高约 825 MiB，不能沿用首轮导航的达标判断。随后分块写入/校验及采集草稿分支复制降低了刷新占用，但真实新增合成记录后的第二次变化仍会重建完整历史聚合。以下改动继续针对该开销，尚未作为新最终包验收：

- `write-statistics.js` 对应用自有 JSON 数据按 records 条目分块输出，SHA-256 与原有整份 JSON.stringify 字节对照；仍使用临时文件及原子 rename。失败保留原文件并关闭/清理自身临时文件。
- 采集草稿只复制会修改的字典，完整记录观察被替换时生成新对象；未改动记录保持只读共享。备份捕获当时的字典和状态，不随后续草稿改变。冻结旧状态、失败持久化、完整快照替换及备份原观察均有回归断言。
- 大账本对 agent/entry/provider/model/timestamp/sessionKey 的完全相等字符串进行有界复用；同值 id 使用字典键字符串。磁盘格式、字符串内容、未知字段及历史不变，各字段池最多 2048 项。
- 单小时的日分组暂时复用同一个累加器，遇到第二小时才分开；与独立日/小时全量算法对照时区/DST、记录顺序、未知和冲突值。
- 小批量采集只重新聚合受影响分组，按完整保留记录重算，绝不对 null 聚合做减法。未变化行跨 revision 只读复用；价格基准、时区、当地日期变化或大批量变化回退全量算法。首归属顺序索引仅在多个已有身份真正竞争时构建，普通扫描避免创建整个历史的 `[id,index]` 临时数组。
- 匹配上一 revision 的窗口可接收白名单聚合增量和行顺序；缺失/过期基准仍返回完整快照。增量中没有账本 ID、路径或会话元数据。客户端错基准自动完整读取，同 revision 的重复完成通知复用已解码结果，迟到旧 revision 不回退当前呈现。默认无 revision 的读取/刷新仍返回完整事实。

曾试验逐行双遍白名单编码及保留隐藏 Usage/Cost 子树，实测没有稳定收益、后者增加占用，已撤回。没有改动外观或留下试验分支。先前全量 verify 的新增测试把含 undefined 的内存对象直接与 JSON 重启对象比较而失败；改成对照实际可保存的 JSON 语义，原回滚/未知/备份断言保留。首个连续采样还将 PowerShell 模块初始化的 CLIXML progress 误判成应用错误，原日志保留；后续在采样器自身进程关闭 progress 并记录实际计数异常。

当前定向回归通过，最终 verify、受影响源码 UI、重新打包与扩大场景的测量仍待闭环。旧 M12 运行包/截图/验收记录完整保留，本轮不合入、不推送。

## 源码检查闭环，准备新候选

上述改动后的 `verify` fail 0、runtime audit 通过；源码 statistics-worker、Today、render-performance 三个直接受影响界面套件通过。新增的实际界面断言确认：已知 revision 的无变化刷新不返回表格，新合成记录仍返回完整的新事实；Worker 重启、启用状态恢复、同 sequence 重定价和发送者校验保持通过。

普通采集还避免了全历史 Object.entries 临时二元数组，以及没有身份竞争时的完整顺序索引。增量分组使用本次计算内的身份字典和短键，取消逐记录构造大段 JSON 键及全历史 ID Set。账本 ID 不进入窗口协议。

源码 `memory-next/bounded-indices-source-100k/results.json`：100k / 100 模型 / 500 会话 / 200 天，两轮六页往返、四次真实合成采集，其中第三次实际追加 120 Token，合计从 10000694 到 10000814；全部完成，无渲染错误。私有工作集离散及连续采样最高约 465.7 MiB，约 30 秒静置后约 321.4 MiB。第二次变化的聚合约 334 ms，增量传输使累计 packed 字节从初始约 2.89 MB 增至约 3.79 MB，而非再次传整份表。**这是源码证据，不能代替新包、不同规模与复测；私有提交量另存原报告，也不是 500 MiB 以下。**

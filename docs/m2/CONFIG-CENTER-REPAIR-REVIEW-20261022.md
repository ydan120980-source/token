## 本次实际修复

管理器原先在编辑一项后检查整份文件，只要同类别其他项仍有错误，就拒绝本次修改。同文件存在多个错误项时，界面一次只能编辑一项，因而无法逐项修复。与此同时，hooks 整文件扫描有有界项数；管理列表中靠后的项可能未进入该次静态扫描，导致本次编辑漏掉其已有确定错误。

编辑现在将所选 MCP 配置项或 hook handler 及其原事件／组单独投影给原静态校验器。原组 matcher、事件与 handler 的兼容规则仍生效；被编辑项存在确定错误时拒绝，超过整文件扫描位置的所选项也必须检查。其他原有配置项保持原值，其中原有错误继续由显式只读检查报告，不再阻止修复所选项。

逐项校验修复只调整编辑预览的校验对象。整份输出仍经过原解析／序列化一致性和大小检查；读取白名单、管理路径、可编辑字段、整文件写入、加密备份、版本保护、原字节撤销、导入的整类别校验和执行边界均沿用原实现。没有扩大认证文件读取、静态扫描上限或在线能力，静态检查／CLI 输出契约不变。

后续状态修复涉及现有 renderer，但没有修改视觉 tokens、布局或范围选择行为。应用／撤销的 IPC 成功响应直接附带原有脱敏 state，页面马上采用该状态，不依赖另一次可能失败的状态请求才能清除旧结果。管理列表重新读取单独捕获失败，不把它改写成写入失败；撤销可用性独立于列表是否已读。保留性能增量的 close/release：管理视图记住最后成功的 context ID，即使后续重新读取失败，关闭时仍可释放该上下文／草稿，不清除合法撤销记录。

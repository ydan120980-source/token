# 用量页总览：Token 总量领头（2026-10-17）

费用有了单独的页面以后，用量页最大的数字仍是 API 等价估算，和费用页的总览说的是同一件事。项目负责人看过两版效果图后批准：
- 两个数字对调位置，各自占用原来那一格的大小；
- 估算保留悬停展开区间；
- "查看费用明细 ›"放在估算那一行的末尾。

## 页面

- **范围**：第一行是范围（如"全部 Agent · 累计"），原来的"API 等价估算 ·"标签移到估算那一行。
- **大字**：Token 总量。字号沿用原来估算大字的规则（`clamp(60px, 7vw, 96px)`），并且不超过所在行宽度的 12.5%（`cqw`），十位数的总量在窄窗口里也不会撑宽页面。靠近页面顶部时略微放大的效果（`focus.js`）也改到这个数字上。
- **第二行**：
  - 依次是"API 等价估算"、估算、"查看费用明细 ›"；
  - 估算用原来 Token 那一行的字号（`clamp(30px, 3.4vw, 44px)`），右侧仍是记录数和日均；
  - 悬停或聚焦估算时，和原来一样展开成"下限 – 上限"；展开的宽度只按这一行剩下的空间计算（`detail-interactions.js`），区间两段之间的分隔线按小字号缩短。
- **不变的部分**：近 30 天柱条、今天卡片和其余部分。

## 其他

- 删掉两样已无作用的东西：
  - 展开时强制 `scale: 1` 的规则。它原本用来抵消顶部放大；现在放大的是 Token 数字，它还会让估算按钮的定位参照变成估算本身（polish 套件因此发现 `offsetTop` 从 134 变成 0，屏幕位置其实没变）。
  - 对应的 `cost-folding` 切换。
- 测试改动：
  - functional：原来检查估算字号不小于 64px，改为检查 Token 总量不小于 64px，估算是较小的第二个数字；
  - polish：展开后不越界的检查，从按大字那一行改为按估算所在行。

## 验证

源码模式，合成 fixture 与独立的 usage/quota 目录：verify 与 `audit:runtime` 通过；全部 16 个 UI 套件通过（visual 在 800 × 600 窗口下检查页面没有横向溢出）；desktop-performance 通过，用量页最大同步耗时 69 ms，费用页范围切换 14 ms，上限都是 200 ms。打包版和真实数据上没有验证。

# 额度并发与重新登录恢复（2026-10-23）

## 所有者请求与范围

所有者反馈 WorkBuddy 重新连接仍报 `PROVIDER_SECRET_STORAGE_FAILED`，刷新慢且逐个执行，要求提高速度和并发。此次只修复额度刷新调度、已有连接的新凭据替换和受控错误信息；无样式修改、浏览器读取、配置维护、GitHub 操作或新增真实额度请求。接续此前正式打包要求，完成本地合入及独立便携包验收。

## 当前源码发现与实现

- Codex 和其他服务各自的全局 tail 都曾串行执行；自动 tick 还要等待 Codex 才启动其他服务。改为主进程共享调度池，最多 16 个独立刷新任务，同服务商最多 4 个、CLI 最多 4 个。队列从可执行任务中取用空闲名额，单服务商阻塞不阻挡其他服务。登录交互不放入刷新池。
- 同一连接防重入，正在重新登录的连接跳过自动和手动刷新，其他连接继续；同一应用拥有的 CLI home 互斥；CLI 关闭完成后才释放名额。排队取消立即移出，删除后不查询/复活该连接。不同连接可独立完成，保存时同步读取当前全部行，保留其他任务已经提交的结果。
- 手动“刷新全部”和共享分钟定时器都使用该池；分钟 tick 同时发起 Codex 与其他服务，保留冷却、15 分钟限流、自动任务不读取外部客户端认证文件、不补过期 tick 的语义。
- 新登录成功后，旧代码先解密旧记录再保存新记录，旧密文损坏会阻挡恢复。改为保留旧密文原字节，验证新登录与额度后加密、内存回读验证，再原子替换；缓存保存失败则回滚旧密文。旧 home 仅在成功提交后清理。系统持续拒绝写入时，不能保证回滚成功，也不会退回明文。
- IPC/连接提示仅透出受控阶段及白名单 OS 错误码；不返回原始异常、路径或凭据。普通加密格式不变，原有连接无需迁移。

## 真实与合成边界

本轮 Windows 原生加密探针只对新建合成标记执行加密/写入/读取/删除；已有应用 vault 密文逐字节保持不变，没有解密真实凭据，也没有服务商请求。该探针使用临时隔离 Electron 配置验证自身保存目录的可写及加密回读，不证明原运行实例的失败原因。

界面合成验收验证：损坏旧 WorkBuddy 记录后重新连接、加密重启恢复；“刷新全部”八个独立读取全部进入执行后才释放其中任何一个，排除仅显示忙碌的假并发。源码首轮新增重连场景因取消用例的挂起标记未复原而超时，隔离修正后通过；没有放宽产品断言。

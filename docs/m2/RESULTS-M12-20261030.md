## 内存：同口径打包前后测量

每次创建新的合成目录；100 模型、500 会话、200 天，依次显示六页再返回用量，各页稳定后取样，然后可见静置约两分钟（实际 125–129 秒）。没有强制 GC、内存压力通知、工作集裁剪、减掉 GPU、清空历史或硬限制旧生代。下面均为全应用进程总和、单位 MiB，**峰值指本轮七个导航样本中的最高值，不是连续监测的瞬时上限**。每个场景执行一轮；驱动/缓存/OS 工作集回收不可完全控制。

| 指标 | 旧 M11，64k | M12，64k | M12，100k |
| --- | ---: | ---: | ---: |
| 导航采样私有提交量最高值 | 826.7 | 642.4 | 763.9 |
| 约两分钟静置后私有提交量 | 505.4 | 447.6 | 473.7 |
| 导航采样私有工作集最高值 | 657.2 | 522.7 | 623.5 |
| 静置后私有工作集 | 348.2 | 347.0 | 333.6 |

64k 导航采样的私有提交量约降 22.3%、私有工作集约降 20.5%；稳定私有工作集基本相当，不能宣传为同幅度的常驻 RAM 降幅。私有提交量来自 Electron getAppMetrics；私有工作集来自 Windows WorkingSetPrivate，仅查询该应用拥有的进程 PID。[Windows 工作集包含共享页](https://learn.microsoft.com/en-us/windows/win32/procthread/process-working-set)，普通 working set 另存原始 JSON，不能直接相加当私有 RAM。旧包有一个静置样本缺少完整 Windows 计数，保留 INCOMPLETE_OWNED_COUNTERS；七个导航样本和最终静置样本均完整，上表没有补零或推断缺值。原始报告在 `before-64k-packaged/`、`after-64k-packaged/`、`after-100k-packaged/`。

**稳定值进入目标区间，但两种负载的导航采样仍超过 500；严格目标未闭环。** 没有把静置结果当全程结果，也没有在真实来源/实际账号规模上验证。另有 V8 heap-growing-percent=10 的独立 100k 启动参数试验，采样仍约 630 MiB 提交量 / 524 MiB 私有工作集，未解决上限，未纳入产品。更早的 GPU 预算和 optimize-for-size 试验也未纳入。

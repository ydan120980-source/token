# 来源与项目分析能力（2026-10-18）

项目所有者批准吸收 Orbital 评估中的五项设计：声明式来源能力、项目级用量与费用、带证据的维护事项、预算周期与费用展示分离、用量事实与价格分离后的历史重算。基线为本地 main a8d1aeb。独立实现于既有 Electron/静态界面和统一计算核心，不复制 Orbital GPL 实现、组件或资源，不引入其 Python 服务、执行器、遥测或凭据系统。

## 接入与隐私契约

- 来源能力来自主进程运行时目录和实际保存用量；格式、输入/输出语义、字段覆盖、规则版本及验证状态分开展示。不读取新目录、认证、配置或正文，不扩大既有采集合同。
- 项目以既有会话元数据的规范工作目录分组。没有依据的记录归入未知项目；自定义来源不推断工作目录。主进程聚合接口只给项目名和本机不透明分组键，不给绝对路径、原始会话/调用 ID、映射或文件索引；项目 CSV 只导出名称与聚合数字，同名不同路径保持不同组。
- 维护事项由来源/历史/用量/价格诊断计算，附受控错误码和影响数量；只提供导航与本应用“已知悉/恢复待办”，不执行来源命令。证据变化后重新提醒，问题消失后不继续保留过期待办。
- 预算是 USD API 等价估算的本地提醒，按全部或项目设置日/周（周一开始）/月/累计，均以统计时区的自然日计算。筛选不暗中改变预算范围；未知费用不当零，区间和未定价覆盖单独展示。不会暂停、启动或停止 Agent，不承诺账单、余额或额度约束。
- 预算、已知悉状态只保存在应用 workbench.json，与来源用量账本分离；保存失败不更新内存。旧账本/偏好没有该文件时正常工作。
- 重新估算仅使用已保存的规范用量与当前价格/映射/倍率；不触发来源扫描，不修改用量记录、身份、账本序号或原始文件。费用分析、项目汇总和导出均使用统一计价及聚合函数。

本轮不启动其他工作台路线：无 CLI/MCP 服务、配置健康内容读取、DIY 脚本、Agent 编排、上下文正文、远程控制或新账户额度。发布候选仍由发布负责人验收；r15 保留、不同步 GitHub。合成、真实与打包验证分别记录。

## 使用

从侧栏打开“费用”，切换到“项目与预算”，选择今日/本周/本月/累计和项目。预算采用自然周期，原费用分析的近 7/30 天仍是滚动窗口，两者独立。各项目可以展开查看来源构成；同名不同目录显示项目编号，分组身份保持独立。无目录依据的用量在未知项目里，不丢弃也不归到猜测的项目。

预算绑定所选项目与周期，正数 USD 保存，移除只清除当前组合。它覆盖该项目的全部来源；未定价记录、费用区间、缺失历史不会变成“确定在预算内”。预算不等同订阅月费、账号额度或账单。

费用、来源和项目归属事项分别出现在费用分析、来源管理和会话页，依据全部已保存历史；预算事项跟随所选项目及自然周期。事项提供影响数量、模型或受控错误码。已知悉状态绑定范围与证据；切换范围不会错误继承另一范围的确认。原独立页的范围确认仍在本机文件中保留，新的全部历史事项不会借用旧周期的确认。打开“显示已知悉”可恢复待办；证据改变会重新出现，底层诊断消失后退出列表。此操作不修改来源、价格或历史。

来源管理中展开对应来源的“解析能力与字段覆盖”，可查看全部已保存历史的格式、输入缓存/输出推理语义、规则版本、混用旧规则及每个桶的已报告记录数。读取状态和真实验证标记分开，零值算已报告，未知不算。应用不将上轮抽样报告自动写成全量验证标记。

费用分析中的“历史费用估算”可打开现有定价设置，也可在不扫描来源的情况下重新估算。价格变更会更新项目、总览、费用页和 CSV；重新估算不改用量事实或账本序号。导出项目 CSV 由主进程重建，金额按最多 12 位有效数字输出以避免浮点尾数，未知留空，项目名作为表格文本转义。

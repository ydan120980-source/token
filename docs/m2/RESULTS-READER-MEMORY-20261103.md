## 做了什么

1. 长阅读挂载附近正文，所有轮仍可定位；焦点、选择和正在跳转的目标保留。末尾仅挂载约 2–3 个正文/栏，300 个轮次高度框仍在。短对话完整挂载。
2. Codex/Claude 按行解析；请求内 Worker 串行执行并在回复前终止，避免把正文堆留在长期统计所有者中。元数据 stamp 不读取正文。
3. 对比、文件历史只投影必要信息。文件历史不再保留整份原文及其小写副本；保持文件增删、错误和条目上限语义。
4. 列表直接累计界面字段；最近会话只为选中的会话分配集合。完整列表的私有传输按请求字典编码，公开白名单 V1 和 null/0 语义保持；没有新增跨请求缓存。详情只算所属组，已有完整列表由 holdAll 引用。

## 流畅度证据和代价

屏幕报告 300 Hz、125% 缩放；使用原生 rAF。五场景的本轮帧间隔 P95 约 5.1–5.2 ms，但最大仍为 160.9–220.5 ms；基线各场景最大约 526.7–1156.7 ms。rAF 仅为有界观察（至多 20k 间隔、各轮耗时不同），不是覆盖同一总时长的稳定 FPS 基准，不能声称全程 300 FPS 或全部切页无卡顿。高刷行为另由 UI 套件检查。

临时 Worker 有冷启动/排队开销。三个长会话对比的单次 facts 最大耗时从基线约 54.9 ms 到 79.4 ms，三栏 transcript 最大从约 159.1 ms 到 324.0 ms；因此不能把它说成所有 IPC 都更快。收益是正文堆及时释放和 UI 阻塞下降。三栏列表请求最大约 397.6→288.6 ms。完整调用数据留在原始报告，不以某个最快探针代表整轮。

## 首轮失败与实验

- 第一轮脚手架曾因侧栏挡住滚轮、文件栏未展开失败，修复操作顺序；保留报告，不算产品通过。
- 窗口化首轮暴露短对话只挂载 4/5 项，保留短对话完整渲染后综合阅读通过；没有删断言。早期 design guard 失败通过把通用高度占位移入 kit 修复，随后重新编译。
- 第一个紧凑传输整轮峰值约 478/486/513/422/523 MiB；元数据投影后的整轮约 486/490/521/425/535 MiB，仍失败。不能用单独探针 492/481 代替失败整轮。最终最小聚合修改后才得到上表。
- 拒绝 copy-on-validate 分享对象实验：三栏探针约 529 MiB，增加复杂度且无改善，已撤回代码，保留记录。
- 最终复测曾误用 Windows PowerShell 5，原生 stderr warning 被 ErrorAction Stop 当作脚本错误；没有产生正式结果，改用默认 PowerShell 7 完成全轮。未遗留该次测量进程。

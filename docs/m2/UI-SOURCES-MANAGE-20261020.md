# 来源管理整合（2026-10-20，界面重做 D 步）

所有者在 2026-10-20 确认的待办 D 项：来源管理只回答"读什么、程序装没装"，分散在四个页面的核对列表合并到这里。后端 IPC 与数据契约不变，只改界面层。

## 页面结构

标题栏 → 采集说明 → 需要处理 → 来源 → 已发现 · 暂不支持。

## 改动

- **标题栏按钮从 6 个减为 4 个**：安装与更新、全部读取 / 全部停用、添加我的 Agent、重新检查。
  - "全部读取"和"全部停用"合成一个随状态切换的按钮：全部来源都在读取时显示"全部停用"，否则显示"全部读取"。两个按钮的 id 不变，只是同一时间只显示一个；切换时键盘焦点移到新显示的按钮。
  - "导入解析配置"移进"添加我的 Agent"面板第一步（"已有导出的解析配置？导入配置文件"）。编辑已有来源时不显示。
- **每行一条状态**：图标、名称和状态标签；下面一行依次是记录文件与读取情况、程序版本（检查过才显示）、账号额度。
  - 支持额度的 Agent，额度部分可点击，跳到额度监控中该 Agent 的卡片（原"管理额度"按钮）。
  - 有读取问题时，状态行末尾显示"N 项读取问题"，点击跳到"需要处理"。
  - 来源说明（如"会话日志 · Desktop / CLI"）移到状态行的悬停提示和管理面板的副标题。
  - 详情放在并排的两个折叠项里：读取位置、解析能力与字段覆盖。展开的那一项占满整行。
  - "添加目录"（Cursor 为"选择用量文件"）和"恢复自动发现的位置"移进读取位置折叠项，和它们修改的路径列表放在一起。读取问题的具体说明也在这里。
  - 右侧只留"管理"按钮和读取开关。个人来源是"编辑规则""管理"和启用/停用；导出配置、回退上一版、移除来源移进"读取位置 · 规则"折叠项。
- **每个 Agent 一个"管理"面板**（沿用定价编辑面板样式，`#agentSetupDialog`）。原来行内的"安装管理""安装与故障恢复""管理额度"三处入口合并为这一个面板，按顺序分为：
  - 程序：安装方式、当前版本、进度与结果，按钮与"安装与更新"总表相同（安装 / 升级、检查、官方下载、取消、回滚、复制启动命令）。
  - 用量读取：读取状态与处理步骤，"查看读取位置"关闭面板并展开该行的读取位置。
  - 账号额度：支持情况、连接状态、最近成功时间；支持时可"在额度监控中查看"。
  - 安装与故障恢复：官方指南、PowerShell 安装命令、重新扫描程序入口，以及原有的说明。
  - 安装进度和额度连接变化时面板原地更新（`installer-change`、`connections-change` 事件），不丢焦点。
- **"需要处理"列表**取代费用页"费用核对事项"、项目与预算页"预算事项"、会话页"项目归属核对"和来源页"来源维护事项"四个列表。
  - 每项一行：类别标签（来源 / 费用 / 会话 / 预算），一句话说明哪里有问题、影响多少记录或 Token，右侧是去处理的按钮（查看来源、去定价、查看会话、查看预算）和"已知悉"。
  - 未定价项的原因沿用 `src/m1/pricing-labels.js` 的措辞；能靠定价解决的（没有价格、价格待核实、缺少部分费率）给"去定价"，用量字段本身缺失或冲突的给"查看来源"，因为改价格解决不了。
  - 不止一类时显示类别筛选；超过 6 项时折叠，"显示全部 N 项"展开。"显示已知悉"开关作用于整个列表。
  - 来源、费用、会话三类按全部历史判断；预算类沿用项目与预算页当前选中的周期和项目，与原"预算事项"一致。
  - 费用页（分析页底部）、项目与预算页（预算提醒下方）、会话页（标题下方）各保留一行提示，写明数量，"在来源管理中处理"跳到列表并筛到对应类别。没有待处理事项时这一行隐藏。
  - 原来写在费用核对列表下的"重新估算"结果提示移到"历史费用估算"区块内。

## 样式

- `pages.css`：删除行内额度块的规则，新增状态行、并排折叠项和路径工具的规则。
- `agent-setup.css`：管理面板的分节样式；`agent-install.css` 删除不再使用的行内安装规则。
- `integrated-insights.css`：需要处理列表与各页一行提示。
- 没有新增颜色或尺寸变量；全部取自 `tokens.css`。

## 接口变化（仅渲染层）

- `window.agentInstallUi`：`{ status(agent), section(agent), reload }`，取代 `{ controls, inline }`。
- `window.sourceConnectionsUi`：新增 `sheetHtml(agent)`；`sourceHtml(agent)` 改为状态行内的一段。
- `window.agentSetupUi`：`{ open(agent) }`。
- 行内的 `[data-agent-install-open]` 入口删除，改由 `[data-agent-setup]`（"管理"）打开面板。

## 不在本步范围

- 会话页 Agent / 时间 / 排序控件的滑动指示器属于 E 步；本步只把会话页的"项目归属核对"列表换成一行提示（E 步的第二项因此已完成）。
- 费用页的"历史费用估算"仍在原位，属于 F 步的定价整合。

## 测试调整

- agent-install：原来从行内"安装管理"打开总表；改为从"管理"面板确认程序版本，并在面板里执行一次检查。
- workbench：核对事项改在来源页的"需要处理"中确认与恢复；新增检查费用页提示能跳到列表并筛到"费用"类；会话页检查一行提示。
- custom-sources：导出和回退前先展开"读取位置 · 规则"；导入改从"添加我的 Agent"面板进入，并确认导入的名称已填入；"全部停用"只在全部来源都在读取时出现，所以先点"全部读取"。
- agent：来源读取内容的说明改为检查状态行的悬停提示。
- interaction-reliability、usage：添加目录前先展开读取位置。
- interaction-reliability 的故障注入此前在源码模式下就失败（main `76eb11c` 上复现）：源码模式下 `app.getAppPath()` 是 `src/quota`，拼出的模块路径不存在。已改为源码模式取上两级目录，打包版仍用应用路径。

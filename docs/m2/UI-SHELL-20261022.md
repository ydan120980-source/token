# 标题栏与侧栏重新设计（2026-10-22）

所有者 2026-10-22 圈出了标题栏和侧栏，要求结合项目今后的推进方向重新设计。本记录对应的分支是 `feat/ui-shell`，需要所有者看过截图后再合入。

## 推进方向对外壳的要求

[PRODUCT-DIRECTION](PRODUCT-DIRECTION-20261019.md) 定下的方向：
- 面向公开用户；
- 下一条主线是 GitHub 账号绑定和远端项目状态，之后是本地 Git 只读状态；
- 额度和来源的状态表达要一致。

这对标题栏和侧栏有三点要求：

1. **侧栏要能加新的分组，但不能出现假入口。** 现在分为"数据页"和"管理"两组，以后接入 GitHub 时可以加一个"项目"组。在实现之前，不放占位导航。
2. **"需要处理"的提醒要在全局看得见。** 额度连接出错、来源和费用的核对事项，以前要进到对应页面才发现。
3. **采集状态要在全局看得见。** 采集失败的提示原来在侧栏底部，侧栏收起或窗口变窄时就看不到了。

| 标题栏右侧的"Agent Usage · 用量"同时重复了侧栏品牌和页面大标题 | 🟢 | 改为只给屏幕阅读器读的文字，不再显示 |

| 侧栏 6 个入口平铺，每行 44px，偏松；以后加分组没有位置 | 🟢 | 每行 38px，字号 14，分为两组，第二组标题为"管理" |

## 改动

- **标题栏**：
  - 左侧仍是侧栏开关、后退、前进。
  - 右侧依次为：
    - **采集状态**：只读本机采集状态，不发新的请求。正常时显示"已采集 · N 分钟前"、"正在采集…"、"采集已暂停"或"尚未采集"，点击进入来源管理。
    - **深浅色切换**：仍是原来的 `#theme` 按钮，挪到了这里。
    - **"⋯"**：弹出完整菜单。
  - 采集失败时，原侧栏的 `#dataBadge`（"最近采集没有完成 · 查看原因"，见 [UI-COLLECTION-DIAGNOSTIC](UI-COLLECTION-DIAGNOSTIC-20261022.md)）整体挪到标题栏，替换正常状态，两者不会同时出现。
  - 只有桌面窗口有集成标题栏。浏览器预览模式下，这些元素保持原样。
- **主进程菜单**：`src/quota/window-shell.js` 的 `window:menu` 新增 `app`，把三组菜单合成一个弹出菜单，用分隔线隔开。原有的 `statistics`、`appearance`、`about` 仍然可用，应用菜单和快捷键不变。此文件只管窗口呈现，没有新增任何能力。
- **侧栏**：
  - 入口文字放进 `.nav-label`。
  - 新增 `.nav-caption`（"管理"）和 `.nav-badge`，角标对屏幕阅读器隐藏，按钮的无障碍名称不变，待处理数写在悬停提示里。
  - 角标由 `usageData.badge(view, count, title)` 设置：
    - **额度监控**：状态带警示的连接数，来自 `quota-cards.js`；
    - **来源管理**：未知悉的"需要处理"条数，来自 `insights-ui.js`。
  - 为了启动时就能显示来源角标，`insights-ui.js` 的 `load` 增加了后台模式：
    - 启动时和每次采集完成后读取一次，不受当前页面限制；
    - 后台模式不写页面提示；
    - 后端的工作台查询本来就按账本缓存，没有新增接口。
- **图标栏**：
  - 收起后宽 `--sidebar-rail: 60px`，新增 token。品牌名、文字、资料名都隐藏，角标变成小圆点，分组标题变成一条细线。
  - 窄窗口（≤ 800px）时侧栏是顶部横条，收起仍完全隐藏。只有这种情况下侧栏才设为不可交互（`inert`）。
- **样式位置**：规则写在原有的 `nowdex.css`（侧栏、标题栏）和 `usage.css`（资料行），没有新增样式文件。

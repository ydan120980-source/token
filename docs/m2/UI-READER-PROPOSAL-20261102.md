## 判断

现在的阅读页按聊天来排版，但人打开它通常是在回看：问了什么、做了什么、哪里出了错、从哪接着做。这是判断，没有用户研究支持。

所以建议把它排成一份文档（A），需要时再打开右栏（C）。不建议保留气泡（B）：气泡占掉一侧宽度，长回复读到中段时看不到问题。

## 三个版式

| 版式 | 怎么排 | 适合 |
|---|---|---|
| A 文档（建议） | 问题是粗体小标题，回复是正文，720px 宽；左边目录带时间，右边位置轨 | 回看长会话 |
| B 对话 | 接近现在：右侧气泡、左侧回复，目录默认收起 | 习惯聊天形式的人 |
| C 审阅 | A 加右栏：这次会话的数字、改过的文件、跑过的命令 | 回顾 Agent 做了什么 |

A 和 C 只差右栏，可以做成一个开关。

## 功能分组

### 现有数据就够（只改界面，不改读取范围）

`TranscriptItem` 已经带时间，工具调用已经有名称、一行摘要、输出和失败标记，后台已能按范围复制和导出。

- 每轮时间，隔得久的两轮之间写间隔；没有时间的不写
- 读长回复时，顶部一行留着这一轮的问题，不挤动正文
- 正文 720px（现在最宽 1024px）
- 全部 / 只看对话 / 只看失败
- 位置轨：全部轮次的长短、失败、查找结果，点哪跳哪
- 上一个 / 下一个会话，不用退回列表
- 标题栏“接着做”：复制恢复命令
- 代码块复制、复制单条、导出选定的几轮
- 键盘：J / K 换一轮，[ / ] 换会话，/ 查找
- 右栏：跑过的命令和失败

### 要改解析（仍在已批准的记录内）

7 个 Agent 要分别核对格式、补合成样例。**这些格式还没有逐个核对**，下面哪些 Agent 能做要核对后才知道。

- **改动视图**：把改文件的操作画成增删对比。我认为价值最高。现在 `src/m1/transcript.js` 把工具参数压成一行摘要，要先把参数留下来
- 改过的文件：要区分读和改，每个 Agent 的工具名不同。稿子里右栏的文件列表属于这一组
- 每轮用量：只显示，不进统计；记录里没有的写未知，不写 0
- 子 Agent 折叠
- 跟随进行中的会话：只在页面打开时重新读取
- 代码高亮：只带常用语言，用到时才加载。要先量内存，M12 还在压峰值

### 要所有者决定（会动到“阅读什么都不留”或读取范围）

- 记住读到哪：只存第几轮，不存内容
- 书签和备注：存在应用自己的文件里
- 记录外的本地图片：要读来源白名单之外的文件
- 独立窗口：可以和列表并排，但多占内存

每项决定后单独记录。

### 不建议做

AI 总结、语义搜索：要把对话内容发给模型，与“不上传”冲突。本地模型是另一个范围，这次不展开。

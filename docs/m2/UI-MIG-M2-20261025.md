## 实现

### 桥接与状态 hook

`bridges.ts` 声明现有 renderer 的 UsageBridge、QuotaBridge 和 WindowBridge。方法名及参数数量与 preload 自动逐项对照，不添加或改变调用参数。`usage-data.js` 已解码 get/refresh 的 snapshotBytes，因此 UI 类型是解码后的 snapshot（可为 null，表示 revision 未变），不是传输层二进制。

三个 getter 返回原有桥接对象，不克隆、不重包装参数，不在 import/getter 时发起 IPC。`getGlobals()` 同样只返回已有全局对象引用，没有重新实现格式化、计价、换算或图表计算。

`useBridge(read, { enabled, subscribe, requestKey })`：

- 明确传入只读 loader 才会加载；enabled=false 时 idle，不调用 loader。页面在可见时启用，可结合 useViewActive。
- loading/ready/error 可判别；错误保留同一 requestKey 的上次成功数据，不伪造零或空快照。
- requestKey 改变时先清空旧作用域数据；旧请求迟到结果、停用或卸载后的结果不覆盖新状态。
- 一个激活作用域中请求串行；订阅突发更新合并为一个后续读取，不启动重叠批次。
- cleanup 取消订阅，reload 显式重读；没有轮询、登录、账号刷新、来源扫描或配置执行。
- hook 不擅自展开 IPC 回执。Quota 的 ok=false/state 缓存、Config 的 error、取消结果都按原协议交给调用方判断；Promise reject 才进入 hook error。
- subscribe 接现有 onUpdate/onProviderUpdate/onInstallUpdate。read 应选 get、providers 等已有只读方法，不应传入 Connect、refresh 或其他写操作。

`useViewActive()` 读取旧外框的 main.dataset.currentView 并监听 ui-view-change；`useDarkTheme()` 读取 body.dark。共享订阅在最后一个使用者卸载时断开，不改外框或主题设置。

### 数据语义

- 账号资源量仍为 decimal string | null；百分比是 number | null，不做字符串到浮点数的金额转换。
- V1/V2 额度与 SourceConnectionsV1/V2 分开声明；getV2 的失败 state 可为 null，其他额度操作保留自己的失败缓存。
- SavedFile 的 canceled、来源选择 sourceSaved 与“保存成功但 discovery 失败”分开，避免把失败发现当作未保存。
- null、undefined、partial、未定价和精确字符串保留；本层不相加、不补零。
- 动态诊断、来源元数据与部分异构结构使用 JSON/unknown 字段，需要消费者缩窄后读取；这些类型不声称对外部运行时载荷做了新的验证。验证仍由原投影/IPC 层负责。
- usageInsights.renderActivity 是旧 DOM 渲染器，仅准确声明原接口，未在 React 中重新实现或调用；对应页面迁移仍需做它的耦合盘点。

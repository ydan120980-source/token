# 用量采集与切页响应 · 2026-11-12

源码分支 `codex/responsiveness-20261112` 从本地 `main` 的 `534b1bd` 开始，对照使用加了同一阶段计时的 `5050c4c`。原生显示为 300 Hz、125%，默认窗口 1482 × 962 DIP。较早的 240 Hz、150% 回执独立保留作诊断。

## 真实数据复测

两对回执均通过桌面资格检查。检查点 `9ac3821` 的两轮各载入 51,503 条统计，最终候选对照的两轮各载入 51,605 条，四轮各有 259 个日聚合行。每对用同一份 `validate:local --performance --collection-overlap` 探针和独立应用状态。表里的采集时间从应用的手动刷新按钮量到结果可见。回执中的 `load.collectionMs` 是初始准备阶段的独立计时。运行中的真实记录仍可能增长，即使统计条数相同也无法推断源文件逐字节一致。

| 实际操作 | 检查点基线 → 候选 | 最终基线 → 候选 |
| --- | ---: | ---: |
| 手动刷新到结果可见 | 32.03 → 13.21 s | 23.41 → 14.79 s |
| 采集期间切到费用 / 用量 | 192 / 128 → 88 / 48 ms | 128 / 80 → 80 / 56 ms |
| 首次切到用量 / 费用 | 224 / 328 → 72 / 232 ms | 144 / 240 → 88 / 232 ms |
| 回访费用 | 144 → 64 ms | 120 → 64 ms |
| 两份长会话返回列表 | 112 / 104 → 120 / 112 ms | 120 / 120 → 120 / 112 ms |

两次基线刷新分别在预解析花 12.95 和 9.58 秒。候选新启动的 Worker 只做一次正式扫描，仍执行原生校验。现有缓存只保留有界的已解析数据。在没有已提交的扫描可对照时，预解析无法判定“无变化”，而缓存容量之外的文件会在正式扫描再读一次。冷启动直接扫描时建立列表与指纹。稳定运行后，监听器仍保留安静快路径，带有新消息但统计事实相同的文件也仍能跳过重新入账。

真实回执在 `artifacts/responsiveness-20261112/` 下的 `resume-real-before/after` 和 `final-real-checked-before/after`，只有数值和固定阶段标识。基线自带的脚本早于重叠参数，第一次启动在参数检查阶段停止，复测统一使用候选的探针，通过 `PERF_SOURCE_ROOT` 指定产品检出。真实打开会话通过探针调用读取入口，最终候选第一份记录最长主线程任务 150 ms。真实返回列表、切页和刷新使用可信指针事件。真实手动刷新覆盖冷采集，单文件增量的达标证据来自合成对照。

## 最终候选的五对交错采集对照

每轮使用 2,000 个合成文件，冷扫 40,000 条，追加后 40,001 条。两版本都通过原生校验，五对非空账本的精确条数、Token、观测语义摘要和定价投影逐对相等。每轮的探针、夹具和各版本产品文件 SHA-256 均已比对。回执为 `final-collection-1` 至 `final-collection-5`。

| 采集操作 | 基线中位数 | 候选中位数 | 缩短 |
| --- | ---: | ---: | ---: |
| 冷采集 | 1,343.4 ms | 1,329.0 ms | 1.1% |
| 无变化刷新 | 60.8 ms | 56.6 ms | 6.9% |
| 单文件增量 | 856.2 ms | 591.8 ms | 30.9% |

单文件增量的五对缩短 23.1% 至 32.3%，超过 20% 的门槛。冷采集中位数满足不退化 10% 的门槛，其中第五对的候选慢了 18.7%。增量采集中费用和用量的可信点击最慢均为 56 ms，冷采集中的首次费用最慢 136 ms。

`9ac3821` 检查点原本只把单文件增量从 1.102 s 降到 1.011 s。在最终候选中，已成功扫描且没有启用的自定义来源时，可以在原生子进程核对投影期间由统计 Worker 构建私有账本草稿。本组候选的原生核对中位数约为 468 ms，草稿计算约 157 ms，与核对时间重叠。核对之后的提交约 41 ms，对照的串行入账约 328 ms。正式快照和采集时间在核对成功后才更新。校验失败会丢弃草稿，账本或定价基础变化时使用当前状态重算。失败后重试的回归检查了旧快照、磁盘字节、提交序列与最终 Token。

## 回归和取舍

- 上轮快速切页断言在 `5050c4c` 上同样失败。该断言要求已访问页面的隐藏 DOM 数为零，与现有 React Activity 保留状态的实现不符。验收现在要求快速切走后原页面隐藏、焦点离开，接下来八帧内没有旧页面的延迟 DOM 挂载。新增历史返回测试实际滚到用量趋势，再返回并恢复滚动位置。首次绘制时的筛选高亮误差、图表几何、键盘及动效检查继续执行。
- 保留用量、费用、外壳、会话与阅读专项的源码定向回执。分阶段呈现后重新运行 Today、外壳和费用布局。较早把费用首屏数字移到标题之后的试验显著延后正确内容。推迟首段和惰性挂载轮播的试验中，首次费用收益不稳定。提前设置阅读外壳和移动阅读焦点两项试验没有稳定降低真实返回或首次阅读耗时。上述试验代码已撤回。
- 最终源码的 ESLint、UI 类型、原生校验、运行时审计、Today 快速切页和 Agent 来源恢复套件通过。默认并发全量测试首轮有五项失败，回执 `final-exact-verify.log` 保留。失败涉及的五个文件以并发 2 重跑通过，随后用 `node --test --test-concurrency=4 tests/m1/*.test.js` 完整复跑得到 `fail 0`，见 `final-exact-verify-bounded.log`。测试与产品的超时设置未调整。
- 单文件增量达标。仍开放首次用量、首次费用、打开长会话以及部分返回和回访费用的 100 ms 门槛，首次会话列表的正确内容就绪也未达到要求的改善幅度。验收范围为源码版。

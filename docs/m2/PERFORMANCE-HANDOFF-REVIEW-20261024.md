## 后端开销

- 统计列式传输的映射字段采用最多 128 个不同值的字典：常见定价原因、已知字段等不再在每一行重复传送数组。超过上限退回原向量表示；仍能解码旧向量形式。null、零、空映射、稀疏字段均有往返测试。
- 新投影替换旧投影时释放旧会话/工作台派生缓存；worker 切换快照时清空旧会话索引和打包缓存。仅保存一代当前快照，按需重算；不改持久化文件格式、数据语义或采集范围。
- 不改定时刷新、连接授权、凭据、真实来源读取或 provider 网络路线。

## 同机合成测量

命令：`node scripts/m1/performance-benchmark.js --rows 20000,100000 --repeats 3 --memory-samples 2 --idle-ms 3000 --output <evidence>`。每个规模各启动三次，各取两次内存样本。使用隔离 fixture，暂停采集，无真实账号请求。私有内存为 Electron 所有进程的 private bytes，包含 GPU；不是单个 JS heap，也不是泄漏结论。

| 场景与指标 | 原版 | 修复版 |
| --- | ---: | ---: |
| 2 万条：传输字节 | 4,168,207 | 2,808,429 |
| 2 万条：解码中位数 | 61.3 ms | 35.7 ms |
| 2 万条：就绪中位数 | 1,103 ms | 1,113 ms |
| 2 万条：总私有内存中位数 | 555.4 MiB | 514.2 MiB |
| 10 万条：传输字节 | 4,368,207 | 2,888,435 |
| 10 万条：解码中位数 | 117.4 ms | 33.2 ms |
| 10 万条：就绪 P95 | 2,080 ms | 1,358 ms |
| 10 万条：总私有内存中位数 | 640.2 MiB | 625.9 MiB |

OS 缓存和机器负载未控制，三次样本中的 P95 实际就是最大值。2 万条原版首次启动约 3.5 秒，另两次约 1.1 秒，不能把冷启动差异写成稳定性能提升。10 万条结果体现这组测试的改善，不承诺任意真实账本等比例下降。

# 额度卡片补全与自动读取减负（2026-11-04）

所有者要求：把能做额度监控的 Agent 补上卡片，风格对标参考卡片，文字不能显示不全；真实读取由 Codex 写；另外修每分钟读取偶尔失败、读取时在桌面上跑指令的问题。显示基准从此以 125% 为默认，150% 其次。

本轮只用合成数据验证卡片。读取改动有一次真实程序对照（见下），没有查询任何账号，没有读取任何凭据。

## 读取为什么会弹窗

对运行中的正式包做了只看进程名和窗口的被动观察（15 分钟），每分钟一轮：

- 1 个 `codex.exe`、3 个 worker；
- 两个 Antigravity 连接各 2 次（`--version`、`/usage`），合计 4 组 PowerShell + `csc.exe` 编译 + `agy.exe`。

**终端窗口的来源是 `agy.exe` 自带的后台自更新**，不是我们启动它的方式。官方文档记录它每 15 分钟触发一次（`~/.gemini/antigravity-cli/updater/`）。这个子进程没有控制台，Windows 就把新控制台转交给默认终端，屏幕上出现 Windows Terminal。

对照（真实 `agy.exe`，空的临时目录，无账号）：

| `AGY_CLI_DISABLE_AUTO_UPDATE` | 新终端窗口 | `updater/update.lock` |
| --- | --- | --- |
| `true` | 0 | 没有 |
| 不设（改动前） | 3 次 | 有 |

试过但无效，已撤回：把程序放到隐藏桌面、放到独立窗口站。默认终端转交不受这两者影响。唯一的系统级开关是用户的默认终端设置，不应由本程序修改。

另外观察到每 30 秒有 `asus_framework.exe` 启动 PowerShell，这不是本程序。

## 改了什么（读取）

| 改动 | 效果 |
| --- | --- |
| 读 Antigravity 时设 `AGY_CLI_DISABLE_AUTO_UPDATE=true` | 消除弹窗来源；也不再有自更新替换被校验的程序 |
| 同一程序只问一次版本 | 每次读取少一组进程 |
| 作业进程的 C# 按源码只编译一次，存 `%LOCALAPPDATA%\AgentUsage\job-host` | 读取不再启动 `csc.exe`、`cvtres.exe`；副本损坏只多编译一次，不影响读取 |
| 需要启动程序的路线（目前只有 `antigravity-cli`）自动读取改为至多 5 分钟一次，手动刷新不限 | **这是对 2026-10-23“每分钟”决定的收窄**，其余路线仍是每分钟 |
| 一批 HTTP 读取共用一个 worker，批次结束 1.5 秒后退出 | 3 个连接从 3 个进程变成 1 个 |
| 自动读取遇到临时失败（超时、请求失败）时静默重试一次，连续第 3 轮才显示 | 卡片保留上次读数和真实的读取时间；手动刷新、登录失效、限流、拒绝访问都立刻显示；没有读数的连接也立刻显示 |

“偶尔失败”的具体原因没有在真实账号上复现。上面处理的是机制：临时失败不再立刻变成错误，自更新也不会再改变程序指纹。自更新是否真造成过失败是推断，没有证据。

跟着参考做的变化：大数字默认不写“剩余”（切到“已用”时才写）；节奏文字移进悬停提示；分段条不再有时间刻度；状态正常时不显示“已更新”，“详情”悬停或键盘聚焦时才出现。

Claude 参考图的双色条没有做：它的比例含义无法从数据确认，不画没有依据的比例。

**文字不再截断。** 卡片内不再有省略号：名称、窗口名、金额放不下就换行或缩小，套餐标签放不下时整个让位（详情里仍有）。`scripts/m1/quota-cards-ui-test.js` 在 125%、两种读法、两种主题、三种窗口宽度下，对正常值和最长值都断言没有被截的文字。`scripts/m1/text-clip-ui-test.js` 再扫六个页面。

两处主动允许截断：会话标题和路径这类由人或 Agent 命名的长文本（悬停可看全）；页面扫描也只覆盖合成数据里出现的文字。

## 右侧概要的入口（所有者 2026-11-04）

所有者找不到右侧概要的按钮。原来是标题栏最右边一个没有文字的淡色图标，窗口宽度小于 1360 时默认也不显示概要，所以两边都看不到。

- 改成带文字的胶囊“概要”：关闭时是白底并微微浮起，打开时变成蓝色底、右侧那格填色。窗口窄到 800 以下只留图标。
- 快捷键 `Ctrl+Shift+B`，和收起左侧菜单的 `Ctrl+B` 成对。设置的快捷键列表、标题栏菜单都有；设置页没有概要，按了没有反应。

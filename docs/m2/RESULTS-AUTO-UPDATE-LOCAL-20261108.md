# 自动更新本机安装版验收 · 2026-11-08

所有者选择在本机安装版升级验收通过后合入本地 `main`。GitHub 上线另行验收。

## 范围与隔离

产品输入为 95a116b。工具 scripts/local/auto-update-acceptance.js 只在显式命令下运行，普通测试与产品入口不会导入它。

测试使用独立 NSIS 名称、appId、安装目录、应用数据、合成 Agent home 和更新缓存，关闭桌面及开始菜单快捷方式。11 月 8 日输出位于工作区外的 `token test/auto-update-installed-20261108-r*`，11 月 11 日复验输出位于 `token-evidence/upd-20261111`。

测试包有意改变包身份、版本及入口封装，更新源为仅绑定 127.0.0.1 的 GitHub 风格 Atom／Release 路由。入口封装固定合成状态与少量本机测试动作；产品主进程、更新服务及渲染源码不替换。真实 electron-updater、NSIS 安装器、SHA-512 校验、差分算法和重启路径均参与执行。逐包 ASAR 与隔离源码核对，包括固定版本的原生 tokscale。

此范围验证本机安装与更新机制，不等同于 GitHub 实际托管、HTTPS／CDN、Actions 在线运行、草稿发布操作或公网下载验收。未签名预览的发布者身份限制不变。CodeGraph 工具不可用，采用定向源码和实际安装路径核对。

## 执行与结果

实际完成 0.1.0 → 0.1.1 → 0.1.2。版本仅用于隔离测试，未提升产品 package.json 或创建标签。三个版本均成功生成 NSIS、blockmap 和更新清单，ASAR 与隔离源码、原生二进制审计通过。

| 检查 | 结果 |
| --- | --- |
| 启动自动检查、未公开测试候选不可见 | 通过，使用真实 GitHubProvider 读取回环 Atom／Release 路由；不是 GitHub 公网验收 |
| 更新源返回 503 | 进入受控错误，已安装版本继续保留 |
| 错误 SHA-512 | 拒绝更新，报告 UPDATE_VERIFY_FAILED |
| 实际传输中取消并立即重试 | 通过，旧传输退出后新传输成功下载 |
| 下载后普通退出 | 不安装，手动重新打开仍为 0.1.0 |
| 0.1.0 → 0.1.1 | 静默安装并自动重启；--updated 为真，原安装目录不变，安装后 ASAR 与目标构建哈希相同 |
| 0.1.1 → 0.1.2 | 差分下载及第二次实际安装／自动重启通过，目标 ASAR 哈希一致 |
| 应用状态保留 | 合成统计记录、阅读标签文件、加密记录的哈希与升级前相同；深色设置和 localStorage 标记保留；合成加密记录在新进程仍可解密 |

差分观察：目标安装包 128,562,937 字节；对安装器发出 9 个 Range 请求，传输 1,075,530 字节。此数字不含另行下载的 blockmap 与元数据，不表示整个发布包大小、应用速度或任意版本都能达到相同节省。

第二轮当时保存了 `results.json`、`before-data.json`、`starts.jsonl`、两轮 HTTP 请求、缓存对齐记录、运行日志和窗口截图。版本与安装字节以运行回执和 ASAR 哈希为准。实装驱动使用真实窗口的 DOM／IPC 入口。

本机复制依赖时 Node 文件复制提前退出，改为本机 robocopy 后完成准备。第一轮升级启动了 0.1.1，测试工具在重连调试端口时超时，随后正常退出并卸载该轮独立测试程序。第二轮用测试封装中的固定动作与状态回执重新执行完整安装链路，沿用相同产品源码。

第二轮还保留一次差分回退：最初的测试环境将 LOCALAPPDATA 与 USERPROFILE 下的 AppData/Local 分别指向两个独立目录，NSIS 存放旧安装器的位置与 updater 查找的位置不一致，因此回退全量下载。核对旧安装器与 0.1.1 构建哈希完全一致后，仅将本轮两个应用专属缓存目录对齐，保留原缓存和失败结果，续测差分及第二次安装通过。产品代码没有调整；新的 prepare 会从一开始就统一这两个测试路径。

两轮测试程序均已正常退出并执行各自的独立卸载程序。11 月 11 日核查时，原回执目录在工作区附近已无法找到，因此从同一产品提交重新构建并实装。

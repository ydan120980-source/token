## 本轮界面接线

仅修改 `design/desktop-reference/quota-cards.js`，没有 CSS／tokens、布局、配色、字号、动效或自动刷新规则变化。

1. 所有服务商已知重复连接在卡片底部提示“重复连接 · 额度不可叠加”。读取中、失败、缺少凭据继续优先显示其状态；鼠标提示及详情仍提供重复关系，避免错误被掩盖。
2. 详情只列出 `duplicateAccountIds` 中同一服务商且当前仍存在的连接名称；用户重命名后同步更新，按文本转义。`credential-match` 明确写“相同凭据及读取范围”，不伪称接口返回了账号身份。未知身份不显示重复提示。
3. 保留每个连接一张卡片、独立刷新／错误／移除。不自动合并，不跨连接合计，也不把两组重复连接混在一起。重复关系写入复制摘要，提醒读者不要相加。
4. WorkBuddy desktop 且 `incomplete === false` 时，卡片显示“可用积分 · N 个积分包”，合计详情／摘要写“本次读取范围内的 N 个积分包合计（分页已读完）”。只表示本次过滤范围枚举结束，不称为账号全部资产。
5. 网站摘要、缺失完整性标记、旧的 incomplete 记录和达到上限的结果仍显示“已返回的 N 个积分包”。冻结／到期／不可用／余量未知的排除及 BigInt 精确加法沿用原实现。

## 所有者反馈：浅色卡片观感偏粉（待复现）

所有者圈出的区域同时包括额度概况栏、额度卡片及用量页的“今天”卡片，共用 `--card`。本轮没有修改 CSS 或 tokens，也未对偏色进行补偿。

- 浅色实际 computed style：卡片 `rgb(255,255,255)`，页面 `rgb(246,246,246)`，卡片 opacity 为 1、filter 为 none；品牌水印为 grayscale。
- 两张所有者圈注附件的卡片大面积区域均测得 `(255,255,255)`，页面 `(246,246,246)`；附件无 ICC 标签，测量区域没有粉色通道偏移。
- 默认 Electron PNG 带 Google/Skia ICC 描述；仅给合成测试进程加 `--force-color-profile=srgb` 得到的对照 PNG 无该描述，卡片像素仍为中性白。没有证明 ICC 是根因，不能把观感反馈记作已修复，也不据此改系统显示配置。
- `QUOTA_IDENTITY_SRGB=1` 是新增 suite 的可选诊断开关，不传给产品的常规启动，不修改主进程。该补充运行 100% 全流程通过，150% 重启导航超时，失败截图停在用量页。随后测试使用已有 `isolatePointer` 隔离物理鼠标输入；默认颜色设置下最终全流程复跑通过。未把补充 sRGB 的完整双缩放流程记为通过；导航超时根因未确认。

晚间需要保留“用户仍观察到偏粉，现有 CSS／PNG 像素没有复现”的区别。若再次获得可测的偏色证据，再定位渲染／显示链；若所有者选择改为柔和灰白，则作为明确的配色调整另行记录，不把它冒充根因修复。

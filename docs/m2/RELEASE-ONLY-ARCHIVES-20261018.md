# 正式打包时才生成交付归档（2026-10-18）

所有者针对截图中的多个日期/主题交付目录明确要求：以后这些只在正式打包时做。

- 日常维护、本地合入：提交代码、测试和必要文档，执行项目要求的验证并保留测试证据；不创建新的 `dist/<代次>` 交付目录，不生成源码 ZIP、交付清单、校验文件或为此执行额外的压缩、解压和逐字节核对。
- 正式打包：按现有发布负责人职责和候选验收流程统一生成运行包及源码交付物，再执行对应的打包、解压与交付完整性验证。
- 打包链路本身有改动时，仍执行 CONTRIBUTING 中要求的必要构建与包审计；这不自动授权创建新的正式交付代次。
- 现有交付目录与 r15 保留。该决定不授权删除历史目录，也不减少日常代码、计算逻辑或受影响界面的必要验证。

此前各功能记录中的源码归档属于历史交付证据；以后不将其作为每次维护的固定收尾步骤。本决定不恢复 GitHub 同步，不改变数据与来源读取边界。

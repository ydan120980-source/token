## 会话页

| 项 | 现在 |
|---|---|
| 默认排序 | 按最近。排序改成下拉（按最近、按成本、按 Token），给 Agent 筛选让位 |
| 点一行 | 能阅读的 Agent 进入阅读页，返回时焦点回到这一行；不能阅读的 Agent（ZCode、WorkBuddy、Cursor）打开详情卡片 |
| 详情 | 行尾信息图标“会话详情”；原来的“阅读对话”图标去掉，详情卡片底部的按钮保留 |
| 搜索 | 一个搜索框加“会话 / 对话内容”范围。选“会话”时边打字边筛选；选“对话内容”时回车才开始 |
| 列表上方 | 时间范围进标题行；搜索一排；Agent、分组、排序一排。汇总行和“部分用量缺少项目归属”提示放进列表卡片顶部。汇总行不再重复写时间范围和 Agent，这两项上方的控件已经显示 |

1440 宽、合成数据下，列表卡片顶部在 304px，第一行会话在 352px。这次没有在同一份数据上测改动前的位置；所有者截图里约 450px 是对照，不是同口径。

**对话内容搜索回车才开始的原因**：一次搜索要现读记录文件（每批约 6 秒，取决于会话数量），每按一个键就扫一遍会反复读文件。结果留到下一次回车或清空搜索框，不会因为改字就消失。这里修订 [SESSIONS-READER-20261101.md](SESSIONS-READER-20261101.md) 第 6 节的入口说明；搜索范围和“不建索引、不缓存”没有变。

搜索结果显示时，分组和排序不起作用，所以暂时隐藏。

## 用量趋势

图上方从五排减到三排：

1. 标题、时间范围、Token / 费用
2. 总量和当前条件，例如“累计 · 30 日均”
3. Agent，构成 / 总量 / 模型，“更多”

来源、模型、每日 / 30 日均 / 累加、时间粒度收进“更多”，在原位展开，不遮挡图。这些条件不是默认值时，第二排写出来，按钮显示个数（“更多 1”）。代价是这几项要多点一步；离开用量页再回来时会重新收起。

## 无障碍核对（只看这次改动）

- 键盘：Tab 到名称按钮，回车进入阅读，Esc 返回且焦点回到这一行；Tab 可到搜索范围，方向键可切换。
- 名称：行按钮读作“Claude Code 会话 …，阅读对话”（不能阅读的 Agent 读作“查看明细”），信息图标读作“会话详情”。

- 没做：读屏软件实测、200% 缩放。

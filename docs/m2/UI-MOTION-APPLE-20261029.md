## 2. 依据

**Apple HIG《Motion》**：2025-09-09 版，原文通过 Apple 文档的 JSON 接口读到。其中直接用到的规则：
- 有目的地用动效，不喧宾夺主，不为了动而动；
- 动效可选：不能只靠动效传达信息；
- 反馈动效要跟随手势和预期，简短、精确；
- 频繁的界面操作一般不加动效；
- 让人能打断动效，不用等它播完；
- 避免持续振荡，尤其是 0.2 Hz 左右的。
- 页面写明：macOS 没有额外要求。

**WWDC 2018《Designing Fluid Interfaces》**，借助本机 `apple-design` 技能的整理：
- 弹簧从屏幕上的当前值开始，所以随时可以打断；
- 默认临界阻尼，不回弹；只有手势本身带了动量（甩、拖拽松手）才少量回弹；
- 松手速度要接到弹簧上；
- 落点按 Apple 的减速公式 `v/1000 · d/(1−d)` 推算（d≈0.998），不用 `v²/2a`；
- 越过边界时阻力逐渐加大（橡皮筋），不是硬停住。

下面的具体数值是 Claude 按这些原则为桌面端定的，不是 Apple 公布的数值。

## 4. 组件库的动效体系

**档位**（`ui/src/vendor/fluid/lib/springs.ts`，经 `ui/src/design/motion.ts` 转出）：

| 档位 | 用途 | 进入 | 退出 |
|---|---|---|---|
| `fast` | 即时反馈 | 弹簧 0.1s | 0.08s |
| `moderate` | 控件 | 弹簧 0.2s | 0.14s |
| `slow` | 面板、弹窗、翻页 | 弹簧 0.32s，回弹 0.12 | 0.2s |
| `momentum`（新增） | 只用于甩动或拖拽松手之后，接手势速度 | 弹簧 0.4s，回弹 0.15 | 0.2s |

`fast` 和 `moderate` 不回弹。`slow` 保留原来 0.12 的回弹：初版按 Apple 的原则去掉了，所有者随后要求保留（“回弹可以要不用删”）。

**数据档**：
- `enter` 0.5s，`update` 0.3s，`follow` 0.15s，都是无回弹的弹簧；
- 每根错开 0.015s，最多 0.12s；
- 图表首次出现的落定时间由 `dataSettle` 给出。

**手势工具**：
- `project`：按速度推算落点；
- `rubberband`：越过边界时阻力逐渐加大；
- `velocityTracker`：用事件时间戳取最近约 100ms 的样本算速度。

**轮播（`Carousel`）**：
- 翻页由“推算落点是否越过半页”决定，取代原来的“拖过 18% 或速度大于 0.45”；
- 松手速度接给 `momentum` 弹簧；
- 首尾越界改用橡皮筋，取代固定的 0.3 倍；
- 开始拖拽时清掉文字选区，防止下一次按在选中文字上变成浏览器原生拖拽，导致手势被取消。

**不变的部分**：
- 减少动效时只保留淡入淡出，关闭动效时直接到终态；
- 禁止发光、悬停时上浮或放大；
- CSS 过渡只用于颜色、底色这类即时反馈。

**减少动效**（所有者随后要求补完）：
- 新增 `reducedFade`：0.2s 的淡入；`useKitMotion()` 新增 `fade`，在应用设置为“减少”或系统开启减少动效时为真；
- 弹窗、菜单本来就只保留淡入淡出，因为 Motion 的 `reducedMotion="always"` 会去掉位移、保留透明度；
- 原来直接跳到终态的三处改为交叉淡入：
  - 图表：形状立即写成新值，改变的形状淡入；
  - 数字：新数字淡入；
  - 轮播：翻页时新页淡入，不滑动；
- 关闭动效时，一切仍然直接到终态。

**可拖排序（`Sortable`）**：
- 松手时，被拖的那一项带着指针速度落回位置；
- X 和 Y 用两个独立的 `momentum` 弹簧，按 Apple 的做法分开；
- 取消拖拽时没有速度；
- 减少动效时，落下的那一项淡入。

# WorkBuddy 积分合计与额度页工具栏（2026-10-21）

所有者 2026-10-21 确认的 G4 步骤，同时按所有者对截图的反馈调整了额度页工具栏。卡片的整体设计见 [UI-QUOTA-CARDS-V2](UI-QUOTA-CARDS-V2-20261021.md)。

## 所有者决定：WorkBuddy 积分包可以相加

原规则是"不同资源池不相加"（[QUOTA-RESOURCE-BACKEND](QUOTA-RESOURCE-BACKEND-20261019.md)）。WorkBuddy 每个积分包是一个独立的资源池，所以卡片上看不到这个账号一共还有多少积分。

所有者 2026-10-21 同意为 WorkBuddy 开一个窄例外，条件如下：

- **范围**：只适用于 WorkBuddy，并且只合计同一个连接、单位为积分、并且至少有两个资源池的情况。其他服务商和跨连接的情况仍然不相加。
- **不计入的积分**：
  - 已到期、已禁用、尚未生效、不可用的积分；
  - 冻结积分（`frozen`）；
  - 余量未知的积分包。未知的个数会写在说明里，不按 0 计入。
- **说明写法**：后端只读取第一页（`incomplete`），所以合计一律写作"已返回的 N 个积分包"，不说成账号的全部积分。
- **算法**：合计由渲染层在十进制字符串上精确相加（`BigInt` 定点数），不经过浮点数。卡片照常显示千分位、最多两位小数；悬停提示和详情面板显示精确值。

### 显示位置

- **卡片**：钱包卡下方的大数字是"可用积分 · 已返回的 N 个积分包"，"共 X 积分"跟在大数字同一行，上方两行显示具体的积分包。
- **详情面板**：每个账号下有一行合计，写明统计范围以及排除了哪些积分。
- **复制摘要**：WorkBuddy 那一行最前面是合计。

## 工具栏

所有者认为原工具栏"看着有点奇怪"：分段按钮、带文字的按钮、浮在外面的"自动刷新"标签、下拉框，样式和高度都不一致。现在与用量页使用同一套控件：

- **左侧**：剩余／已用分段按钮（`range-tabs`）。`motion.js` 的滑动指示器加入了 `#quotaMeasure`。
- **右侧**：一个浅色底的操作组（`profile-actions`），里面依次是"自动刷新 关闭 ▾"、复制摘要、刷新全部。后两个是图标按钮，带无障碍名称和悬停提示。
- **尺寸**：两组高度都是 40px，底色同为 `--soft`。
- **不变的部分**：`#quotaInterval`、`#quotaRefreshAll`、`#quotaCopy` 三个 id 不变，现有测试照常使用。

### 自动刷新默认开启：未改，等待所有者确认

所有者要求自动刷新默认开启，本步没有改，原因如下：

1. **后端行为**：自动刷新状态只保存在内存里（`src/quota/service.js` 中 `this.autoRefresh = 'off'`），重启后恢复为关闭。这一点由 `quota-ui-test` 的 `restartOffHistoricalCache` 断言保护，并且属于后端（GPT 负责）。
2. **与已记录的决定冲突**：默认开启意味着应用一启动，每分钟就会自动读取一次 Codex 额度。已记录的决定要求恢复已保存的连接时不联网，额度只在用户明确刷新时读取（[QUOTA-WEBSITE-LOGIN](QUOTA-WEBSITE-LOGIN-20261020.md)）。

所有者确认后，再按选定的方案修改并记录。

# 来源管理：扫描修正与自动发现（决策记录）— 2026-10-14

- **状态：** 已批准（项目所有者，2026-10-14，基于本地 `main` 的 `3579599`）。步骤 0–3 批准；步骤 4（新 Agent 的采集适配）方向批准、逐个另做。
- **效力：** 本地模式期间不开 issue，本文就是超出原有范围的决定记录。

## 背景

对扫描逻辑的检查（只看代码、应用自己的偏好文件，以及本机目录名和文件数量，不读来源文件内容）结论：

- 本机九个来源的数据都在扫描范围内；Gemini CLI 与 Cursor 本机确实没有数据（`~/.gemini` 下是 Antigravity 的数据）。
- 代码有四处会在别的机器或别的安装方式下漏数据：
  1. 默认读取路径在首次启动时整份写进 `preferences.json`，此后代码新增的默认路径永远到不了老用户（`store.js` 用已保存的列表整体覆盖默认值）。
  2. Agent 目录被目录联接（junction）或符号链接迁到别处时，`filesUnder` 因真实路径不同报 `SOURCE_ALIAS_REJECTED`，整个读取根目录的文件全部丢弃。
  3. 不认 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`，设置后仍只找用户目录下的默认位置。
  4. 超过 16 层或 10 万个文件时整个读取根目录作废，而不是保留已列出的部分。
- 来源只能添加读取路径，不能移除，也不能恢复默认。

## 决定

1. **扫描修正（步骤 1）。** 读取路径改存为"自动（默认 + 环境变量）+ 用户追加 − 用户排除"，并支持单个来源停用；旧偏好按规则迁移（下节）。允许读取根目录的上级目录是链接，但每个文件的真实路径必须仍落在该根目录的真实路径之内，根目录本身是链接仍拒绝。认 `CODEX_HOME` 与 `CLAUDE_CONFIG_DIR`，原默认位置同时保留。超限时保留已列出的文件，来源标为部分（`partial`）并报 `SOURCE_LIMIT`。
2. **自动发现（步骤 2）。** 对每个已支持的 Agent 列出已知位置，只检查是否存在、可读文件数量和最近修改时间，不读内容；发现结果默认纳入，用户可排除。另有一份第三方 Agent 特征清单，只按目录是否存在判断，显示为"已发现 · 暂不支持"，不读其中任何文件。
3. **来源页（步骤 3）。** 一键全部纳入或停用；按来源、按路径开关；恢复自动。停用只停止采集，历史统计保留。
4. **新 Agent 适配（步骤 4，另做）。** 项目所有者明确今后继续扩充 Agent，不再以"九个来源"为上限；每接入一个 Agent 仍需一份采集契约、合成 fixture 与测试，单独合入。

不做：

- 全盘遍历。按已知位置探测，不遍历所有磁盘。
- WSL 中的 Agent（网络路径继续拒绝）。
- 读取第三方 Agent 的任何文件内容；读取认证文件。

## 旧偏好迁移规则

旧版从未提供移除路径的界面，所以已保存列表与当前默认值的差异只可能来自：用户追加的目录、Cursor 的"替换"选择、旧版本的默认值，或手工写入的空列表。据此：

| 已保存列表 | 迁移为 |
|---|---|
| 与当前默认值相同，或是其子集 | 自动（缺的默认路径是旧版本造成的，补回） |
| 多出默认值以外的路径 | 自动 + 用户追加这些路径 |
| Cursor：只含用户选择的文件，不含默认路径 | 用户追加该文件 + 排除默认路径（保持"选择即替换"） |
| 空列表 | 该来源停用（保持原"有意清空"的效果） |

迁移只发生在内存与下一次保存偏好时；`statistics.json` 与历史记录不变。

## 共同约束

未知仍为 `null`，不填 0；不上传，采集器保持网络阻断；不写任何 Agent 的数据库或配置；本应用的 usage/quota 数据目录不能被选为来源。验收如实区分：已实现 / 合成测试过 / 真实数据验证过 / 未执行。

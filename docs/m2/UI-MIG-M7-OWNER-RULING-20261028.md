# M7 所有者补充：旧版布局与当前标准动效 · 2026-10-28

本记录转录当前会话所有者的新要求；与此前M7开工文件的冲突处，以本记录为准。不扩展M7以外的页面、后端或外部操作权限。

## 1. 所有者原话

> 旧版的用量页的排版和ui和motion是标准设计,大功能的ui和尽量做到还原,不要像费用页似的Claude审核时出现图中的问题,必须加入kit的直接问我并给我截图

随后补充：

> motion用当前的标准库就行

附图作为所有者对维护方式的说明：费用页专用样式与kit里的页面条件分支会增加重复维护成本。本步不据此修改费用页，也不把图中其它会话的技术结论当作已核实的当前源码事实。

## 2. 本步执行口径

- `d079ae5`旧用量页是布局和主要功能UI的对标：保留首屏主次读数、费用/事实同行、近30天条带、今日Agent→模型的列组织、日历与星期小时及趋势的区块关系，尽量用现有kit恢复。
- 动效按随后明确的要求，使用现有kit/Motion规范、full/reduced/off及data档；不复刻旧版的毫秒值、Canvas或专门的动画实现。
- 不引入UsageReferenceProvider、用量专用参考CSS、kit中的页面判断、按aria-label选择样式，或另一个旧DOM renderer。页面组合现有kit及布局容器，计算留在UMD。
- 当前C配色、外框、共享小组件、无用量摘要栏、数据/隐私铁律、五个未改页面的像素门槛及Claude最终审核继续保留。规范之外确实需要的新kit能力或token，先给真实原版/当前截图与限定方案，直接请所有者裁决，获批后再改。
- “尽量还原”不自动放宽门槛，也不代表可自行补充kit接口。既有组件承载后的差异逐项记录。

## 3. 图例淡出诊断的处置

在补充要求到达前，Codex核对了旧版图例淡出在当前默认LineChart中的表现。合成实测：隐藏cacheRead时，原来两条path在首个采样帧已移除；full/reduced均没有旧版的中间淡出。实际mode已逐项核实。证据保留在：

- `artifacts/ui-mig/M7/kit-audit/trend-legend/results.json`；
- 确认复跑的`artifacts/ui-mig/M7/kit-audit/trend-legend-confirm/{run.json,probe.log,results.json}`：exit1，5.906秒，373字节，失败断言为`full: no intermediate opacity while hiding the known series`。

所有者随后明确“motion用当前的标准库就行”。据此，本步保留当前默认组件的图例显隐行为，将旧fade形态断言映射到当前库的显隐终态、打断后目标和图形边界检查；这项诊断不再作为申请复刻旧动效的阻塞。没有修改LineChart或其它共享motion代码。现有Motion规范的真实失败仍须报告，不把此处解释成任意改动动效的授权。

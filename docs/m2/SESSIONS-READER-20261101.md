## 2. 读取范围

- 只在点开一个会话的阅读视图时读取，读这个会话自己的记录：

| Agent | 记录 | 找到这个会话的方法 |
|---|---|---|
| Codex | `rollout-<时间>-<ID>.jsonl` | 文件名；对不上时看文件开头 64 KB 的 `session_meta` |
| Claude Code | `<ID>.jsonl`，2026-11-02 起还有 `<ID>/subagents/agent-*.jsonl`（见 `UI-READER-PARSING-20261102.md`） | 文件名；对不上时看开头 64 KB 的 `sessionId` |
| OpenCode、MiMo Code | `opencode*.db`、`mimocode*.db` | 库里 `session_message`（2.x）或 `message` 加 `part`（1.x）中这个会话的行 |
| Gemini CLI | `chats/session-*.jsonl`（或旧版 `.json`） | 开头 64 KB 的 `sessionId`；同名的 `.jsonl` 优先于迁移前的 `.json` |
| DeepSeek Harness | `<项目>/<会话>/session.vN.jsonl[.zstd]` | 会话文件夹名；取最新一代 |
| Antigravity | `brain/<ID>/.system_generated/logs/transcript_full.jsonl` | 文件夹名；完整版优先于 `transcript.jsonl` |

- 按文件头查找时最多检查 5000 个文件（DeepSeek 要先解压，最多 500 个）。
- 读取范围仍是已有来源目录和文件白名单（`policy.filesUnder`），不读认证、配置和其他文件。OpenCode、MiMo Code 的数据库在统计时只读用量字段，阅读时还读这个会话的消息正文和 `part` 表。
- 文件超过 128 MB、数据库超过 1 GB 不读取。
- 读出的内容只经过统计进程返回给窗口，不写入统计库、统计导出、查询接口、日志或错误文本，也不在应用里缓存；关闭阅读视图即丢弃。
- 不删除、不修改 Agent 的任何文件，不上传。

## 3. 显示规则

| 内容 | 显示 |
|---|---|
| 你的消息 | 右侧气泡（2026-11-02 起提高对比度） |
| Agent 的回复 | 文档正文，宽 720px；代码块单独显示。2026-11-02 起去掉回复旁的图标，见 `UI-READER-DOCUMENT-20261102.md` |
| 思考 | 默认折叠。Codex 只有可读的思考摘要，加密的推理内容不读；Gemini 把各条思考的标题和内容合在一起 |
| 工具调用 | 折成一行：工具名和命令、文件或查询；展开看输出；失败的标“失败”（Codex 按退出码，Claude Code 按 `is_error`，OpenCode 按 `status: error`，Gemini 按 `error` 或取消，DeepSeek 按 `isError`） |
| Agent 注入的上下文（环境、说明、系统提醒、Gemini 的 `session_context`、DeepSeek 非本人来源的消息、Antigravity 在请求外附加的内容） | 默认折叠为“注入的上下文” |
| 斜杠命令 | 一行灰字 |
| OpenCode 自己拼进去的文字（`synthetic`、`ignored`） | 不显示 |
| Antigravity 的其他步骤 | 以步骤类型为名的工具行，展开看原文 |

- **按轮显示**（参照 CC Switch 的阅读页）：每轮是你的提问、执行过程和最终回复。最终回复是这一轮最后一段、之后没有工具调用的回复；其余（思考、工具调用、中间说明、注入的上下文）折成一行“执行过程 · N 步 · M 次工具调用 · K 次失败”。只有一步且没有失败时直接显示这一步。折叠时失败的工具调用仍逐条显示（最多 5 条）。
- **目录**：轮数不少于 4 时默认在左侧显示，每轮一行（提问的第一行），跟随当前位置，点一下跳过去；底部按钮可以收起。
- **同一工具连续调用**：同一工具连续 3 次以上且都没失败时，合成一行“工具名 · N 次”（参照 CC Switch 的“调用了 X 共 N 次”），展开看每一次；失败的调用总是单独一行。
- **Markdown**：标题、列表、引用、表格、代码块、行内代码、粗体、斜体、删除线。只转成界面元素，从不当作 HTML 解析。
- **链接**：写成链接的和直接写出的 http、https 地址可以点，点了用系统默认浏览器打开（主进程再校验一次：只接受 http、https，不带用户名密码，最长 2048 字符）；其他地址只显示文字。
- **图片**：只显示记录里自带的图片（Claude Code 的 base64 图片、Codex 的 `input_image`、OpenCode 的图片附件），限 PNG、JPEG、GIF、WebP，单张不超过 20 MB；滚到附近时才读取。远程地址的图片不读取，只显示“[图片]”。
- **完整内容**：整份会话都读进来（最多 10 万条），但发给窗口的每条都是轻的：8K 字以内的文字整条发送，更长的文字只发前 1200 字，工具输出只发前 12 行（不超过 1200 字）。点“显示全部”时按这一条重新读取记录，每次 512K 字，可以继续往下显示；单条最多 32M 字。
- **会话内查找**：在后台对全文查找，不只查已显示的部分；回车跳到下一处，Shift+回车跳到上一处。落在折叠的执行过程或预览之外时，自动展开并读取这一条的全文，再定位到这一处。
- **记录变了**：展开、看图和查找都会重新读取记录，并核对文件大小和修改时间与打开时一致；不一致时提示“会话记录已更新”，点“重新读取”后继续。不缓存任何内容，所以符合“不保存”的规则，代价是每次展开要重新解析一遍这个会话（28 MB、1000 轮的合成会话打开约 0.5 秒）。
- 长会话的轮次随滚动陆续加入页面；看不到的轮次不绘制（`content-visibility`）。
- **复制和导出**：每轮末尾的复制按钮把这一轮按 Markdown 复制到剪贴板；底部“导出 Markdown”把整个会话存成你选定位置的 `.md` 文件。两者都重新读取全文（不是预览），不含注入的上下文，图片写成“[图片]”，工具输出放在比内容里最长反引号更长的代码围栏里。只在你点击时生成，应用自己不保存。

## 5. 概览小组件“当前窗口里的会话”

所有者选定的形式：时间轴取最近几小时并对齐额度窗口；每个 Agent 一条横道，显示该窗口已用多少；点会话跳到会话页。

- 每个 Agent 取服务商报告的**最短的当前窗口**：开始 = 恢复时间 − 窗口长度，结束 = 恢复时间。过期、缺恢复时间或缺长度的窗口不画。
- 已用比例直接用服务商报告的数（或 100 − 剩余）；缺失时写“已用未知”，不推算。
- 时间轴从最早的窗口开始（最多回看 12 小时）到最晚的恢复时间（至少到现在后半小时，最多 12 小时），竖线标出现在。
- 横道上画落在窗口里的会话；最近一小时内还有记录的会话带一个小点。会话名按 名称 → Agent 标题 → 项目 取。
- 指向或聚焦一个会话时，横道上方那一行显示它的名称、起止时间和 Token 数，不遮挡横道和标题；平时显示会话数。
- 点击会话：能阅读的 Agent 打开阅读视图，其余 Agent 打开会话页当天的列表。
- 小、中、大三种尺寸分别最多显示 2、3、5 个 Agent；小尺寸只写已用比例。
- 只用已保存的额度和会话元数据，不读取会话正文。

## 6. 跨会话搜索

- 入口：会话页搜索框旁的范围选“对话内容”，回车开始；已有文字时选中范围即开始。结果替换会话列表，点“返回会话列表”或清空搜索框回到列表（2026-11-02 修订，见 `UI-SESSIONS-REFOCUS-20261102.md`）。
- 范围：会话页当前的时间范围和 Agent 筛选里、能阅读的会话，从最近的开始。
- 方式：搜索时现读这些会话的记录（同第 2 节），不建索引、不缓存；每批最多约 6 秒，没搜完时显示“已搜 n / m 个会话”和“继续搜索更早的会话”。
- 匹配：不区分大小写的原文包含；查你的消息、回复、思考、工具调用的命令或文件、工具输出和注入的上下文。
- 结果：每个会话显示名称、开始时间、匹配处数和最多 3 处上下文（前约 36 字、后约 72 字）。点开即进入阅读视图，查找框已填好这个词并跳到第一处。
- 返回给窗口的只有会话键、匹配处数和这几段上下文；不返回文件路径，不写入任何地方。

## 7. 依据

记录结构参照 CC Switch（MIT，`farion1231/cc-switch`，提交 `8be8405`）的 `codex.rs`、`claude.rs`、`opencode.rs`、`opencode_blocks.rs`、`gemini.rs`、`dsh.rs`、`agy.rs`，再按合成样本测试。CC Switch 的 `mcode.rs` 是 MiniMax Code，不是 MiMo Code；MiMo Code 的数据库与 OpenCode 同结构，统计时已按此读取。

- Codex 只读 `response_item` 行（消息、思考摘要、函数调用及其输出、自定义工具、shell、网页搜索）；`event_msg` 是重复内容，跳过。
- Claude Code 读 `user`、`assistant` 行中的文本、思考、`tool_use` 和 `tool_result`。
- OpenCode、MiMo Code 读消息的 `text`、`reasoning`、`tool`、`file` 部分，按 `seq` 或创建时间排序。
- Gemini CLI 按 CLI 的方式回放 `.jsonl`：同一消息 ID 后写的替换先写的，`$set` 替换消息列表，`$rewindTo` 删掉那条及之后的。
- DeepSeek Harness 读 `user/message`、`assistant/message`、`tool/result` 事件；`surfaceOp: replace` 的副本和重复的消息 ID 跳过。
- Antigravity 每一步取最后写入的那一行。

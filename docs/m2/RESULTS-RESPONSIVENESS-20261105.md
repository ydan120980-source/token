## 后端读取与当前内存复测

解锁后的 `unlocked-read-attribution` 把读取分成后端 handler 和 renderer bridge 等待，第一份 Antigravity 会话分别约 1,390 / 1,422 ms。CPU 诊断将它的主要开销定位为目录 `lstat` / `readdir`；解析不是这一来源的首要瓶颈。该诊断的 UI 后半程超时，只有已完成的解析采样作归因，不作合格交互回执。

后端改为只遍历 Antigravity 规定的 `brain/<id>/.system_generated/logs` 分支，仍经原链接／别名／白名单检查、仍比较所有已选根里的完整日志。其它追加解析器原本重复遍历一次来源根，已去掉这次冗余。Antigravity 与未压缩 DeepSeek 使用逐行解析；最后修订、全文分页、查找和记录变化拒绝语义有回归测试，未增加正文缓存。

首轮 `unlocked-targeted-reader`：同一 Antigravity 样本的统计记录数仍为 3,599，handler 约 256 ms，正文就绪约 603 ms；归因轮约 1,390 / 1,702 ms。另一份 Codex 记录持续增长，这轮 handler 约 876 ms，未证明提速。整库统计数在轮次间改变，不能把整体帧率变化或冷采集时间当成等负载对照；本项收益只归于指定会话的读取路径。单独逐行读取试验没有明确的速度收益，未据此宣称加速。

# 采集减负、未报告口径与构成/习惯重构 — 2026-10-07

2026-10-07 用户授权两条。主线 `m2/agents-r4`，主开发 Claude Code。本记录为主线程源码验收，尚未打包新候选。

## 采集减负（提交 `e86e0ee`）

- 实测原因：每轮刷新重读并解析全部源文件（本机约 1.3 GB，约 8 s CPU），并整份重写 24 MB `statistics.json`。写盘不到 1 s，不是主要开销。
- 采集 worker 常驻，按文件大小/修改时间（数据库另含 WAL）缓存每个文件的解析结果；合并会修改记录，所以缓存结果每轮先克隆再用。
- 源戳不变则跳过解析、tokscale 校验、入账和写盘；读取失败或超时后下一轮必定重扫；账本在采集外被改动（清空、维护应用）时强制完整入账。
- `Store.ingest` 只在持久内容变化时写盘并推进 sequence。
- 真实来源只读测量（只输出汇总）：完整扫描 8.2 s；源未变 0.18 s、读 0 个文件；缓存重扫 0.33 s；35,183 条记录与 token 合计和完整扫描一致。

## 未报告口径

- "输出（不含推理）未报告"是展示缺陷：Claude Code、DeepSeek Harness 的输出每条都有，只是来源不单独记录推理。现在显示"输出（含推理）"的实际值，推理显示"含在输出中"。
- 来源从不记录的字段（Codex、DeepSeek 的缓存写入）显示"来源不记录"，相应 token 已计入输入；不再显示成缺数据，也不让混合范围出现无意义的"≥"。
- "≥"只在记录该字段的来源有部分记录缺失时出现，表示已报告部分的下限。
- 数据质量提示（如 `USAGE_UNREPORTED`、`SOURCE_USAGE_CONFLICT`）不再算作"部分来源读取失败"，也不再触发 30/60/120 s 退避；真实读取错误照旧。

## 构成与习惯重构

- 删除"Token 构成"分布条与"使用习惯"星期柱状图。
- **成本去向**：API 等价估算按各项"用量 × 单价"分摊到输入/输出/缓存读取/缓存写入，分项之和等于总估算（含 Agent 倍率）；缓存命中率；缓存约省下金额（缓存读取按未缓存输入单价计费时需多付的差额）；未定价部分不计入并标明覆盖率。
- **用量占比**：按 Agent 或模型排序，前 6 项加"其他"；显示 token、占比和估算费用，点击即筛选。
- **活跃时段**：星期 × 小时热力图（本地时间，随页面范围与筛选），列出最集中的时段、最常用的钟点、最活跃的星期和有用量的时段数。小时级快照行从最近 7 天扩展到全部历史（本机 671 行）；单日趋势因此任意日期都可按小时绘制。
- **效率**：日均费用（按有用量的天数）、每百万 token 成本、每条记录 token、缓存命中率、活跃天数；与等长的上一周期对比，上一周期早于记录开始或为累计范围时不对比。只对费用和命中率标注好坏方向。
- 成本定价"已用模型"默认显示用量最多的 8 个，可展开/收起；搜索时显示全部匹配。

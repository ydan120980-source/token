# 额度页 v4 第一步：卡片随窗口排满、概况栏不重叠、全部刷新覆盖所有连接（2026-10-22）

所有者 2026-10-22 看过额度页 v4 融合设计稿后确认分三步实施（"可以，品牌色再稍微柔一点，按三步开始做吧"）。这是第一步，只修布局和读取。卡片新形态与页面顶部在第二步，详情面板、筛选和拖动在第三步。设计稿不入库。

起因（所有者反馈）："默认尺寸的额度监控排版有大量留白""卡片的下方小字有重叠""当前的读取系统做的也不好"。

## 卡片排满一行

- 原因：卡片固定 296px（`repeat(auto-fill, 296px)`）。默认 1180 宽窗口的额度页内容宽约 860px，只放得下两张，右侧空出约 250px。概况栏按三张卡的宽度绘制，与两列卡片也对不齐。
- 改为 `repeat(auto-fill, minmax(var(--quota-card-min), 1fr))` 加 `aspect-ratio: 1`：
  - 卡片仍是同一尺寸的正方形，以后的长按拖动不受影响；
  - 列宽随窗口平分，最小 260px（新令牌 `--quota-card-min`，取代 `--quota-card-size`）；
  - 默认窗口一行三张（约 273px），1000 宽两张，1600 宽四张。
- 概况栏去掉按三张卡计算的最大宽度，和卡片区同宽。
- 卡片变窄后内容收紧：
  - 卡片内边距从 24px 改为 20px，窗口之间的间距从 12px 改为 8px；
  - 钱包卡有合计时只列一行积分包，取最先到期的可用包；已到期、已禁用和不可用的包只在详情面板里列出（原来列出的正是两个"0 / 100 已到期"的包）。
- 合成数据下，1180、1000、1600 三种宽度和深浅两种外观，卡片内容都没有被裁切。

## 概况栏小字重叠

- 原因：可点击的"需要处理"一项用了 `justify-items: start`，副标题按内容撑开，省略号失效，连接名称压到右侧一栏上。
- 改为 `stretch`，文字仍然左对齐，超长时显示省略号。

## 全部刷新覆盖所有连接

- 原因：工具栏的"全部刷新"只调用 Codex 服务的 `refreshAll`，其他服务商的连接不会被刷新，卡片停在"1 天前"，汇总却显示"成功 1 / 失败 0"。
- 现在"全部刷新"分两部分：
  - Codex 账号仍由 Codex 服务刷新；
  - 其他每个连接各自走一次显式刷新（`providerAction refresh`）。
- 正在读取、处于冷却或缺少凭据的连接跳过，和 Codex 服务的跳过规则一致。汇总合并为一行："上次全部刷新：成功 / 失败 / 跳过"。
- 这仍然是用户点击触发的显式刷新，不改变后端，也不改变"恢复连接时不联网"的规则。
- **自动刷新仍只覆盖 Codex**：其他服务商要不要自动刷新，涉及对外请求和限流，需要所有者另行决定，并交给后端实现。

## 测试调整

- `motion-ui-test`、`visual-ui-test`：原来断言卡片为 296px，改为断言三点：卡片是正方形、宽度一致、宽度不小于 260px。
- `provider-quota-ui-test`：DeepSeek 连接重新提供凭据之后，点击"全部刷新"，该连接被读取一次，汇总为"成功 1 / 失败 0 / 跳过 0"。

## 验证（源码模式，合成数据）

截图工具 `.cache/ui-tools/probe-quota.js`（不入库）：用隔离的空数据目录启动真实应用，在主进程替换 `quota:get`、`quota:getV2`、`quota:providers` 三个读取接口，换成仿照所有者截图的合成连接，包括两个重复的 WorkBuddy、OpenCode 授权过期、ZCode 无额度项、Antigravity 待刷新和 Codex；不读取凭据，也不联网。

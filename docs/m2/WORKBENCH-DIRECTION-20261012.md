## 背景

项目所有者希望应用从"用量统计"发展为一个 Agent 工作台，打开后主要做三件事：

1. 看今天花了多少钱：用了哪些 Agent、哪些模型，输出、缓存命中、成本、速度各是多少。
2. 检查每个 Agent 的状态：会话、skills、MCP、hooks、全局 AGENTS.md 是否健康。
3. 不只用固定视图：用户能自己写配置定义视图，也能接入大模型来提问。

同一天先讨论了换技术栈（Tauri 2 / Electrobun），实测后搁置，结论见文末"附：换栈实测"。

## 决定

按下面的顺序分四个阶段推进。阶段 4 依赖阶段 2 的查询层，阶段 3 与 2、4 互不依赖。每个阶段按 `AGENTS.md` 的本地合入条件单独合入。

### 所有阶段共同遵守

- 未知仍然是 `null`，界面显示"未知 / 未定价"，不填 0。冲突保护不为了凑出总价而关闭。
- 不上传。应用自己不发起新的网络请求，也不开新的网络监听端口。
- 不修改任何 Agent 的数据库或配置；本文不批准任何写操作。
- 验收按四态如实区分：已实现 / 合成测试过 / 真实数据验证过 / 未执行。

### 阶段 1：今日视图补强

- 今日按 Agent × 模型列出输出、缓存命中率、成本，口径与现有统计相同；会话数用已有的 `sessionKey` 计数。
- **会话列表（2026-10-12 追加）：** 按项目分组列出会话，并提供复制恢复命令。这一项需要保存工作目录和原始会话 ID，是对边界的一处小幅放宽，规则见 [SESSIONS-LAYER1-20261012.md](SESSIONS-LAYER1-20261012.md)。
- **速度：暂不做（2026-10-12 决定）。** 归一化记录（`src/m1/normalize.js`）没有耗时字段。参考 cc-switch 的做法，只能从 Claude Code、Codex 的日志时间戳估算，而且估算值包含首字等待和工具执行时间，偏低；耗时字段还会在快照切换到 tokscale 路径时被删掉。成本与质量不成比例。以后如果需要比较模型或中转服务的快慢，再按 cc-switch 的估算算法重新评估：结果标为"估算"，无计时用 `null`，不用 0。
- 除会话列表外，不改边界。

### 阶段 2：本地只读查询接口（CLI + stdio MCP）

这是"接入大模型"的实现方式：应用不内置模型、不保存 API key，而是让用户已经在用的 Agent（Claude Code、Codex 等）通过 MCP 来查询。

- **只读应用自己的已保存事实与计费文件**（2026-10-18 澄清）：statistics.json、billing.json、pricing.json、model-pricing.json 的封闭白名单，使用与 GUI 一致的计价核心，整组双读稳定性检查；不读来源/配置/原始会话元数据，不触发采集，不启动 tokscale。见 [实施范围](QUERY-BILLING-SCOPE-20261018.md)及[查询合同](SAVED-QUERY-20261018.md)。
- **只走 stdio**，不开 TCP/HTTP 端口。
- **只返回聚合结果：** 维度固定为 Agent、模型、provider、日期、入口、会话数；指标为各 token 桶、缓存命中率、成本，以及已定价 / 未定价的覆盖情况。不返回 `sessionKey`、记录 ID 或本机路径。
- **统计计算放在 `src/m1/`。** usage-math 与 insights-math 已迁入共享库，GUI 与查询使用同一份 UMD 实现；查询复用 Store 的计价与共享费用汇总，库不依赖渲染层。
- **运行时：** 价格同步已经在用 `ELECTRON_RUN_AS_NODE` 方式运行应用自身的 exe（`src/m1/price-sync-service.js`），查询接口优先沿用，不另带 Node。外部官方 SDK MCP 客户端以这种方式启动打包版 EXE + ASAR 入口已在本轮合成验证；各真实 Agent 客户端的配置和模型调用未执行。
- **隐私：** 应用本身不外发，但调用方 Agent 会把查询结果发给它自己的模型服务商。合入时 `docs/PRIVACY.md` 要写明这一点。

### 阶段 3：配置健康检查（边界变更）

这是唯一放宽现有边界的阶段：为了检查结构，允许读取各 Agent 的配置文件（settings、config 一类），但必须遵守下面的脱敏规则。认证文件仍然一律拒绝。

**脱敏与安全规则**

1. **独立模块，不走采集路径。** 用量采集用的 `src/m1/policy.js` 中 `allowedFile()` 和 `localPath()` 的拒绝规则保持不变；健康检查有自己的文件白名单。
2. **逐个 Agent 列清单。** 本阶段第一项交付物是一份清单：每个 Agent 要读哪些文件、取哪些字段。清单要对照该 Agent 的官方文档，并用合成 fixture 验证。某个 Agent 没有 skills、hooks 之类概念的，显示"不适用"。
3. **只取结构信息：** 名称、传输类型、命令文件名、"是否存在"布尔值、数量、文件大小、修改时间、能否解析、frontmatter 是否有效、条目是否重复或冲突。
4. **值一律不保留：** `env`、`headers`、`args`、URL 查询串、任何密钥或令牌的值，不保留、不写日志、不显示、不持久化，也不从阶段 2 的接口返回。原始字节只在内存里解析，解析完就丢弃。
5. **认证文件照旧拒绝**（auth、credentials、token 等）。配置和账号信息混在同一个文件里的，只读白名单键；白名单解析不了的，状态记为"未检查"，不尝试读其余内容。
6. **只做静态检查：** 不启动 MCP 服务器，不执行 hook，不做网络探测。只允许查 PATH 判断命令是否存在。
7. **状态四选一：** 健康 / 有问题 / 未检查 / 不适用。检查不了的不默认算"健康"，与"未知不填 0"同理。
8. **路径：** 界面里的路径相对于该 Agent 的根目录显示；阶段 2 的输出和任何导出都不含绝对路径。

**测试：** 在合成 fixture 里埋入假密钥（env、headers、args、URL 里都放），断言它们不出现在快照、IPC、日志和阶段 2 的输出中。

**合入时同步更新：** README 的"这不是什么"、`docs/PRIVACY.md`、`AGENTS.md` 的 Boundaries，以及接入合同新增的"配置健康"一节。

### 阶段 4：声明式组件（DIY）

- 用户用 JSON 定义组件：从阶段 2 查询层的固定维度和指标里选，再选图表类型和筛选条件。
- **不执行用户代码：** 不支持脚本，也不把表达式当代码执行。所有计算在查询层完成，组件只负责"选什么、怎么画"，因此没法把 `null` 变成 0。
- 配置非法时显示错误状态，不悄悄回退成默认视图。配置存放在应用数据目录。
- 固定的默认视图保留；DIY 是额外加的一层，不替代默认视图。

## 测量条件

- Windows 11 家庭版，系统版本 `10.0.26300`，AMD Ryzen 9 9955HX（16 核／32 线程），约 15.2 GiB 系统可见内存；Electron `43.4.0`，驱动 Node `24.13.1`。
- 所有数据由合成 fixture 创建，usage、quota 与 home 分离；统计条数为 0／20,000／100,000，最多约 20,000 日行与 20,000 小时行，500 个合成会话。额度网络在 fixture 模式禁用。
- 启动每个场景 10 次，记录窗口加载与统计数字可见的 P95；性能套件串行执行。磁盘缓存未控制，不称严格冷启动，未使用 CPU profiler、强制 GC 或修改系统／GPU 策略。
- 稳定期对照在两个有数据场景各启动 3 次，每次在数据就绪后第 30、35、40、45、50 秒取样，先取每次启动的中位数，再取 3 次启动中位数。独立基线 checkout 固定在 `7e3b669`，没有依赖共享 main 在测量期间保持不变。
- 私有内存为 Electron `app.getAppMetrics()` 所列进程的 privateBytes 换算 MiB 后求和，另列 GPU 与非 GPU。它不包含瞬时原生子进程峰值，也不是 OS 的整体内存。各列独立取中位数，不能靠分项中位数相加还原总列。

重复启动与稳定期样本中，优化后的主进程事件循环 P95 最大值约 16.5 ms，低于 50 ms 目标；这是统计就绪后的测量，不包含主进程启动阶段。

## 页面响应与故障恢复

源码桌面性能套件使用 20,000 行／100 模型／200 天。100% 缩放同步切换 P95 为 101.2 ms，150% 为 79.9 ms；最大值分别相同，均低于原有 200 ms 门槛。100% 场景比本轮 100 ms 目标高 1.2 ms，记录为未完全达标。最大帧间隔为 108.6／96.7 ms，费用页切换为 15.8／21.8 ms；图表实例复用、状态更新跳过绘图、同采集序号重新计价与范围合计正确。不能据此声称持续 60 FPS 或所有真实显示环境都流畅。

实际工作线程与 Electron 验证了主进程不持有账本、完整会话延迟加载、IPC 发送方校验、线程强制终止后历史总量／版本恢复、重新计价时导航及停止采集时账本字节不变。复核新增测试先复现“替代线程恢复历史后未恢复采集安排”，再验证修复后的启用状态无需手动刷新即可产生新的 `checkedAt`。`start` 幂等，退出优先于恢复；不重放未确认写操作。

已查看恢复后的用量页、150% 价格编辑器、深色费用页、会话列表及窄窗口深色概览截图，这些捕获状态未见明显布局缺陷；本轮没有修改视觉令牌或样式。

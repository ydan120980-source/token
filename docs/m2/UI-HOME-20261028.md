# 首页“概览”实现记录 · 2026-10-28

**状态**：已实现，并用合成数据做了测试。依据是所有者 2026-10-27 通过的第四版设计，见 `UI-PALETTE-QUOTA-SUMMARY-PROPOSAL-20261027.md` 第 3 节。

## 1. 内容

| 区块 | 实现 |
|---|---|
| 导航 | “额度监控”改名为“概览”，图标换成格子。内部的视图名仍是 `quota`。 |
| 页头 | 标题“概览”和日期；右侧依次是剩余 / 已用、自动刷新、复制摘要、全部刷新。原来标题下的“已连接 N / M …”统计行和“最快 … 后恢复”短语都删掉了，符合不放说明性小字的规则。 |
| 三个数字 | **本月至今**：本月估算，胶囊里是推算的整月区间；不足 7 天有用量的日子时不推算，与费用页同一规则。**缓存约省下**：本月的缓存节省；胶囊里是命中率，按缓存读取 ÷（缓存读取 + 未缓存输入）计算，只算两项都报告了的记录。**下一次恢复**：时间；胶囊里是 Agent 和剩余时间。没有依据的项显示“未知”或“—”，不显示 0。 |
| 今天的活动 | 每个 Agent 一条泳道。色块是会话的起止时段，颜色越深 Token 越多（分三档）；圆点是今天之内即将恢复的额度窗口；竖线是现在。右侧是当天 Token。可以切换到“7 天”。时间轴从 6 点开始；如果有更早的会话，起点相应提前，不会把它截掉。 |
| 额度节奏 | 每个额度窗口一个环：外圈是额度已用，内圈是时间已过。待刷新的窗口画虚线环，不显示数字。 |
| 卡片 | 结构不变。筛选条增加“未连接”：选中后不显示卡片，下方只显示未连接的 Agent。 |
| 卡片下方 | “需要处理”和“未连接”两个列表。未连接的 Agent 只保留名称和操作，删掉了逐条说明。保留的提示有两种：状态类（例如没找到 Codex CLI、没有安全的读取方式），以及网站会话路线必须标明的“网站接口可能变更”（2026-10-20 的决定）。 |

## 2. 与设计稿的差异

- 积分这类没有时间窗口的额度没有画成环。现有视图模型里，积分只有余额和到期，没有“已用占总量”的比例，画外圈需要编造分母。
- 首页还不是打开应用时的默认页面，启动时仍然打开用量页。改成默认页面会影响几十个按“启动即用量页”编写的 UI 套件，这件事等所有者确认后再做。

## 3. 测试

- `quota-v4-ui-test.js` 中针对旧“现在 / 接下来 / 余额”区块的断言，改为检查概览：三个数字、额度环（用完、16%、两个待刷新且不显示数字）、活动范围切换、“未连接”筛选，以及“超过 1 天未更新”的定位（仍可通过 `quotaUi.locate('old')` 使用）。
- `render-performance-ui-test.js` 改为检查卡片里的余额更新和卡片点击打开详情，静止数字改查首页三个数字。
- `polish-ui-test.js` 的页面名改为“概览”。
- 与本分支无关的失败：`quota-identity` 在 main 上同样失败；`interaction-reliability` 仍在找 M8 之前旧费用页的选择器。两者都没有修改。

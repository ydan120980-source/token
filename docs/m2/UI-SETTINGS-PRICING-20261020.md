# 设置页与定价整合（2026-10-20，界面重做 F 步）

所有者在 2026-10-20 确认的待办 F 项：设置页居中；定价改为紧凑表格，点行打开详情面板，处理方法和匹配建议放在面板里；把分散的未定价、别名建议和手动价格合成一个流程。费用页的"历史费用估算"一并移到这里。后端接口、价格规则和数据语义都不变。

## 改动

- **居中**：设置页改为 820px（新 token `--settings-width`）的居中栏。标题、说明、搜索框和分类栏都居中排在栏顶；下面各节仍从左往右读。
  - 原来 960px 的栏在宽窗口里虽然整体居中，但标题、分类栏都靠左，看起来偏向一边；本步按"头部居中、正文窄栏"理解这条要求。
- **定价表格**：
  - "未计入估算的用量"和"模型与自定义费率"两张列表合成一张"模型价格"表。有未计入用量的模型排在最前，用量列下写"未计入 N%"：橙色点表示补价格可以解决，斜纹点表示来源没有报告完整。
  - 表头旁一句话说明有几个模型、多少 Token 未计入估算。
  - 整行可点，右侧是展开箭头；"调整""撤销手动"按钮和行内的"处理方法""匹配建议"折叠项都去掉了。
- **每个模型一个面板**（沿用原价格编辑面板 `#priceEditor`）。从上到下：
  1. 未计入估算：原因、各自的 Token 数，以及处理方法的步骤（措辞沿用 `src/m1/pricing-labels.js`）。
     - 只有"来源没有报告完整"这类原因才给"检查 某 Agent"按钮。缺价格的问题就在这个面板里解决，不再引导去来源页。
     - 缺缓存写入时给"核对手动费率"，切到手动价格并定位到缓存写入。
  2. 计费方式：按目录模型计费 / 手动价格。
     - 匹配建议放在"按目录模型计费"里，点"选择此模型"填入计费模型，仍需"按此模型计费"保存。
     - 撤销手动价格就用手动价格里的"移除手动价格"。
  - 面板打开时如果后台刷新了价格，状态和候选会原地更新，面板不关。
  - 费用页"计价覆盖"卡片上的"处理方法"直接在费用页打开同一个面板，不再跳到设置页。
- **历史费用估算**：从费用页底部移到定价卡片内，位于 Agent 计费规则之后；"重新估算"按钮和计价条数说明保持原意。原来的"打开定价设置"按钮不再需要，已删除。

## 接口变化（仅渲染层）

- `uiPricingView`：`gapsHtml` 换成 `statusHtml(item)`（单个模型的面板状态）；`rowsHtml(models, { gaps })` 给有未计入用量的行加 `data-gap` 和状态；`suggestionsHtml` 输出面板里的候选行。
- `uiPricingEditor.explain(key)` 改为打开该模型的面板。
- `insights-ui.js` 在设置页也加载工作台数据，以显示计价条数；重新估算的结果写在 `[data-insight-status="settings"]`。

## 第 2 批：定价（已完成）

**只用合成数据、源码模式验证。** 所有者说“选了建议的模型还是无法定价”。合成记录复现了这些原因（真实数据里是哪种，没有核对）：

| 原因 | 现在 |
|---|---|
| 候选缺少费率（如没有缓存读取价），记录里却有这部分用量 | 每个候选先试算，写明“全部可计入 / 可计入 12% / 不能计入”和差在哪；能全部计入的排最前 |
| 记录本身不完整或冲突，选什么都没用 | 不再显示候选，直接说明“改价格算不进去” |
| 点“选择此模型”但没点保存 | 选中后马上显示“保存后的结果” |
| 手动价格优先于映射，选了不生效 | 明确提示，并禁用保存 |
| 按规则计价的模型（映射、默认模型、标识匹配）被列为目标，保存时才被拒绝 | 不再列出 |

**一键处理**（设置 › 定价）：每次切换都重新向后端试算，数字就是应用后的结果。应用前什么都不写，应用后可以撤销。

| 档 | 规则 |
|---|---|
| A 自动匹配 | 所有能全部计入的候选价格都相同才匹配；价格不同的留给人选 |
| B 保底模型 | 人选一个模型，只给没有可用价格的模型用，已有价格不变。标“保底估算”，设置页和费用卡片单独写金额 |
| C 下限（红色，默认关） | 只算记录已报告的字段，缺的字段不填 0，账本不变；费用标 +，设置页和费用卡片写明“实际更高”。两个来源冲突、记录自相矛盾的仍不计入 |

**接口**：`usage:priceTry`、`usage:pricePlan` 只读；`billing.json` 新增可选字段 `fallback`、`partialLowerBound`，没打开时不写入，旧文件不变。

测试：`tests/m1/pricing-plan.test.js`、`scripts/m1/pricing-fix-ui-test.js`。

**已知限制**：费用卡片写的是全部历史中的保底和下限金额，不是当月；费用页主体（性能分支在改）没有动。

## 第 3 批：来源管理（已完成）

**只用合成数据、源码模式验证。**

- **两个标签**：来源、Agent 配置。
- **问题写在对应 Agent 的卡片上**，并分清：可以处理（有“处理”按钮，直接打开定价）、无法修复（只有“不再提醒”，不再给“查看来源”这种走不通的按钮）、读取问题（“查看”）。相同原因合并。

- **右栏用词和卡片一致**：有记录的来源是“已读取”，没有记录是“尚未读取”。

## 第 4 批：Agent 配置（本机 Agent 管理后台，已完成）

**只用合成数据、源码模式验证；真实 Agent 的配置文件没有读过。** 路径来自官方文档：[Claude Code 插件](https://code.claude.com/docs/en/plugins/loading.md)、[Codex 插件](https://developers.openai.com/codex/plugins/build)、[Gemini CLI 扩展](https://geminicli.com/docs/extensions/reference/)、[Gemini CLI Skills](https://geminicli.com/docs/cli/skills/)、[OpenCode 配置](https://opencode.ai/docs/config/)。`installed_plugins.json` 的字段官方只写了 scope、installPath、version，具体结构是按已知形状解析的，需要真实样本核对。

**所有者决定**：定位是本机 Agent 管理后台。授权记住所选目录和读取指令文件内容；不做在线安装；MCP 连通测试、供应商切换、本地路由不做。

| 能力 | 内容 |
|---|---|
| 范围 | Codex、Claude Code、Gemini CLI、OpenCode 的 MCP、Skills、Hooks、插件、指令文件，用户级和人选的项目。其他 Agent 未适配 |
| 什么时候读 | 只在点“检查本机配置”时读，在无网络的工作线程里，不执行任何配置。打开页面、重启都不会自动读。 |
| 健康 | 命令找不到、缺环境变量、明文密钥、地址未加密、结构错误、Skill 缺前言或同名、插件文件丢失、指令文件过长；每条写明怎么办 |
| 使用状态 | 开关状态、更新时间；点“统计使用情况”才按批扫描已读取的会话记录，只回名称和次数，不保存。Hooks 和指令文件在记录里看不到，直接写明 |
| 修改 | 启停 MCP、Skill、插件、整个文件的 Hooks，MCP 复制到另一个 Agent（不覆盖同名），编辑指令文件。都先预览，写入前加密备份。只有 Codex、Claude Code 能改；Gemini、OpenCode 只读 |
| 恢复记录 | 所有修改跨重启可恢复；文件之后又被改过就拒绝 |

**页面拿不到的东西**：参数、环境变量值、请求头值、地址的路径和查询串、完整命令行、绝对路径。只有名称和数量。

**不读的文件**：认证文件；`~/.claude.json` 混有账号信息，所以 Claude Code 的用户级 MCP 看不到，页面写明了这一点。

**已知限制**：
- “找不到命令”查的是本应用看到的 PATH，可能和 Agent 启动时的不同，所以只算“需要注意”。
- 插件内部的 Skills、MCP 只列在插件详情里，不算进 Skills 和 MCP 的列表。
- MCP 的“使用”依赖工具名 `mcp__服务名__`，这个形状只对 Claude Code 核对过文档，Codex 的真实记录没有核对。
- 旧的“按目录逐项检查和编辑”折叠在页面底部，字段级编辑和本地导入还在那里。

测试：`tests/m1/agent-inventory.test.js`、`scripts/m1/agent-admin-ui-test.js`。

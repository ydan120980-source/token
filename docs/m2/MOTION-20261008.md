# 采集再减负、页面留白、筛选返回与动效 — 2026-10-08

2026-10-08 用户授权。主线 `m2/agents-r4`，基于 r7。本记录为主线程源码验收，尚未打包新候选。

## 后端：运行中的 r7 仍在持续占用 CPU

- 实测（本机运行中的 r7，5 秒刷新）：每 5 秒约 0.8 CPU 秒，主进程（含采集线程）约 5 秒/30 秒，渲染进程约 3 秒/30 秒。原因是本机有 Agent 正在写会话记录（例如本次 Claude Code 会话的 transcript），源文件每轮都有变化，r7 的"源戳不变就跳过"几乎不生效，每轮都要合并缓存、tokscale 校验、把 3.5 万条记录传回主线程并入账。
- 分阶段计时（本机账本副本，真实来源只读）：源戳 0.19 s，缓存合并 0.36 s，传回主线程 0.23 s，tokscale 1.7 s（独立进程），入账 0.8 s（主线程阻塞约 0.65 s），快照重建 0.5 s。
- 改动：
  1. **结果比对**：先只重新解析有变化的文件，若每个文件的解析结果、文件集合与列目录结果都和上次相同，就不再合并、校验、传回和入账。新增握手：worker 只在服务确认已入账它上次交出的扫描后才走这条捷径，避免"交出但未入账"时漏数据。
  2. **变更通知**：worker 用系统文件变更通知（递归监视各来源目录；数据库按所在目录监视，WAL 写入也算）代替每 5 秒的目录遍历；无事件时直接答复未变化。至少每 60 秒仍做一次完整源戳检查，兜住漏事件、后来才出现的来源目录和不支持监视的环境。本机开启了 NTFS 最近访问时间更新，程序自己读文件也会触发事件，因此每次真正有变化后会多一次只做 stat 的检查，然后恢复安静。
  3. **快照不重复传输**：渲染进程带上已有的快照版本号，主进程在版本未变时只回状态、不回快照体（约 700 KB）。
- 同条件对比（同一账本副本、真实来源只读、5 秒刷新、60 秒）：主进程 7.39 → 1.24，渲染进程 1.00 → 0.41（`getAppMetrics` 的 cumulativeCPUUsage 差值）。
- 服务新增 `lastCollection` 诊断：`unchanged:quiet | unchanged:stamp | unchanged:outcome | ingested`。

## 前端

- **页面留白**：标题区与资料行、数字与事实行、今日卡和各分区之间的间距加大；洞察卡片内边距加大。
- **今日/当日明细**：0 token 且没有任何已知用量的空记录（例如 `mimo-auto` 的空回复）不再单列；账本和记录数照旧保留。全是空记录时提示"此日只有 0 token 的空记录"。
- **趋势 Agent 筛选**：全部只显示图标，选中的那个展开名称（宽度与透明度过渡）；名称始终在 aria-label 与悬停提示里。
- **用量占比**：列表不再受自身维度的筛选影响，选中项高亮、其余变淡，再点一次取消；卡片右上角出现"‹ 全部 Agent / 全部模型"返回按钮。Agent/模型切换使用滑动指示块。
- **成本去向 / 效率**：金额与指标从旧值滚动到新值；分布条从左向右展开；占比条依次生长；内容切换淡入。小于 1 美分显示"<$0.01"，每百万 token 成本保留三位有效小数（例如 $0.244），不再显示 $0.00。
- **活跃时段**：单元格按小时依次浮现；悬停显示浮层并高亮所在星期与钟点；点击或回车固定该时段明细（各 Agent 的 token、占比、天数与估算费用），Esc 或关闭按钮收起；方向键在格子间移动（单一 Tab 停靠点）；"最集中的时段"可点击直达。事实卡在两栏布局中改为 2×2，不再挤出。
- 深色模式下列表中的 Agent 图标与趋势筛选一致（Claude 保留品牌色，单色图标反相）。
- 所有动效遵循"界面动效"设置：减少动态或关闭时只保留即时切换。

# 界面 P6：启动页、外观、30 日均、未定价定位与悬停反馈（2026-10-15）

项目负责人在 r13 试用后提出的问题，以及随后批准的范围：按检查报告的顺序全部修复；外观加"跟随系统"；启动落在用量页；今天卡片的会话入口和悬停反馈改成 Apple 风格；30 日均重做；会话页刷新不改频率、消除跳动；成本定价要能定位到具体哪些模型没有计入估算。

本记录是这些改动的决定和语义，实现以 `feat/ui-p6` 的提交为准。

## 决定

### 启动与外观

- 启动直接显示"用量"。`quota-ui.js` 不再在加载后跳到"额度监控"，避免先画一遍用量页再切走。窗口标题栏补上"会话"的页名。
- 色彩外观新增"跟随系统"并设为默认。选择记在本机 `localStorage`（`agentusage.theme.v1`），重启后保持；系统切换深浅色时，"跟随系统"立即跟着变。侧栏按钮和菜单"切换深浅外观"切到与当前相反的固定外观；"外观 → 色彩外观"菜单可选三项。窗口在页面加载前按系统外观设置底色和标题栏颜色，深色系统不再先闪白。
- UI 测试不受影响：Playwright 启动 Electron 时默认把 `prefers-color-scheme` 模拟为浅色。要测跟随系统，用 `page.emulateMedia({ colorScheme })`。

### 30 日均

旧规则要求近 30 个自然日全部有记录，均值按 30 除。只要中间有一天未记录，这一天就没有均值，所以历史稀疏的人整条线只剩最后几天，挤在长时间轴的右端。

新规则与用量概览的"日均"一致：

- 某天的 30 日均 = 近 30 个自然日里**有记录日期**的用量之和 ÷ 这些日期的天数。未记录的日期是未知，不算作 0，也不进分母。
- 有记录、但某个系列（模型、字段）没有数据的日期是已知的 0，计入分母。
- 费用：有记录但没有定价的日期，费用未知，不进分母；定价日期不足时没有均值，不会用 0 补成一个偏低的平均。
- 窗口内有记录的日期少于 7 天时不显示（`usageMath.AVERAGE_MIN`），图表从第一个有值的日期开始画，并注明"MM-DD 起近 30 天有 7 个以上有记录日"。
- "淡线连接未记录日期"只在区间里确实有未记录日期时出现。

### 未计入估算的用量

旧面板只列出"设置价格就能解决"的模型。用量字段不全或有冲突的记录合成一句"另有 N Token 的记录缺少用量字段或存在冲突"，指不到任何模型；同时页头还写着"全部已定价"。

现在：

- 估算（`src/m1/pricing.js`）在 `usage-incomplete` 之外给出具体原因 `cause`：`missing-<字段>`（来源没有报告输入、输出、缓存读取、缓存写入或推理）、`conflict`（两个来源的用量不一致）、`invalid-cache`、`invalid-reasoning`、`total-mismatch`、`partial`。
- 每日和每小时聚合行新增 `unpricedTokens`（按原因的未计入 Token）和 `incompleteTokens`（按原因细分的不完整用量 Token）。窗口白名单（`local-snapshot.js`）只放行已知的原因和细分原因。这是新增的诊断字段，不改变任何已有数值的含义；未知仍是未知。
- 设置页的定价卡片：
  - 覆盖条分三段：已定价、可设置价格、来源未报告完整（斜纹，表示未知，不是费用），下方图例给出各自的 Token。
  - "未计入估算的用量"列出每个有 Token 未计入的模型，按未计入量排序。每行显示原因和对应 Token、占该模型的比例，以及唯一能做的动作：价格缺失时"设置计费"；来源没报告完整时"查看来源"，因为设置价格补不上来源从未写下的字段。默认显示前 5 个。
  - 已用模型表的用量列对有未计入的模型显示"未计入 X%"。
  - 页头计数改为"N 个已用模型 · M 个有未计入估算的用量"，只有全部计入时才写"全部已定价"。
- 旧快照没有按原因的 Token 时，把该模型的剩余未计入量整体归到它唯一已知的原因下，不编造拆分。

### 会话页刷新

刷新频率不变（随每次采集）。以前每次刷新都整段替换 `innerHTML`，每个项目组都会重播入场动画、活跃点的脉冲从头开始、悬停和焦点丢失。现在按项目和会话的 key 原地更新，只改变化的文字和属性；顺序变了就移动原元素，只有新出现的项目和会话才有入场动画。

### 动效与悬停

- "近 30 天"柱条只在首次出现时长出。切换页面范围时它的数据不变，所以保持不动；切换筛选时，每根柱从当前高度过渡到新高度（完整动效；减少动态和关闭时立即变化）。
- Agent 选择条改为固定宽度：只显示图标，"全部"保留文字。选中只改变背景，其余按钮不再左右移位。选中 Agent 的名字已在图表标题和会话摘要里。
- 切换 Agent 时折线从当前位置变形（P5 已实现，本次复核无误）。检查报告里那张"从左往右擦出"的帧，其实是图表滚入视口时的入场动画，与切换无关。
- 悬停反馈不再抬起、放大或发光：日历和"星期 × 小时"格子显示一圈细环；柱条加深颜色并显示整列浅底；键盘焦点另有强调色的环。今天卡片的"N 个会话 ›"和"会话"数字改为普通文字加展开箭头，悬停时出现圆角浅底，按下时加深，不再有描边、着色或位移。
- 隐藏的图例项不再加删除线，改为浅色文字和空心色块。

### 视觉修正

- 修复按天查看时 24 小时柱图塌缩。原因有两个：P5 把小时区第一列改成按内容宽度，而按天的柱没有固有宽度；P5 的 CSS 清理又在列已塌缩的状态下判断 `.day-hours i { width: 100% }` 无效，把它删了。
- 主滚动条改为浮在表面的圆角滑块，不再有系统箭头（Windows 上 Chromium 的 `scrollbar-width: thin` 仍会保留箭头，所以改用滚动条伪元素绘制）。
- 设置页：去掉"定价"分节下重复的"成本定价"标题（保留给读屏）；"Codex 用量维护"改成和"Agent 计费规则"一样的折叠卡片，带一行用途说明。
- 额度空状态卡片占满宽度；"选择 Codex CLI"改为居中的次要操作，说明用途。
- 窄窗口：刷新和导出不再竖排；图表说明不足一行时换到单独一行。
- 费用与构成两张卡片按各自内容高度排列。头像中文名只取一个字。"N 记录"改为"N 条记录"。
- 来源状态：读取正常但解析规则尚未用真实样本核对，显示"已读取"，悬停说明尚未核对的部分；从未读取过显示"尚未读取"。不再显示内部用语"未验收"。

## 验证

源码模式，合成 fixture 与独立的 usage/quota 目录：verify 与 `audit:runtime` 通过；全部 15 个 UI 套件通过（continuity 首次运行在启动时遇到 Playwright 的"promise garbage collected"偶发错误，重跑通过；functional 在批量运行中出现过一次下拉选项等待超时，单独重跑和全量重跑均通过）；desktop-performance 通过，最大同步耗时 83.5 ms / 81.7 ms。

新增的回归检查：layout 套件 `dayHoursFill`（去掉 `.day-hours i { width: 100% }` 时确认会失败）；sessions 套件检查刷新后元素不变、不重播入场；polish 套件检查启动页、各页标题、跟随系统与记忆、Agent 选择条不移位、切换范围时 30 天柱不重播；单元测试覆盖 30 日均新规则、未计入用量的拆分与旧快照回退、估算原因与快照白名单。

打包版和真实数据上没有验证；打包验收属于发布负责人。

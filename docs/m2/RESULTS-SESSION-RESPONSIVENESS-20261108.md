# 会话页与阅读三栏专项 · 2026-11-08

本批仅处理会话页和阅读的左、中、右三栏。分支 `codex/session-response-20261107` 从共享 main `3846ec5` 开始，不继续上轮停止时的未提交候选。没有推送、打包、归档、像素对照或修改他人的文件。

**状态：针对性改善，尚不能保证整体不卡顿；RESPONSIVENESS_REMAINS_OPEN，RAM_NOT_RETESTED。** 首次读入和退出仍有真实长任务。最终字节的检查记录见末节；资格通过、功能通过与性能目标通过分别记录。

## 改动与语义

- 阅读区当前位置、展开状态或悬停更新不再无条件重绘右侧概况。右栏使用默认浅比较；传给它的文件、跳转和对比处理器保持稳定，并保留所用状态的完整依赖。没有用忽略业务字段的自定义比较器掩盖更新。
- 左侧会话行与悬停层分开更新。稳定的行绑定在实际事件发生时读当前卡片处理器，保留指向、焦点、Escape、切换与并排行为，不封住旧的卡片状态。既有 host 的会话／标签事件仍更新行。
- 右侧长命令列表、文件树和平铺文件只挂载附近内容，沿用正文的窗口化组件、原生高度测量与焦点／选择保护。占位高度保持滚动空间，数据、筛选、继续显示与既有文件展示上限均未减少；没有新的正文缓存。短列表仍完整显示。
- 文件筛选原来对每次编辑调用整轮划分，重复编辑同一个文件会形成二次扫描。`processExpansion` 在本次点击中为每个受影响轮次各划分一次步骤与工具／子 Agent 分组；只保留临时数字索引，展开结果、失败与子 Agent 语义不变。
- 阅读容器宽度只用于决定两侧栏和并排能否放下；现在按这些规则的完整分界更新 React 状态，实际连续尺寸仍由 CSS／原生布局决定。当前窗格从初始化就有焦点归属，避免第一次普通点击再做一次整组焦点更新。未改栏数、最小尺寸、布局、颜色、字体或动效参数。

样式文件仍与基线一致：`agent-ui.css` SHA-256 `5de2d63a7002613214397504c314f4e9d12b776b7933a978e8acd8b5178b286f`。

## 针对性证据

私有数值证据目录为 `session-response-20261107`。探针与夹具均记录 SHA-256，基线产品为 `561e0a4`，其产品源码与 main `3846ec5` 无差异。合成负载有八千余会话、37 轮／2960 次工具调用的工具密集记录，以及 180 轮长记录。默认原生窗口 1482×962、300 Hz、125%，不强制降低显示条件、关闭动效或调整 GPU。

初轮诊断中，正文滚动触发右侧概况／分组重算；六次侧栏悬停触发行数据格式化 66 次。隔离后对应阶段不再调用这些模型方法。CPU／布局诊断有额外采样开销，统一标为不可用于计时验收。

文件展开的确定性核对 `expansion-operations.json`：同一轮中 1000 次编辑，旧调用方式访问条目 5,000,000 次，新方式 5,000 次，展开结果相等。这是该算法的操作量变化，**不是应用提速 1000 倍**。

在加入宽度通知优化前，同探针／同夹具 `final-before` 与 `final-after-repeat` 的阶段点击如下（ms）：

| 操作 | 基线 | 候选 |
| --- | ---: | ---: |
| 命令首次／再次 | 88 / 72 | 40 / 24 |
| 文件 | 72 | 32 |
| 概况首次／再次 | 32 / 32 | 32 / 32 |
| 左栏切会话 | 56 | 48 |
| 左栏打开另一长会话 | 48 | 40 |
| 切目录 | 48 | 56 |
| 目录跳转 | 32 | 24 |
| 返回列表 | 80 | 88 |

该候选轮未采到超过 50 ms 的主线程长任务，基线有三项；两类正文滚动 p95 都约 3.5 ms。保留切目录／返回略慢的数字，不声称所有操作均变快。另一次 `final-after` 功能检查通过，但窗口最后失焦一次，计时不具备验收资格，未删除该回执。

计时停止后的专项检查覆盖：命令默认页保留 200 个条目、初始只绘制 54 个；滚到底可见条目无空白；继续显示保留 400 个条目；控件先确实获焦，再滚离仍保持焦点；全列表筛选得到 37 个匹配；长文件树只绘制附近条目；筛选可找到默认前 200 项之外的文件并切正文；会话卡片可由焦点打开、由 Escape 关闭。当前窗口截图仅使用合成数据。

## 真实数据与未关闭的问题

真实检查只通过 `validate:local --performance --reader-only`，新建临时应用状态，不读认证文件、查账号、改来源或保存正文／截图。保留数值结果，不复制真实记录。记录正在变化，所以不把读入耗时作严格等文件解析速度对照。

最初的紧邻对照中，命令的重复点击约 88–96→24–40 ms，正文滚动不再重算右侧概况。加入文件窗口化后的晚轮出现更慢的读入、导航和退出。随后的 `real-adjacent-before`／`real-adjacent-after` 两端都在前台且无渲染错误：

| 操作 | 旧版两份记录 | 候选两份记录 |
| --- | --- | --- |
| 命令首次 | 184 / 232 ms | 48 / 136 ms |
| 命令再次 | 160 / 136 ms | 40 / 64 ms |
| 文件 | 48 / 120 ms | 32 / 32 ms |
| 左栏会话 | 176 / 104 ms | 152 / 88 ms |
| 返回列表 | 248 / 168 ms | 184 / 160 ms |

命令／文件阶段的长任务减少，但候选首读仍采到 370 ms 长任务，退出约 114/94 ms，滚动仍有超过 50 ms 的帧间隔。旧版同样有问题并不能证明候选所有回退都由外部负载造成；不将资格合格的慢轮次改标为通过或无效。没有关闭用户进程、调整优先级或改系统设置。

因此，本批不能称为整体响应速度达标、真实会话均不卡顿、读取速度普遍翻倍或发布可用。下一步若继续，应单独归因首次读入与退出路径；现有解析请求仍为 FIFO，过期的前端结果会被忽略，是否需要按窗格取消旧请求尚未复现验证，不能把这个推断当成本轮已确认的根因。

## 最终字节的交互复核

`width-after` 是无采样器、前台无失焦的合成轮次。命令首次／再次 40/24 ms，文件 24 ms，左栏会话 56 ms，左栏打开长会话 40 ms，切目录 56 ms，目录跳转 24 ms，返回 80 ms。没有采到超过 50 ms 的主线程长任务。`width-checks` 在同一最终产品字节上重核了前述窗口化、全列表筛选、继续显示、文件跳转、焦点和 Escape，并保留当前合成图；不使用截图时间作性能证据。

`real-width-after` 两端桌面与原生窗口资格通过、无失焦／渲染错误，两份真实记录成功读取。两份记录的命令首次 32/88 ms、再次 40/32 ms，文件 32/24 ms，左栏会话 88/56 ms，返回 128/104 ms；桥接读取约 209/863 ms，包含读取与传输，不称为单独解析耗时。正文滚动和这些栏内切换没有采到超过 50 ms 的主线程长任务。

**仍未关闭：** 最终真实首读仍有 142/58 ms 主线程长任务，退出仍约 73/70 ms。这轮比前面的慢轮恢复得快，不能把全部差异归因于宽度优化，也不覆盖前面采到的 370 ms／更慢回执。应用整体流畅度目标仍开着；本地合入这批经功能验证的修复只交付已证明的改善。

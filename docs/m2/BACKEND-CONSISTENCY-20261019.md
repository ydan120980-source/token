# 保存、计费与查询一致性维护（2026-10-19）

所有者授权实施三项并由本线程复核结果后本地合入：写入失败及计费引用一致性、查询版本及分页一致性、只读计算模型拆分及合成性能测量。基线为 `codex/query-billing-20261018` 的 `363ced0`，本地 main 为 `7a2d8fb`；本轮包含复核并合入该分支此前的已交付增量。主线程独立实施，不派发 Agent。

## 实施与验收

1. 保存操作先形成候选、校验和落盘，再发布内存状态。清空、采集开关、读取位置、刷新间隔和订阅设置的失败不能改变内存或重启结果。采集、个人来源和计费沿用各自已具备的提交保护。
2. 删除手动价格、替换价格目录时验证映射和默认模型引用；有效参考价可回退，否则拒绝该操作并提示先解除引用，不自动改用户规则。旧的悬空引用保留为未定价事实，不能让整个只读查询不可用；新写入仍严格验证目标。
3. 查询增加不含路径、身份和原始配置的结果版本。第一页可无版本；继续 offset 分页必须携带返回版本，数据或计价依据变化则受控拒绝并要求从第一页重查。版本同时绑定筛选、分组、时区与计算合同。保留现有工具名和有界输出。
4. 从 Store 中抽取显式输入的计价与投影模块，GUI 与只读模型共用；只读模型不继承或伪造 Store，不引入存储、来源、认证读取或采集依赖。保留未知、零、冲突、去重、会话隐私及既有估算规则。
5. 使用独立合成账本测量不同规模的读取、投影及查询耗时和内存，先测后优化；不预设数据库迁移、额外持久化缓存或常驻服务。

运行 verify、audit:runtime、test:native、pricing:check、外部 SDK 查询集成、受影响源码 UI 及定向故障/重启/版本/大账本检查。SDK 的工具内部分页为应用合同，不混同 MCP 的 tools/list 游标协议；协议参考：[MCP pagination](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination)。首轮失败、修正、复跑和未执行项目进入结果记录。

全部完成后检查 diff 和证据、主题分支通过本地门禁，再确认共享 main 干净、基线未变化且无其他合并正在进行，用 no-ff 本地合入。共享 main 若变化先在主题分支整合并补测。不 push/开 PR、不替换运行包、不创建正式 dist 代次或源码 ZIP。

## 第一项实现

清空、开关、来源范围、刷新间隔和订阅均先保存候选再发布内存；失败保留对象、投影和定时状态。价格移除或目录替换在保存前检查有效引用，错误码 PRICE_TARGET_IN_USE；移除面板明确提示先解除引用。旧悬空引用只在保存读取中允许，仍未定价且不改盘；setBilling 新写入严格校验。

定向故障、重启、引用、旧账本测试及 lint 复跑通过。首次新测试脚本有对象字面量括号错误，修正后通过；未放宽断言。源码 UI 与整体验证在三项完成后统一执行。

## 第二项实现

usage_query 增加 revision，保持原工具名与 UsageQueryV1 的既有指标；继续 offset 页强制传版本。版本绑定公开聚合结果与计算依据，不是账本文件、身份或路径的散列。groupBy 和过滤集合规范化，分页大小不参与版本。版本变化受控拒绝，没有历史快照缓存或磁盘事务承诺。

单元检查覆盖多页拼接、不同页大小、筛选变化、价格/倍率/映射/目录/用量/时区变化和身份元数据不影响版本；外部 SDK 客户端已实际连续查询两页、核验缺版本与改价后的旧版本错误。证据位于 artifacts/backend-consistency-20261019/query/results.json。

## 第三项实现及测量

valuation 接受价格目录、手动价格与计费规则，负责解析/估算/引用校验；usage-projection 接受记录、估算器、时区和时间，返回统计投影。Store 仅封装持久化与进程内缓存；usage-read-model 构造独立只读接口，读取链不再加载 Store、来源读取器、policy、原生校验或会话模块。依赖边界测试和冻结输入的独立算例覆盖该分层。

先以冻结的 `45f161f` 模块测量，再测本轮实现；每规模独立 Node 进程，重复三次查询取中位数。相同合成数据为 400 个日行、600 个小时行和 20 个模型，完整查询包含双读、解析、计价、聚合和会话去重。查询逐条创建 Intl 格式化器是可消除的开销，现改为最多八个时区的格式化器缓存，日期与 DST 对照不变；未增加账本/查询结果持久化缓存。
